## DESIGN-001. 面向公众的聊天产品即将上线，预训练已经结束。后训练阶段、安全闸门、推理集群三条线上，各自允许放量的判定条件分别是什么？

**答：** 训练侧把通用语言模型收成可对话、可拒答的产品模型：用清洗过的示范做监督微调，再用偏好数据做 DPO 或 RLHF 一类对齐，并单独跑安全与红队集。服务侧不是把 checkpoint 挂上就结束——网关做鉴权限流计费，对话服务管会话、系统提示和输出过滤，推理集群用连续批处理、KV cache 和量化把 prefill 与 decode 分开扩。放量要三条同时过线：离线安全/质量集达标、小流量对照的拒答与投诉不恶化、P95 首 token 和每 token 延迟在预算内；训练 loss 还在降不能当放量理由。

**深入展开：** 数据流是基座语料去重并滤低质有害内容，SFT 把问→答格式写进权重，偏好对齐改排序而不是只模仿示范，安全训练和分类器挡越狱与违规补全。分布式训练用数据/张量/流水线并行，检查点必须能从失败 rank 续跑，否则一次节点故障会吞掉数小时步进。服务上 prefill 吃算力、decode 吃显存带宽，GPU 数应按「峰值并发会话 × 平均输出 token / 单卡 decode 吞吐」估，不要把接口 QPS 当成普通 HTTP。量级只作示意：同代硬件上，7B 级单卡 decode 常见每秒数百到数千 token，70B 级往往低一个数量级；上下文 8k、batch 32 时 KV cache 经常比权重大先顶满。多模型路由把寒暄和分类交给小模型，长推理才上大模型，系统提示走前缀缓存。安全是训练对齐、输入输出审核、滥用速率特征三层。用户反馈进下一轮评估集，不无过滤地写回训练集。新版本必须能灰度，并瞬间切回上一 checkpoint 和上一套提示。

**后续追问：** 离线安全集全过、金丝雀投诉却上升，你查分布偏移、提示改动还是解码温度；怎样用峰值并发和平均输出长度反推 GPU，而不把 prefill 高峰和 decode 稳态混成一个数；偏好标注分裂时，你停对齐还是拆成多条政策头。

**扩展问题：**
- 预训练中途一个数据并行组掉线，怎样在不从头开跑的前提下保住全局步数和优化器状态？
- 连续批处理窗口加大后首 token 先坏，怎样把交互会话和离线批任务切到不同队列？
- A/B 里新模型胜率只高约 1%，样本要多大你才敢切全量，避免把噪声当改进？

**推理回答：** 目标是公众可聊且可撤回，约束是安全、延迟和 GPU 成本。先把训练产物定义成带版本的对齐 checkpoint，再把服务定义成可路由、可限流、可回滚的推理面。门槛用离线集、在线对照、延迟容量三条同时过，而不是「能生成完整句子」。

## DESIGN-002. 跨会话助手月活大约一千万，单轮记忆查找必须落在约 150ms。提示里该给记忆留多少 token、每用户每月要花多少钱？近轮原文、滚动摘要、长期事实怎么分成冷热层，摘要生成走在线还是离线？

**答：** 在线路径禁止为了「整理记忆」再跑一次生成模型。热层是会话 KV 里最近十几到几十轮原文，温层是按时间窗滚动的摘要，冷层是带主键的长期事实表加向量；150ms 预算里只做按 `user_id` 预过滤的 KV 读取和 ANN，拼出例如 200–400 token 近轮、300–600 token 现行摘要、200–400 token 相关事实。摘要和事实抽取放在会话空闲后的近线作业，只对超长会话触发。月成本用「检索次数 × 基础设施单价 + 被抽取会话数 × 小模型 token」估算——对千万月活，必须先假定只有一小部分会话够长才值得摘要。

**深入展开：** 规模账（示意，不是某家产品的指标）：1000 万月活、日活约 80–120 万、人均每天 8–15 轮要读记忆，则日检索大约 10⁷ 量级；峰均比按 3–5 估，峰值大约每秒数百到一千次，用「按用户分区的 KV + 带元数据过滤的 ANN」可以扛，不必每轮召一次大模型。延迟拆开：鉴权后读热 KV 约 5–15ms，长期事实 ANN 约 30–80ms（必须先滤 `user_id`，禁止全局 top-k 再丢），拼装约 5–10ms，余量给尾延迟和跨区。三层职责不同：近轮保住未决约定和指代；滚动摘要把上周的长聊压成一段现行版本，注入只带这一版；长期事实是稳定槽（界面语言、默认时区、常用项目）加少量情景笔记。对象存储里的全文转录不进 150ms 路径。摘要作业在会话空闲或满 N 轮后入队，只压缩相对上一版本的增量，用小模型批处理，允许延迟数分钟；高峰积压时在线继续用旧摘要加近轮，绝不堵住首 token。提示里的记忆预算要写死：例如 8k 上下文中记忆总共不超过约 1k–1.5k，并按当前意图取事实（改日程取时区，不取饮食笔记）。存储本身不贵：活跃会话按几十 KB 计，热 KV 只要数十 GB；人均几十到一两百条 768 维向量量化后，千万用户是 TB 级。贵的是抽取——若对日活全员每天摘要一次，输入 token 会到十亿量级/天；所以触发条件应是「本会话已超约 2k token 或超过约 20 轮」，实际抽取得可能只有日活的 10%–20%。评估看检索 P95、注入 token 分布、每用户每月美元，以及关掉摘要作业后只靠近轮是否仍能接上话。这里不裁决两条互相矛盾的住址，也不设计删除如何传遍备份。

**后续追问：** 摘要队列积压约 40 分钟，用户已经聊完一个新项目，你注入旧摘要加近轮，还是同步跑一次短摘要；150ms 内 ANN 只能稳取约 8 条事实时，近轮和摘要谁先让路；小模型摘要把关键截止日期写丢，你补抽取槽位，还是把近轮窗口加长。

**扩展问题：**
- 写出「每用户每月记忆成本」公式，标出哪一项随日活线性涨，哪一项只随超长会话涨。
- 热 KV 按会话 TTL 三天，用户第五天回来、冷层还没抽出事实，第一轮靠什么不空白？
- 记忆检索 P95 从约 80ms 漂到 220ms，你先查跨用户误广播、分片倾斜，还是嵌入模型变慢？

**推理回答：** 千万用户和 150ms 一起否定了「每轮现做摘要」。读路径收成按用户过滤的分层读取，写摘要挪到近线并限制触发面，再用 token 上限和分项成本验收。跨会话连贯性靠近轮原文加现行摘要，不靠把全文历史塞回窗口。

## DESIGN-003. 记忆管理界面必须支持逐项翻看、改写以及把整包带走。有人点了「忘掉去年那套住址」之后，本机与服务器各自落下哪些数据、加密怎么做、每条保留多久，这次清除怎样才能真正覆盖冷备份、审计日志、提示缓存以及向量索引？

**答：** 每条记忆必须是带 `memory_id` 的可寻址记录，而不是写进模型权重的隐式知识。面板只列出该用户的现行条目：原文、类别、来源会话、写入时间、存放位置（本机或云端）、保留期和加密状态；改写落新版本，导出给一份不含密钥、不含他人数据的用户可读包。「忘掉」先对主键打墓碑，使在线读视图立即不可见，再异步清理向量倒排、提示缓存和摘要派生件；冷备份靠作废该条数据密钥（加密粉碎）或恢复时重放墓碑日志，不能指望备份盘在几分钟内被物理擦除。

**深入展开：** 存放位置按伤害分级，而不是按「好不好检索」一刀切。健康信息、证件号、精确住址一类高敏槽默认停在本机安全区，数据密钥封在系统密钥库或 TEE，云端若要为多设备同步服务，只存信封密文：每条（或每用户）一把 DEK，由 KMS 或用户口令派生的 KEK 包裹，服务进程只在当次请求解开需要的那几条。低敏偏好和跨设备摘要可以进云端行存与对象库，静态加密、传输走 TLS，密钥不得进应用日志。向量侧：高敏条优先在端上建小索引；必须上云检索时，向量元数据带 `memory_id` 和 `user_id`，查询先按用户预过滤再做 ANN，禁止先搜后滤。每条自带 `retention`：会话级（进程结束即无）、短 TTL（出差和临时安排，数日到数周）、用户显式长期；与模型隔离的审计轨只记「谁在何时对哪条 id 做了查看/改写/导出/删除」，不回灌提示。删除传播要写成同一条事务意图下的多汇点：①行存 `status=tombstone, deleted_at`；②向量按 id 立刻退出可检索视图，物理 vacuum 允许异步（ANN 删除常常惰性）；③提示和前缀缓存的键必须含 `memory_set_version`，墓碑一写，含该条的缓存整段失效；④滚动摘要若提过该住址，标 `stale` 并排队一次不含墓碑内容的重写，重写完成前注入层不得使用旧摘要；⑤应用日志里的明文回声按 id 遮盖或截断；⑥备份窗口内，恢复流程必须先应用墓碑，或删除该条 DEK 使密文不可读；⑦单用户住址本来就不该进训练语料，若误入，排除名单按 id 进下一轮数据作业。验收不是「面板能看见一条」，而是删除后的下一轮注入日志、缓存命中样本、以及一次备份恢复演练里都不再出现该住址明文。

**后续追问：** 用户只要求忘掉住址，同一条记录还绑着时区，你拆字段删还是整条打墓碑；用户卸载客户端时本机 DEK 怎么处置，云端密文跟不跟着重粉碎；导出包被拷到另一台设备，你给可再导入的加密容器，还是只给一次性明文快照。

**扩展问题：**
- 向量索引的惰性删除可能要数分钟才物理掉盘，这几分钟内怎样保证检索也召不回已忘条目？
- 操作日志依法要留一年，和「忘掉住址」冲突时，日志里只留 id 与动作，还是允许留遮盖后的原文？
- 一台设备已写墓碑，另一台还在离线队列里回放旧写入，墓碑与迟到写谁优先？

**推理回答：** 目标是用户能检查、改写和拿走自己的记忆，并且「忘掉」在所有会把旧值送回模型的路径上生效。约束是 ANN、缓存、摘要、日志、备份各有生命周期，权重也无法按用户擦一条。因此记录必须可寻址、按条加密、读路径认墓碑，备份用密钥作废或墓碑重放。验收看删除后的注入、缓存和恢复演练，而不是看面板文案写得清不清楚。

## DESIGN-004. 有人发现「接受会议」被写进了标题差不多的另一条会话——这套能翻信箱、拟草稿的助手不该再悄悄动别人的日程。读写授权和线程定位该怎样切开？

**答：** 读邮件、写草稿、发送、改日历必须是四套可单独开关的授权；默认只写本地草稿，发送和回复出席弹出确认卡，写明收件人、时间和线程主题。线程定位只认线程 id、消息 id 和引用头，禁止用主题字符串模糊匹配。意图先分类：摘要和待办是只读；任何对外副作用都走工具层确认。指标看误发送率和草稿采纳率，不看回复有多像本人。

**深入展开：** 连接器用最小权限：只读范围就够做摘要和预填草稿；发送和日历事件分开授权，令牌放用户侧保险库，助手只拿短期委托。一次请求：用已有消息 id 拉取当前信 → 沿引用链取最近几封（不是「同主题」）→ 模型提议动作（草稿 / 发送 / 出席回复 / 无动作）→ 策略引擎对写操作生成确认卡，用户点了才调外部 API。错误线程的根因通常是主题相同且参与者略有重叠；所以工具参数里线程 id 必填，模型不准自己按主题搜索。日历还要带事件 id 和实例时间，避免回错到系列会议的其他一次。正文进模型前按规则遮盖验证码和卡号；日志只留动作类型和哈希。模型不可用时退回「生成可复制草稿、不发送」。多账号必须显式选身份，防止用工作账号回私人邀约。

**后续追问：** 用户说「帮我回 OK」但当前焦点不在那封邮件上，你是拒绝还是列出候选线程强制选择；确认之后模型又改了收件人，要不要二次确认；委托令牌被撤后，已经排队的发送如何作废。

**扩展问题：**
- 如何用一周只读影子模式对比人工发送，估出误操作率再打开自动发送？
- 系列会议中只改一次发生时间，出席回复该绑到主事件还是这次例外？
- 草稿引用了另一封邮件的附件，权限检查发生在生成时还是发送时？

**推理回答：** 目标是省起草时间，约束是发送和改日历不可逆。先按动作拆授权和确认，再用协议级消息标识锚住线程。验收看误发送、误回复出席的件数和确认被绕过的次数，而不是看语气像不像。

## DESIGN-005. 「解二次方程」已经连错三题。下一练和随后那句讲解该瞄准哪项先修能力，技能关系网、掌握程度模型和课本检索该怎么一起拍板，而不是仅仅把口吻改软？

**答：** 个性化是选技能和例题，不是选口吻。三道错题先归因到图谱缺口（例如因式分解、移项、判别式），掌握度下调对应节点，下一题从该节点尚未掌握的前置出；讲解检索教材对应章节，逐步推导，并用符号工具核对闭式答案。只改语气会让学生在同一缺口上再错一次。面向未成年人时，对话默认最短留存、可删除、不用于无关画像。

**深入展开：** 图谱节点是可观察技能，边是前置关系；「解二次方程」指向合并同类项、因式分解、求根公式等。掌握度可用知识追踪或简易贝叶斯更新：连续失败则该节点下降，若前置也错就沿边回退。选题约束难度、未重复的表面数字、对准目标节点。判分用规则或求解器，不用生成模型判断数字对错；生成题必须先过求解器，生成讲解必须能对上教材片段，禁止口算一个可能错的根。数据流：作答 → 判分 → 更新掌握度 → 选节点 → 检索讲解 → 模型只组织语言、不得改写公式。教师侧看班级技能热力。学生乱填或直接要答案时给提示不给终解；超出图谱范围就标明并停。模型不可用时退回题库里的人工例题，不要即兴编可能超纲或错解的题。评估看技能曲线和同一缺口是否反复出现，不看点赞或会话长度。

**后续追问：** 三道错题表面都是二次方程，但错因分别是算术失误和概念错误，图谱如何避免一直打同一节点；求解器判对但过程跳步，掌握度加不加分；教材有两种解法时，讲解跟课标还是跟学生上次打开的那一版？

**扩展问题：**
- 掌握度只有约 20 次作答时，怎样避免过早判定「已掌握」而跳过前置？
- 生成题和题库题各占多少，才能在防重复泄露和题目校准之间折中？
- 学生要求「不要告诉老师这次错了」，哪些记录仍必须按学校政策保留？

**推理回答：** 目标是补上缺失技能，约束是讲解必须算对、未成年人数据要最小。先用对错更新图谱位置，再选题和检索，语言生成放最后并受求解器和教材约束。验收看缺口是否合上以及公式差错率，而不是看助手好不好说话。

## DESIGN-006. 断网的飞行模式里，这台手机上的助手仍得改本日日程，并把相册里那张收据讲清楚。哪些技能得常驻端侧？端上模型按什么规格选型？链路恢复后如何判断要不要回云？

**答：** 端侧先保住不连网也能完成的个人数据操作：改本地日历、检索相册和文件、听懂短指令。解释收据若本地只有小视觉编码器，就出结构化字段和偏保守的说明，完整推理等用户同意后再回云。常驻模型按内存和 NPU 分档：始终在线常见是量化后的 1B–3B 级；7B 的 4-bit 权重大约 3.5–4.5GB，加上 KV 和工作区，很多手机不适合当常驻。路由看任务难度、是否要出域知识和当前网络，默认个人数据不出设备。

**深入展开：** 关键手段是权重量化、内存映射加载、把 decode 放到 GPU 或 NPU，CPU 只做编排。电量和发热是隐藏预算：长 decode 要降频或改短答。请求路径：本地意图和隐私分级 → 能本地完成则走日历接口和端侧向量索引 → 否则入队，复网后询问是否用云端模型继续，拒绝就保留本地草稿。模型按机型档位下发不同包，差分更新，失败回滚到上一包。相册索引的 embedding 留在设备上，只有用户明确分享那一张才上传。评估看量化后字段是否仍可用、低端机首 token 和耗电、断网复网会不会把同一日程写两遍（本地事件要有幂等 ID）。「7B 4-bit 能不能跑一下」和「能不能当常驻助手」不是同一道题。复网后若云端把店名理解成另一家，以用户已确认的本地结构化字段为准，云端结果当建议。

**后续追问：** 可用内存大约只有 6GB 的机型，本地模型砍到多大，日历写还保不保完全离线；复网后云端结论和本地抽取冲突，以哪一侧为准；用户从未同意上传，相册检索却出了设备，哪一层策略没挡住。

**扩展问题：**
- 本地小模型和云端大模型对「明天下午和李开会」理解不一致，怎样避免双写日程？
- 端侧要搜「上个月红色小票」，索引建在原图、缩略图还是识别出的文字上？
- 飞行模式结束但漫游很贵，怎样把「能等」和「必须现在回云」分开？

**推理回答：** 从离线改日程和本地看相册这两个必须可用的目标，反推常驻模型必须小、工具必须本地、云只是增强。规格用内存和电量验收，回云用同意和网络状态做门闩。验收看断网任务完成率、复网不双写、相册向量是否离机。

## DESIGN-007. 周五刚发过新版说明书，周一却仍有人引用已经拿掉的登录鉴权那一章。切块、增量建索、以及搜不到就拒答，这条问答链路你会怎么搭？

**答：** 离线把手册解析成带版本和标题锚点的块，算 embedding，并同步写一份关键词倒排；在线先补全指代，再混合检索、重排，只把现行版本的块塞进提示，并强制按引用生成。手册一发布就按文档 ID 增量：新块写入，旧版本块作废，而不是全库重嵌。检索分低于阈值，或召回块的版本对不上现行目录时，直接说没有依据，不许模型补完已删章节。

**深入展开：** 切块跟标题走，重叠大约 10%–20% 的 token，避免把「鉴权」标题和下面的参数表切开；表格按结构解析，不要当纯文本竖切。单块常见 200–800 token：太短检索碎，太长无关句稀释向量。更新链路：发布事件 → 解析得到 (doc_id, version, chunk_id, text, heading_path) → 计算向量并 upsert，同时按旧 version 批量删除 chunk_id。双写倒排是为了错误码、接口名这类稀有词。在线：用对话历史改写查询 → 向量 top-k 与关键词 top-k 做倒数排名融合 → cross-encoder 重排到大约 4–8 块 → 组装带 citation id 的提示。生成后校验每个 id 都能回到块表，对不上就剥句或整段拒答。评估拆开：检索看现行版本上的召回和 MRR，生成看忠实度，并用「已删章节」当负例。高频问法可以缓存检索结果，但缓存键必须含文档版本。块内若出现「忽略以上指令」一类句子，只当不可信正文，不当系统提示。

**后续追问：** 同一标题下连续三版只改了一段，你整篇重切还是按段落指纹只换脏块；重排比生成还慢，你砍候选还是做异步预热；用户问「和上周有什么不同」，检索要不要显式带旧版本，还是拒绝跨版对比。

**扩展问题：**
- 答案必须同时用到限流和鉴权两章，单次 top-k 不够时，怎样发第二轮查询且不把过期块召回来？
- 评估集怎样记账，才能把「没召回现行块」和「召回对了但模型写飞」分开？
- 手册里大量时序图和表格，纯文本切块会丢掉什么，你补结构抽取还是补图内文字识别？

**推理回答：** 失败模式是旧块还活着，以及模型补已删事实。所以版本进入主键，删除是同步硬删，生成必须绑 citation。切块和混合检索服务于召回现行段落，拒答阈值保护忠实度。验收看已删章节引用率为零、现行章节召回，以及该拒的时候是否真拒。

## DESIGN-008. 数仓扩到三千张表，六个列都长得像收入，分析师开口要的却是「上季度收入」。提示里只塞少数候选表的 schema 要怎么做到，跑 SQL 时又怎么拦住整表扫描和越权读取？

**答：** 先检索再生成：用表/列描述、样例值和业务术语表做混合检索，只把少量候选表（例如 3–8 张）及其关联键放进提示。「收入」对上多条核定指标时先消歧或反问。SQL 经过语法检查、只读角色、行/列权限、扫描上限和超时才执行；执行计划若是对超大事实表无谓词全扫，就拒跑。对错看结果表是否符合标注，不看语句是否和金标字符串一致。

**深入展开：** 离线元数据：每列一段审过的描述、少量样例值、拥有者和新鲜度；术语表把「收入 / 净收入 / 签约额」映射到核定指标。检索用问题向量、关键词和术语精确命中，再按外键把漏掉的维度表补上，避免只召回一张事实表。提示里放候选 DDL、两三条已验证的问题–SQL、以及该用户能见的行级约束说明。两个同名列描述不同，就问清口径，不要猜。沙箱角色无改表改数权限，默认限制返回行数，大表必须带分区或时间谓词，解析树禁止多语句和危险外部调用。失败信息最多回灌模型改一次，再失败就停并展示原因。有语义层时，优先让模型查指标定义而不是裸表，减少口径漂移。用户改过的成功 SQL 可进示例库，但必须按权限隔离。评估集用业务问题比结果（允许列别名和排序差异），并单测低权限用户问高管表时检索或执行必须失败。

**后续追问：** 检索漏了维度表导致没有连接，你怎样用空结果和问题里的实体回补；历史日志里的过期表名会怎样带偏示例检索；执行计划的行数估计不准时，你还用什么硬限制护住数仓。

**扩展问题：**
- 用户属于约 200 个权限组时，检索时预过滤和执行时再过滤各有什么漏放或漏召回？
- 如何发现「语句能跑，但聚合粒度和问题不一致」，例如按天问却按月汇总？
- 语义层和裸 SQL 同时能答时，怎样避免两套口径都看起来正确却对不上账？

**推理回答：** 目标是答对业务问题，同时不拖垮数仓、不越权。约束是 schema 放不进上下文，自然语言高度歧义。先检索缩小可见表，再生成，最后用权限和扫描预算卡住执行。验收看结果准确、越权单测和长查询被杀，而不是看 SQL 好不好看。

## DESIGN-009. 生成层必须按调用者可见集来陈述：员工检索只有政策库的 500、看不到财务邮件里的 800，可否把 500 讲成全公司仅有的现行数字？财务管理员两边都进上下文时，如何逼着两数并排并开出校对工单，既不泄漏邮件，也不让特权会话悄悄只留一个数？

**答：** 生成层只叙述本调用者可见证据集里的槽位，不叙述组织里的隐式全集。员工上下文只有政策库的 500，应答「按你可见的政策文本，上限是 500」，可以报这个数，但不能说「全公司只有这一个现行值」，也不能用「也许还有内部通知」去暗示那封邮件。管理员上下文同时有 500 和 800 时，必须走冲突模板：并列两个值、来源类型和日期，并自动开「报销上限不一致」校对工单；特权只扩大可见范围，不授予本轮聊天的裁定权。泄漏是员工答案里出现 800 或「财务邮件」，以及管理员答案只留下一个数却不提分歧。

**深入展开：** 编排顺序是身份 → 投影可见块 → 抽槽 → 按基数选模板 → 生成 → 输出守卫，而不是先生成再按角色改口。员工束：注入集合是其可见块的子集；槽位若只有一个值，允许给出该值，话术锁在「依据你权限内的政策库（文档 id / 版本 / 日期）」；禁用「现行唯一」「其他口径已废止」这类全集量化。系统即便在特权侧登记了「该槽位另有不可见来源」，也不得把「存在未授权材料」写进员工回复——那会泄露邮件的存在。管理员束：同一槽位抽出两个及以上的值，就强制结构输出，例如 `{slot:"报销上限", values:[{n:500, source:"policy"},{n:800, source:"finance_mail"}], ticket_id}`。解码后校验：只出现一个数字、或把两个数收成第三个数，整段失败，回退到结构卡。工单带上两个原文块 id，把裁定留给政策库维护流程，不留给这一次对话。输出守卫对员工扫描：可见集以外的 800、「财务邮件」等来源词不得出现，除非可见集里真有同名标题。对管理员扫描：两个源数字都必须出现，且不能只复述其中一段。边界：员工追问「是不是有内部邮件调过额度」，没有可见依据就拒答或请走行政渠道，既不否认也不确认。管理员说「按邮件的来，直接答 800」，本轮仍不得改口，只能把该偏好写进工单备注。可见集版本必须进入会话与答案缓存的隔离键，避免管理员答被员工复用。评测必须成对跑同一问句：员工样本不得含 800 和邮件痕迹；管理员样本必须双值加工单 id。这里不把「哪一份更权威」交给生成模型去自动盖章——那会把特权会话变回「挑一个顺口的数」。

**后续追问：** 员工稍后被授予那封邮件的可见权，下一轮要不要主动改口并提示「你现在能看到第二份材料」；管理员把整段回答转发给员工，前端是按接收者重跑可见集，还是把原答案当静态截图冻结；槽位抽取漏掉邮件里的 800，管理员模板以为只有一个值，你在哪一层再做一遍数字扫描。

**扩展问题：**
- 可见集为空时，员工能不能用模型常识猜一个上限，还是必须拒答？
- 校对工单的受理人若就是提问的管理员，怎样避免自己销单而不改政策库？
- 如何用成对账号探针证明「员工零邮件痕迹、管理员强制双值」，而不是只看平均答对率？

**推理回答：** 目标是员工读不到邮件里的数，管理员也不能把冲突收成一句流畅的唯一答案。约束是两边看到的证据集合本来不同，而生成模型倾向写「只有一个正确答案」。所以先投影可见集再分模板：员工只叙述可见值且不做全集断言，管理员走强制并列加工单。验收看成对探针和输出守卫，而不是看谁报的数字更像「真正的现行政策」。

## DESIGN-010. 买家搜夜间跑步用的红鞋、预算不超过 800，商品库对不上精确匹配；意图解析把鞋码弄错，候选被热销款塞满。属性与库存筛选该在召回之前做，还是等到排序完成？

**答：** 价格上限、有库存、用户坚持的颜色、可售状态这类硬约束应在召回阶段就作为过滤或独立通道生效，不能等排序后再砍——否则前若干名会被无库存爆款占满，滤完变空。夜跑、缓震这类软偏好放进召回扩展和排序特征，允许近邻品类进入，再在结果上解释“为什么算相关”。查询理解给出的槽位要分成必须和可选；抽错尺码时应让用户改槽，而不是默默改写查询。

**深入展开：** 链路是：查询 → 抽出颜色、价格、场景、品类等槽位并做同义扩展 → 多路召回（倒排、类目预测、向量相似、导航路径）→ 硬过滤（价格、库存、配送、合规）→ 粗排 → 精排（相关性、转化、多样性、曝光公平）→ 业务规则重排 → 无结果时放松可选槽。生成模型适合做槽位抽取、同义词和导购文案，不适合单独当召回引擎。大目录下若向量先取前 200 却不过滤库存，精排再好看也会在展示层塌掉。“800 以内”是硬过滤，比较的是可售价而不是划线价；“适合夜跑”若无结构化字段，用场景标签、评论向量或反光、夜灯等属性做软匹配，并在卡片上给出依据。粗排要加多样性或按品牌配额，场景类查询提高属性匹配权重、降低纯历史销量权重。零结果不要在不提示的情况下用完全不相关的畅销货填满。付费排名不能把唯一匹配的长尾商品压没。指标看无结果率、价格和颜色约束满足率、转化、延迟、曝光多样性。

**后续追问：** 用户没写尺码但画像里有，你自动加硬过滤吗；促销价抖动造成过滤价和展示价不一致，以谁为准；向量把“红”扩成酒红，算命中还是要二次确认。

**扩展问题：**
- 硬过滤放在召回查询里，和放在召回后、排序前，空结果率和性能差在哪？
- 夜跑是场景不是字段，怎样建一条不依赖生成模型也能工作的降级召回？
- 如何用“结果集中违反价格约束的条数”作为必须为零的线上检查？

**推理回答：** 目标是满足硬约束且不空，约束是目录稀疏和爆款偏差。先分硬软槽位，硬条件进召回过滤，软条件进排序和解释。用约束满足率和无结果率验收。

## DESIGN-011. 工单、PDF 和各部门 wiki 挤在同一库，答完题得串三份材料，评审还规定每句都能点开对照原文。引用对齐、有界多跳检索、找不到就停笔，这三截怎么接到一起？

**答：** 企业文档问答的难点常常是一次 top-k 装不下推理链。做成有界迭代检索：第一轮用改写后的问题取种子块，抽出缺失实体再查第二、第三轮，每轮带文档类型过滤，最后把大约 6–10 个带锚点的块交给生成。生成后做引用对齐，每个句子映射到块标识和偏移，点不开或对不上原文的句子删掉。三轮之后仍缺关键块就整题停，列出已找到和仍缺的部分，不拼一个看起来完整的答案。

**深入展开：** 离线由连接器拉 wiki、工单和 PDF，解析保留标题路径、工单状态、页码，切块带 source_type。在线由计划器判断是否需要多跳，最多三轮，以免把 P95 从约 1s 推到数秒以上；第一轮结果可以先流式说出已找到的部分。引用对齐用生成后核对：句子与块内片段匹配，低于阈值标为无依据。源文档下线则块标识作废，已缓存答案按文档版本失效——「能点回原文」包含原文还在。每轮检索都做权限过滤，但本题的中心是推理链和引用，而不是大规模 ACL。审计保存检索轨迹和最终引用列表。工单是活文档，页级锚点容易漂，更稳的是段落哈希或评论 ID。评估集要标出「必须同时命中的块集合」，防止只靠一份材料刷高分数；不可回答题单独记账。

**后续追问：** 第二轮把范围漂到无关部门，你用什么约束把跳限制在种子文档的链出关系上；引用对齐砍掉一半句子后，产品展示残缺答案还是改拒答；扫描件 PDF 没有可选中文本，引用定位到页和框，还是先识别文字再对段落。

**扩展问题：**
- 三份材料时间戳相差一年，每条引用旁要不要标生效日期？
- 多跳评估题怎样标必须命中的块集合，才不会让单份材料刷高分？
- 源文档下线后约 10 分钟内旧答仍能点开，缓存和索引谁没失效？

**推理回答：** 目标是可点击的完整答案，约束是窗口装不下三跳、原文可能已下线。检索改成有界迭代，生成服从引用对齐，缺块就停。验收看必须命中块的集合、无依据句率为零，以及原文下线后旧答失效。

## DESIGN-012. 成交负责人能整份拉走网盘里那份合同，路人检索只能看到标题，可预览身份却在问答里拼出了条款正文。块级 ACL 要按三种动作拆权：「可下载」与「可检索元数据」以及「可注入正文」。吊销时这三层时间窗能否各自规定？

**答：** 文件级「能看见」不够用，必须按动作拆权：`search_meta` 只允许标题、类型、更新时间等非正文字段进入命中卡片；`inject_body` 才允许切块正文进入模型提示；`download` 才签发对象字节。预览账号通常只有元数据检索（最多再加打码封面），没有注入权，问答一旦把「搜得到」当成「能喂模型」，就会把条款拼出来。回收窗口按层分开写：下载短链用秒到分钟的签名寿命；注入权必须在下一次组提示前切掉；标题从搜索消失可以略慢，但不能把「还能搜到文件名」解释成「正文仍对模型开放」。

**深入展开：** 入库时每个块带 `doc_id`、`chunk_id` 和三个互不推导的授权集合，禁止用一个 `visible` 布尔量兼管三件事。查询展开调用者身份后，三路各走各的闸。检索投影只返回元数据字段：向量或关键词可以命中该文档 id，payload 和日志都不带条款原文，侧栏卡片只渲染文件名和类型。组提示是第二次鉴权：`inject_body` 为假的块不得进入 messages，也不得以「相关片段」明文出现在调试面板；预览用户若产品允许「知道有这份合同」，最多注入「文件名 + 无正文占位符」。下载按钮与会话脱钩，另签短时对象凭证（示意：30–120 秒），过期即 403。事故根因几乎总是把预览映射成「只读可见」，检索服务把全文当 payload 回给编排器，生成器照单全收——缺的是注入闸，不是另一句「请勿输出无权内容」。回收分层写成明确 SLA，而不是绑同一次全库作业：`download` 靠短 TTL 和停签，已发出的链随寿命死亡，不必等索引；`inject_body` 靠权限视图版本，目标是下一次交互请求前生效（示意：秒到一两分钟），进行中的流式若已注入则停后续句并剥可点击正文；`search_meta` 的索引传播可以放到数分钟级，因为标题泄漏面小于正文，但标题本身含项目暗号时，要把这一层收紧到与注入同级。答案回放和「已读片段」缓存必须带动作位，撤注入后不得把旧正文再灌进本轮。验收用三组探针：访客用条款里的独特句提问，命中卡可以出文件名，组装日志里正文 token 必须为 0；预览账号点下载必须失败；对接人三路都通。撤掉预览的注入权之后，下一问不得再拼出已经见过的句子。

**后续追问：** 预览政策写的是「可看带水印的首页图」，你把首页 OCR 写进元数据，还是一律算 `inject_body`；同一人既是访客、又被临时加进对接组，动作位冲突时按并集放行，还是按本会话选定的角色钉死；`search_meta` 已回收但对象副本还在，问答侧栏的「打开原件」跟哪一层的 SLA 走。

**扩展问题：**
- 切块时标题被预置进每块正文开头，只有元数据权的用户会不会借向量命中读到条款首句，入库怎样把标题字段和正文字段物理拆开？
- 前两轮已经对预览用户注入过一段，第三轮撤权，历史消息里的正文还能否回灌本轮提示？
- 如何用「命中卡有标题 / 提示无正文 / 下载失败」三元组做发布门禁，而不是只扫答案里有没有敏感词？

**推理回答：** 失败是预览用户在问答里读到了只有对接人才该拿走的正文，说明可见性被压成了一比特。把搜索、注入、下载拆成独立动作，生成路径只认 `inject_body`。回收按各层对象的生命周期分别写窗口：链先死、注入次之、标题可以稍慢——除非标题本身敏感。验收看三组探针和撤权后的下一轮组装日志，而不是看模型会不会自己保密。

## DESIGN-013. 票据流水线每天大约要过手 4 万张发票影像、抽出 12 个栏位，约 1/3 来自手机斜拍。OCR 识别、版面分析、字段抽取模型、人工复核怎么交接，金额分数不够时怎样才能进不了总账？

**答：** 按「能解析再抽字段、能勾稽再入库」接力：纠偏去噪 → OCR → 版面/表格 → 按 schema 抽 12 字段 → 金额与税率交叉校验 → 置信度门控。低于阈值或校验失败的单据进人审，人审通过才写账务；模型不得直连总账写接口。每个字段保留页码、框坐标和原文，对账能点回像素。拍照件单独走增强和阈值，不要和扫描件共用一条及格线。

**深入展开：** 4 万/天平均大约每秒不到 1 单，高峰按 5–10 倍留 OCR 和推理队列即可，瓶颈常常是人审和下游入账，不是生成模型。数据流：上传后先做安全扫描 → 图像质量分（模糊、反光）→ 拍照件去透视 → OCR 出字和框 → 版面划分表头、行项目、合计 → 抽取器只看相关块，不要把几十页附件全文塞进上下文。字段包括销方、税号、日期、币种、净额、税额、总额等；规则上净额加税额应约等于总额（允许最小货币单位误差），税号走校验位，日期不得晚于今天。置信度由 OCR 字置信、抽取分和规则是否通过合成，任一层低就挂起整单或单字段。人审界面并排裁切图和识别字，改值回写金标。提示、模型和规则打包发版，用昨天失败件回放。多票一页、多页一逻辑单、手写金额要能拆单或拒识。这是结构化抽取，不要做成全文问答。

**后续追问：** 总额 OCR 对但行项目加总不对，你信哪边、人审看什么；同一供应商版式稳定时，模板和生成抽取谁更安全、何时切换；人审积压数小时，哪些字段可以进暂存、仍不准进总账。

**扩展问题：**
- 给出置信度合成的示意，并说明为什么不能只用模型自报信心。
- 拍照件单字错误率到约 15% 时，先加图像增强还是加人审席位，你用什么曲线决定？
- 怎样构造负例，防止页脚电话被写成税号？

**推理回答：** 目标是字段可对账、错金额不入总账。约束是拍照质量差，OCR 和模型都会静默错。用证据框、勾稽和人审把门控放在写账之前。验收看入账差错率和人审时延，而不是看抽取结果看起来是否完整。

## DESIGN-014. 大约三千条改 repo 的作业在午间高峰同时执行，队列来自编程 agent。每条任务该如何安排一份一次性销毁的沙箱，并布置节点上的仓库快照缓存、密钥彼此隔离和出站网络策略，既要顶住这份并发，也要把一条任务的成本算清楚？

**答：** 每个任务领取一份用完即毁的沙箱（容器或微虚机），可写层不在用户或任务之间复用。仓库按 `repo_id@commit` 做成节点上的只读快照，任务只叠一层稀疏检出。生产密钥不准进沙箱，git 和包缓存用任务级短令牌；出网默认拒绝，只放行内部 git 和经拉取缓存的包登记处，并封掉云主机元数据链路。扩容看「正在执行命令的沙箱」，不看「等模型回包的在途任务」。单任务成本拆成沙箱秒、缓存未命中时的克隆，以及通常占大头的模型 token。

**深入展开：** 入队后的数据流：调度到对某仓库快照亲和的节点 → 挂载或 `clone --reference` 式对象库 → overlay 工作区 → 以无特权用户启动、只读挂上依赖缓存 → 执行工具 → 回收可写层。3000 在途不等于 3000 台满配机器：编程 agent 大部分墙钟在等模型，编译和测试才吃 CPU。示意拆分：在途约 3000，同时跑命令的大约 300–600，其余休眠可写层或根本不占执行槽。基础镜像预热，沙箱从快照拉起应对准秒级，而不是每次拉镜像加分钟级冷启动。仓库缓存的键是 `repo + commit + lockfile_hash`：热门裸库和按锁文件固化的依赖层只读共享，未命中才回源；键少绑一维就会把脏 `node_modules` 或错误提交串到别人的任务。密钥：环境变量和常见密钥路径在启动前剥离；仓库读权限由经纪人签发、TTL 按任务墙钟（例如 15–30 分钟）和最小 scope 收口；组装提示时若检索命中疑似密钥文件，只送路径和行号范围。出网用默认拒绝的策略路由加 DNS 白名单，阻断链路本地和云元数据地址；装包走组织内 pull-through，不给开放互联网。成本账（示意）：墙钟 8 分钟、其中真正执行 2 分钟时，若沙箱按 8 分钟计费，机时会比「只在执行期唤醒」贵三到四倍；一次中等修复的模型侧常是数万到十几万 token，往往超过沙箱机时。把同仓库任务打到同节点写成调度亲和，缓存命中率才上得去。指标看沙箱逃逸、出网违规、冷启动 P95、缓存命中、在途/在跑比、以及机时与 token 的分项美元。这里验收的是执行底座，不是补测或自动审 PR 的短闭环。

**后续追问：** 依赖安装必须访问公共登记处时，你开一条经代理的域名白名单，还是预置厂商镜像并禁止即时安装；同节点缓存了两个租户的私有仓库对象，层隔离漏了会漏出什么；模型要对外发起一次 HTTP 才能复现缺陷，默认拒绝后任务是失败、升人批，还是签发一次性域名。

**扩展问题：**
- 怎样用「在途任务数 / 在跑沙箱数」证明该扩的是模型排队，而不是 3000 份满配虚机？
- 快照按 commit 还是按树哈希，force-push 和子模块各自会命中哪类脏缓存？
- 任务结束后工作区要留约 15 分钟给用户下载日志，销毁时钟和短令牌 TTL 谁先到期？

**推理回答：** 目标是同时跑上千个互不信任的改仓库任务，并且单任务账能拆开。约束是密钥、出网和磁盘都会在任务之间泄漏，而模型等待会让「按在途数买机器」爆掉。所以沙箱短命、快照只读共享、密钥和出网收到最小、扩容看在跑执行。验收看逃逸和出网、缓存命中，以及机时与 token 的分项成本。

## DESIGN-015. 同一张客服单已被三路专家（物流、退款、技术支持）传来传去五次。入口分诊、交接协议、升人工，你打算冻结哪些规则，免得用户把诉求再叙述一次？

**答：** 入口只放一个分诊 agent，输出单一主意图和可选次意图，一次只交给一个专家，并把已收集槽位写入共享会话，禁止专家互相点名转来转去。每个专家只有本职工具：技术支持进程里根本没有退款接口，改地址、退款额度走独立政策引擎。循环用最大跳数（例如 2）和「同一专家不得被连续退回」打断，再转就升人工，并自动带时间线摘要。若单模型加订单、物流、知识库工具已经稳，先不要拆三个专家。

**深入展开：** 交接是结构化记录：原因、已填槽、已尝试工具、对顾客可见的摘要；下一个 agent 不得再问订单号这类已填槽。一句话两个诉求（退款加改地址）由分诊排成有序子任务，在同一会话里串行，避免两个专家同时改政策。共享知识库必须同版本，免得退款话术和技术支持各引一版。每跳记 agent_id、工具和延迟，看板上盯人均跳数和原路退回率。评估：一次解决率、转人工率、错误退款率，以及顾客被重复询问订单号的次数。高峰坐席不足时，转人工改为排队并报等待，专家可以继续只读安抚，但不放宽写权限。先证明单 agent 在意图互撕、工具权限必须隔离时才拆，否则编排本身就是故障源。

**后续追问：** 分诊置信度大约只有 0.4，你先问一句澄清还是进通用专家；专家 A 认为该退、B 认为不该退，以谁的政策引擎为准；最大跳数用尽但顾客拒接人工，会话怎么收。

**扩展问题：**
- 测试里如何注入「物流推技术、技术推退款」的脚本，在上线前暴露循环转交？
- 顾客已报订单号，下一跳又问了一遍，你判槽位没传，还是提示没禁止重问？
- 晚高峰人工队列约 30 分钟，只读安抚由谁生成，谁仍被禁止碰写操作？

**推理回答：** 失败是循环和重复询问，所以分诊只定一个主意图，交接强制带槽，跳数硬顶，写操作不共享。先证明单 agent 不够再拆。验收看跳数、重复问槽次数和错误副作用，而不是三个专家能否各自演示一遍。

## DESIGN-016. 关于市场综述稿，团队在争：交给单个 agent 依次调网页搜索与电子表格工具，还是由一个规划模块再挂三名并行 worker？token 和墙钟时间都会被成倍放大，这笔账如何决定拆不拆成多 agent？黑板里每件工件归谁所有，何时拆完反而更亏？

**答：** 先按依赖画任务图。边都是串行、单窗口也装得下原材料时，一个 agent 加工具更便宜、轨迹更好查。只有子任务真正互不依赖、或一份材料就会把窗口撑爆时，才加规划者扇出 worker。账要同时算 token 乘数和墙钟：拆开后总 token 常常是单 agent 的 2–4 倍，墙钟只有在关键路径变短时才回本。黑板上每份工件有唯一 owner、版本和冻结态，worker 不得改别人的已定稿；规划者只写任务图和验收清单，合并者只读冻结件。

**深入展开：** 单 agent 示意账：大约 8 轮，每轮输入 3k–5k、输出 0.5k–1k，合计约 3 万–4 万输入加数千输出，墙钟是轮次相加（工具等待通常占大头）。规划者加 3 个 worker：规划一次约 2k+0.8k；三个 worker 各 5–7 轮，单轮上下文可以更窄，但轮次乘在人数上，输入很容易到 6 万–10 万；再加一次合并约 6k+1.5k。若三个子问题本来就要排队做，墙钟几乎不降，只是多付一倍以上 token 和三条必须对齐的痕迹。并行回本的条件是：子问题之间无边、各自工具或权限不同、单 agent 为读三份长材料会反复爆窗。共享状态用黑板而不是群聊：记录 `artifact_id, type, owner_role, version, hash, status`。调研 worker 只写 `evidence_*`，数据 worker 只写 `table_*`，撰稿只读已冻结的证据和表；要改数字必须回到数据 owner 出新版本，禁止在散文里把数字「改圆」。异议写成新版本加结构化评论，不用一份可变文档当唯一真相。编排只允许无依赖边并行，有依赖就串行，避免三角色在同一条对话里讨论格式。不值得拆的信号很具体：输出只是一段短答、工具调用少于约 10 次、子任务共享几乎全部上下文、预算只有几分钱、或排障必须沿一条轨迹复盘——这时协调税高于并行收益。评估看成功率、总 token、墙钟、人工返工，以及「拆开之后墙钟几乎没变」的比例。这里比较的是一次作业的拓扑，不是客服工单在专家之间转交。

**后续追问：** 三个 worker 里有一个超时，你带着两份冻结件合并，还是整图失败；规划者写的验收标准和数据表对不上，终审权在规划者、数据 owner 还是人；单 agent 基线已经在约 90 秒内完成，拆开后 token 翻倍却只快 10 秒，你还保留拆分吗。

**扩展问题：**
- 把「token 乘数 × 墙钟缩短」画成是否拆分的决策表，哪一格必须退回单 agent？
- 黑板用带版本的对象存储，和用一份加锁的可变文档，对「谁改了数字」的审计差在哪？
- 两个 worker 需要同一份财报原文，是共享只读快照，还是各自抓一份再在合并时对哈希？

**推理回答：** 从「子任务能不能并行」和「单窗口装不装得下」决定拓扑，再用 token 乘数和关键路径墙钟验收，而不是先上多个角色。工件所有权防止合并阶段改写证据。当乘数明显而墙钟几乎不降，就退回单 agent。

## DESIGN-017. 每一个 PR 都得附上一条额外的单元测试并挂上评审意见，但模型吐出的代码绝不可放到生产环境的 runner 里执行。评审评论这条回路、一次性沙箱，再加上仓库只读上下文，如何串起来，好让生成测试与查漏洞共享同一批证据？

**答：** 生成路径和审查路径读同一份只读上下文：变更 diff、相关文件、依赖锁文件、已有测试布局、静态分析和代码搜索命中。生成只许小步补文件，补丁在一次性沙箱里跑（无外网、无生产密钥、有时间和内存上限）；审查不对生产环境 apply 任意补丁，只对 diff 出带行号的发现并挂到评论。两边都把测试日志和静态分析当证据，模型解释必须指向这些工件，避免空口通过。

**深入展开：** 数据流：PR 事件 → 取 merge-base 和变更文件 → 按调用图或检索补齐被改函数的调用方 → 在数万 token 量级封顶的窗口里组装上下文，超出就裁。生成：提议补丁 → 打到只读 checkout 的写拷贝 → 沙箱跑目标测试 → 失败则回灌日志再改，轮数封顶。审查：同一 diff 加同一测试结果 → 输出文件、行、严重级、规则和证据，安全类默认人工必看。沙箱用独立容器或虚拟机，丢掉多余权限，密钥只用一次性假凭据。交付物是 PR 上的测试补丁和评论，循环短、权限面小，不要扩成在仓库里长时间自主改代码的代理。指标：补测通过率、假阳性评论率、高危漏报、沙箱逃逸零事件、单 PR 的时间和 token 成本。模型不可用时退化为只跑静态规则，不发生成补丁。组装提示时若搜索命中了疑似密钥文件，只送文件名和行号范围，不送原文。

**后续追问：** 沙箱里测试要连数据库，你提供一次性库镜像，还是禁止这类 PR 自动补测；审查要删、生成要留，以测试结果还是以更高优先级的安全规则为准；日均约 200 个 PR 让沙箱排队 10 分钟，怎样把安全审查和锦上添花的补测分成两个队列。

**扩展问题：**
- 生成的测试只断言不抛异常，覆盖率是绿的，你用什么契约或变异来拒绝这种补丁？
- 审查要判断依赖是否倒退，除了 diff 还要读哪份锁文件，没读到时能不能写「无风险」？
- 未改动文件里出现密钥，怎样保证它进不了模型上下文？

**推理回答：** 约束是生产 runner 不执行模型代码，所以副作用进沙箱，生产侧只收评论和人工合并。生成和审查共享 diff 与测试证据，避免两套幻觉。验收看沙箱策略、评论带证据率，以及密钥是否进提示。

## DESIGN-018. 墙钟预算卡在 8 分钟附近、单稿 token 花到数美元量级，这份竞品调研还得带着引用交出去。子问题怎么摊给同时跑的 worker，搜索与抓取的配额、缓存如何顶住限流，去重来源、核对引用应挡在组稿前那一环？

**答：** 规划者只澄清范围并产出互不重叠的子问题图，每个子问题交给一个 worker 并行跑「生成查询 → 搜索 → 抓取 → 抽出可引用片段」，主上下文只回收结构化笔记。搜索和抓取走租户令牌桶加按域名的礼貌度限制，查询结果和页面快照分层缓存，避免八路同时打穿同一开放 API。组稿之前设独立核验层：URL 规范化和正文哈希用来源去重，每条论断必须能在抓取快照里落到原文 span，对不上的句子不得进入组装提示。

**深入展开：** 数据流是：题目 → 规划者输出 `{sub_q, depends_on, search_budget}` → 调度器只对无依赖边扇出。并发上限按外部配额反推，而不是按 GPU 空闲：示意上若租户搜索接口约 10 QPS、每个子题要 3 次查询，同时跑超过约 3 个 worker 就要排队或合并查询；抓取再加「每域名 1–2 路、随机抖动」。Worker 只写笔记 `{source_id, canonical_url, snapshot_hash, quote, claim}`，不回传整页散文。缓存分两层：`normalize(query)` 到结果列表（TTL 数小时，键含地区和安全策略版本）；`canonical_url` 到内容寻址快照（TTL 数天）。同一报告内和跨报告共享这两层，扇出才不会把同一篇通稿抓八遍。去重去掉跟踪参数、合并镜像宿主、正文去导航模板后再哈希；辛迪加转载记成一条证据，附录可列站点，不把五个转载站当成五个独立来源。核验器是组稿前的硬门：quote 必须能在快照中作为子串对齐（允许空白折叠），数字和专名再做一次精确匹配；失败则丢句或标 `unverified`。过了这扇门，组装模型不再持有搜索工具，只能看见已核验笔记。延迟账（示意）：规划 5–15 秒，两到三波并行搜索/抓取各 10–20 秒，抽取加核验 20–40 秒，组稿 20–40 秒；8 分钟预算限制的是扇出波次和每波查询数。成本账：8 个 worker 各 2–4 次中等上下文调用，加上规划和组稿，token 常常是单循环的 2–4 倍；把数美元打住的旋钮是缓存命中率和并发封顶，不是组稿时再「补搜两篇」。抓取正文当不可信数据，域名要能拒绝，重定向次数封顶。评估分开记子问题覆盖、唯一来源数、核验通过率、超预算中止率；「组稿之后才发现引用对不上」必须为零。

**后续追问：** 三个子问题都打到同一份财报，去重后证据不够，你加一波扇出还是放宽「同源」上限；搜索接口突然返回 429，是降并发、改用未过期缓存，还是把该子题标失败并继续组稿；核验刷掉大约四分之一句子，报告是缩短，还是带 `unverified` 标记交出去。

**扩展问题：**
- 子问题有「先确认公司主体再查子公司」的依赖时，DAG 怎样避免无脑全并行？
- 快照和现网在约 10 分钟内不一致，引用以抓取时刻为准，还是强制重抓？
- 怎样用每份报告的搜索次数、缓存命中和核验失败句数，证明钱花在抓取层而不是组稿模型上？

**推理回答：** 8 分钟和数美元一起否定了单线程长爬，也否定了组稿阶段再上网。先把题目拆成可并行的子问题，用配额和缓存保护搜索/抓取接口，用去重和快照对齐把不可引用的句子挡在组装之前。验收看墙钟、花费、唯一来源和核验通过率，而不是看报告页数。

## DESIGN-019. 大促期间的电商客服台，高风险操作得先经确认，还要在约 3 秒内调出订单、按当前生效的退货条款作答。意图分类、工具授权、人工接管之间如何切分，才能保证机器人不会自行发起退款？

**答：** 这是单会话机器人：身份绑买家，意图分成查询、政策解释、写操作三类。查询走订单服务，政策走带版本的知识检索，退款和改地址只生成待确认指令，用户明确同意后再调工具。3 秒里，身份和订单应在数百毫秒返回，语言模型只负责把工具结果说清楚，不能当订单系统。政策不确定、用户要求超权或需要安抚升级时转人工，并带上已查到的订单摘要，避免坐席再问一遍。

**后续追问：** 订单接口 300ms、生成还要约 2s，你砍检索、换小模型，还是先回「正在查这张单」；用户说按上次那样退，槽位从历史取还是必须重确认；检索命中了过期的七天无理由，怎样强制改走大促专项规则。

**扩展问题：**
- 用户情绪激烈但只要查物流，转人工看情绪、看意图，还是看坐席水位？
- 工具返回不可退，模型却答应能退，输出层用什么校验挡住？
- 流量再乘十，哪些请求改成预写政策卡片，哪些仍走生成？

**推理回答：** 3 秒和不能私自退款是两条硬约束。工具结果先到，确认门闩拦住写操作，模型只做表述。验收是错误退款为零、政策版本命中、P95 延迟，而不是话术有多像人。

## DESIGN-020. 单测只盖住四成的老代码栈，任务是把 Python 2 升到 Python 3。随后模型一次性抛出一份触及 200 个文件规模的改动包，接着回归全军覆没。怎样把这次搬迁收成可核验的闭环，以免把行为走样误认为成功？

**答：** 成功标准是“切片级行为与基线一致并且测试变绿”，不是“生成了能编译的新代码”。按依赖图把仓库切成可独立验证的模块：先迁叶子，每片只改接口边界以内的文件，补丁一出就跑该片单测、契约测试和冻结的输入输出金样。覆盖空洞处先补能表征行为的金样或特性测试，再让模型改代码；200 个文件的巨型变更必须拆掉。人工审查看语义等价和回滚点，不看新代码像不像目标风格。

**深入展开：** 数据流是：静态分析抽出模块依赖、入口和外部 IO → 为每个切片在旧运行时上录制或补写金样（HTTP 响应、数据库行、文件副作用）→ 模型只看到该切片源码、目标语言或框架文档片段、失败日志 → 产出 diff → 沙箱执行测试 → 失败日志回灌有限轮次 → 通过后开小规模变更请求。量级上，例如约 8×10⁵ 行、覆盖约 40% 时，一次 200 文件补丁会让审查和二分定位同时失效；切片宜控制在数十个文件、一次能在数分钟跑完的测试集。兼容层（适配函数、类型转换、双栈路由）允许新旧并存，避免必须大爆炸切换。行为漂移常见于隐式的字符串与字节差异、异常类型变化、小数与浮点、并发和 IO 时序、依赖大版本接口。金样必须覆盖这些，而不是只证明“能 import”。边界：没有自动测试的核心入口禁止直接改生产路径，先加金样再改；模型不得改断言来让持续集成变绿；执行必须在无密钥、无生产网络的沙箱。回滚以版本控制还原加特性开关为单位，不指望再让模型“改回去”。

**后续追问：** 金样是在旧解释器上录的，目标运行时本身语义有变，你怎样区分录制环境差和真实行为漂移；依赖图有环时切片怎么切，接口契约放在哪一层；模型反复靠改测试过门禁，编排层哪一步硬拦截。

**扩展问题：**
- 某模块只有手工验收、没有任何自动测试，你用最少的表征测试怎样把它变成可迁切片？
- 兼容层打算留一个季度，怎样防止业务继续往适配层堆新功能？
- 如何用“金样失败数 / 被模型改过的测试数 / 人工回滚次数”证明迁移在收敛，而不是在改考试？

**推理回答：** 目标是行为等价，约束是低覆盖和不可审的巨型 diff。先补可检验信号，再按依赖图小步改，用金样和“禁止改测试”守住成功定义。验收看行为一致和回滚能力，不看生成行数。

## DESIGN-021. 误删会扣掉创作者分成，因此 UGC 图文必须在公开前挡住仇恨和露骨色情。哈希、分类器、人工审核如何分层；政策修订之后，怎样按当时版本重放那次决定？

**答：** 发布前做成漏斗：第一层用精确哈希、感知哈希和关键词规则秒级拦住已知样本；第二层用文本和视觉分类模型打分，两端阈值分别对应机拒和机过，中间进人工。误杀伤收入，所以模糊样本、尤其是高分成作者的内容默认进人工而不是机器直接拒。每条判定写下政策版本、模型版本、分数和人审员，申诉时按当时版本回放，不用新政策重判旧帖来证明「当时就该拒」。

**深入展开：** 提交后先看账号风险和元数据，再走哈希库和轻量规则，然后多模态分类，把分数量化成放行、拒绝、送审。阈值按类拆开：明显色情可以偏向召回，争议讽刺必须更低误杀，用验证集分别画准确率–召回曲线，不要一个全局分。同一内容对多地区可以有不同动作，存储和分发要按地区隔离，避免 A 区放行缓存打到 B 区。人审队列按风险乘曝光排序，模糊样本的时效用分钟级 SLA 示意，不能把作者挂在「审核中」过久。指标：违规漏放、误杀、人审一致、发布增加的 P95 延迟。政策是规则表，模型是分数校准，两者解耦；改政策先回放历史样本再切。这不是直播流审，没有一秒级死线，但发布阻塞也不该拖到作者失去进度可见性。对抗上，微扰逃哈希靠模型，用户文本里的指令不当系统提示，漏放样本补回哈希库。

**后续追问：** 误杀压到约 0.5% 时漏放翻倍，你动哪一类阈值，还是加人审；同一张图在两个地区政策相反，存储和分发怎样避免缓存串区；申诉成立后，样本进训练集还是只进规则白名单，怎样避免过拟合申诉账号。

**扩展问题：**
- 政策周更，怎样用回放集证明只动了目标类，没有把上周已放行的教程图打成色情？
- 正文干净、图里小字是仇恨口号，融合层以谁为准，漏了哪路特征？
- 人审员对反讽看法不一致，金标准怎样定，才不会让模型学会某个班次的口味？

**推理回答：** 目标是发布前拦住明确违规，约束是误杀损收入、判定必须可申诉。漏斗把确定项交给哈希和模型两端，模糊项给人，版本化保证回放。验收是分类别的漏放和误杀、回放一致、以及发布延迟，而不是单一准确率。

## DESIGN-022. 三分钟成品是用户按本人歌词生成的，现在只想重渲副歌那八个小节，且仍对得上词。离散音频 token（也可以是潜变量）按时间窗怎么切开，并与歌词时间轴对齐？

**答：** 把歌当成带结构标签的时间轴：主歌/副歌起止、歌词音素对齐、可选的伴奏分轨，而不是一条不可切的波形。整曲可在离散音频 token 或压缩潜空间上一次生成；重做副歌是在该时间窗做条件重采样，冻结窗外状态，窗口边界做短交叉淡化。前十几秒 token 就绪就可以开播，不必等满三分钟。点名模仿在世艺人或复刻已有作品的请求，在提示分类和输出指纹处拦截，不把希望寄托在生成核「自己知道收手」。

**深入展开：** 常见两段：先把主题收成带段落标记的逐行歌词，再在 codec 离散单元（示意：每秒几十到上百 token）或潜变量上生成，解码回波形后做响度规范化（目标响度由产品自定，例如按广播常见 LUFS 区间）。词曲对齐是一条时间映射：每个词或音素对到 token 下标或潜变量帧，否则「副歌」会切错拍。编辑接口吃 `section_id` 或 `[t0, t1]` 加可选新词；模型看到的条件是窗外上下文加窗内新歌词。边界留约 100–300ms 重叠做 crossfade，避免相位断裂。若模型暴露人声/伴奏分轨，只重做人声更稳。长音频按段落写检查点，失败从该段重启，不要整轨重来。排队按 GPU 秒，和图像服务同一套配额思想。质量几乎只能靠人工听：可懂度、是否跑调、结构是否完整；自动音高跟踪只抓崩坏。对已授权曲库做音频指纹，阈值保守，过近的进人工。

**后续追问：** 只改词不改旋律时，你冻哪些 token、放哪些；边生成边播时副歌被重采样，已经播出的前半段如何保证不再变；用户写「像某位在世歌手」时，拦截发生在提示分类还是声音嵌入空间。

**扩展问题：**
- 三分钟若必须整轨自回归，怎样用段落级并行降墙钟，又怎样接住跨段调性？
- 输出和曲库指纹很近但提示完全不同，你下架、改生成，还是只打标？
- 响度规范化放在解码后还是 codec 前，对用户「副歌就要比主歌大声」这种意图有什么伤害？

**推理回答：** 目标是局部可编辑和可开播，而不是每次整轨重算。约束是音频在时间上强耦合、版权敏感、墙钟长。先把结构、对齐和分轨变成一等公民，再在窗口内重采样。验收看切段后听感连续、越权模仿被拦、以及重做副歌不再付整曲 GPU 秒。

## DESIGN-023. 审核链路里，傍晚流量高峰时在播房间将近 5000 路，违规镜头或许只出现 2 秒。画面抽帧、声轨、弹幕哪一路先下第一刀？误切热门流、漏放那 2 秒，这两本账的时延额度该如何切开？

**答：** 直播审核是级联，不是每路每帧都跑大模型。弹幕和音频关键词可以在约 100–200ms 内出第一刀；视频按每秒 1–4 帧抽关键帧跑轻量分类，可疑片段再升级到多模态或人审。高危类目走自动切断或遮罩，目标是 1–2 秒内生效；低置信的擦边不要为了「宁可误杀」切热门流，而是局部打码、短延迟或送人审。漏放和误杀写进不同阈值，不要共用一个「敏感」分数。

**深入展开：** 5000 路若按 2 帧/秒做小图分类，每秒约 1 万次视觉推理，必须用小模型、批处理，并且只在运动或场景变化时抽帧，而不是 25fps 全跑。音频流式出字后套分类器和关键词，往往比逐帧看画面更早抓住口播违规；弹幕是最便宜的快通道，但会被谐音绕过，只能当快刀不能当唯一刀。融合规则：任一快通道高危即动作；中置信且画面也脏才升级。动作阶梯是记录、观看端打码、切断推流、封号，越狠越要短证据窗和可申诉。人审按晚高峰排班，队列按风险乘房间热度排序，热门房间的中置信不能躺十分钟。贴纸挡脸、变速、换背景需要周期更新样本，哈希拦截已知违规素材。指标包括从出现到动作的延迟、抽检漏检、主播申诉成立率、人审负荷。这里没有「先审后发」的窗口，必须接受部分事后补刀，并把高危的事后窗口压到秒级。模型不可用时，关键词和哈希仍工作，视觉升级暂停并加大人审，而不是放开。

**后续追问：** 热门房间误切的客诉和普通房间漏 2 秒，阈值要不要按热度分开？主播用教学讨论当挡箭牌，要看多长的历史才敢切？切断后给主播回放证据，怎样避免把未打码的违规画面再分发一次？

**扩展问题：**
- 怎样用「违规时长约 2 秒」倒推最低抽帧率，并算出 5000 路需要多少视觉 QPS？
- 弹幕打码和视频切断由不同服务执行，时钟差 1 秒会怎样被绕过？
- 如何把申诉成立的样本在约 24 小时内加进回归，同时避免拟合到某一间房的背景？

**推理回答：** 目标是高危秒级动作、热门流低误杀，约束是 5000 路算力和两秒级事件。用便宜信号做快刀、贵模型做升级，阈值按类目和热度拆开。用检测延迟、漏检和申诉成立率验收。

## DESIGN-024. 两小时的讲座要精确到秒，手头只有一张幻灯截图，嘴里还说「讲报价表的那段」。离线跨模态索引和在线查询各干什么，才不用对着整段视频做全量扫描？

**答：** 离线把视频切成带时间戳的检索单元：镜头关键帧的视觉向量、ASR 字幕、幻灯片 OCR，分别写入向量索引和倒排索引；在线用截图走图搜图、用句子走文本检索，再按时间桶融合，返回起止秒和可点证据，而不是整段文件。查询路径禁止对原始帧做全量前向。两小时讲座按镜头切通常是数百个单元，按 1fps 切也只是数千帧量级，ANN 加重排就能定位。

**深入展开：** 数据流是：容器解复用 → 音频送 ASR 得到带时间的句级字幕 → 视频按镜头边界（直方图或光流突变）抽关键帧，对关键帧做 OCR 和可选的一句场景描述 → 每个片段（常见 5–15 秒）写成一条记录：`t_start, t_end, frame_emb, text_emb, ocr, asr, shot_id`。视觉和文本不要强行塞进同一个 encoder：图搜图、文搜图用开放世界图文双塔（对比学习对齐后按余弦检索）；专名、数字、报价表标题用 BM25/OCR 倒排补召回，因为短专名在 embedding 里不稳。融合按时间对齐：两路命中落入同一秒级桶，用 RRF 或浅层重排取最高桶，证据必须带关键帧、OCR 框和字幕句。边界：暗场、口播无字幕、幻灯片切太快会造成视觉和 ASR 错位，要允许关掉其中一路；用户只给截图不给字，就关闭文本路。规模账：1 万场两小时讲座 × 约 400 镜头是约 400 万向量，带元数据过滤的 HNSW/IVF 足够，不要为每次查询解码整段 H.264。

**后续追问：** 截图来自观众手机、带摩尔纹和倾斜时，视觉路怎么对齐到演播室关键帧；同一张报价表在开场预告和正文各出现一次，你按什么信号消歧；字幕相对画面延迟 2–3 秒时，融合窗该开多大。

**扩展问题：**
- 只建关键帧索引、不建 ASR，哪些查询会系统性失败？
- 如何评估「定位误差 ≤ 3 秒」，而不是用视频级召回冒充成功？
- 内部分级导致某些时段对部分用户不可见时，过滤应发生在 ANN 之前还是之后？

**推理回答：** 目标是秒级可点证据，约束是不能在线扫全片、也不能把专名完全交给向量。先按时间把多模态信号落成可检索单元，再按查询所带模态选路并在时间轴融合。验收看定位误差和越权时段是否被滤掉，而不是看是否返回了一个视频文件。

## DESIGN-025. 一条 10 秒 1080p 的作业做到六成时 worker 没了。多 GPU 排程以及潜空间里检查点的落盘方式如何设计，才能接着跑、任务不用从头来，并且成片带上离线可验证的出处标记？

**答：** 按「时长 × 分辨率」预留多卡，每隔若干去噪步把时空 latent 和随机状态落盘；崩溃后从最近检查点恢复，而不是从纯噪声重来。预览短片和成片分池，避免 10 秒 1080p 打散一堆 2 秒预览。成品在像素域打不可见水印，并附带签名后的来源声明（模型版本、时间、提示哈希），校验方只需公开验证逻辑，不必访问你的内网。入队和出队各做一次安全审核，真人滥用和深度伪造风险默认拒绝或强制显著标识。

**深入展开：** 流程：短提示经 LLM 扩成镜头描述 → 在压缩时空潜空间跑扩散 Transformer → 解码 → 可选超分 → 转码分发。算力比单张图高一个到两个数量级：十秒 24fps 是 240 帧，即使时间下采样，仍可能多卡盯着同一任务数分钟。检查点间隔过大则失败回退贵，过小则 IO 拖步；应异步复制到另一台可调度节点。调度器按预估 GPU 分钟装箱，长短任务分池减少碎片。成本控制：先出低分辨率或数帧预览，用户确认再满规格；最大时长和分辨率写死。转码失败不应重跑扩散。水印要在常见压缩和裁剪后仍能检出（用这些变换做回归，不要声称不可破坏）；来源声明用签名，验证器核签即可。评估以人工为主：主体是否换脸、运动是否撕裂、是否贴提示；光流平滑只能抓崩坏。

**后续追问：** 检查点每步写还是每 10 步写，对墙钟和期望重算如何权衡；预览通过但成片主体变了，怎样把预览潜变量当条件而不是重新采样；离线验证器报水印失败时，该不该阻断分发。

**扩展问题：**
- 付费任务插队时，怎样避免把免费任务的检查点从磁盘上挤掉？
- 如何测试「截屏再压缩」后的水印检出率，而不把不可破坏当成设计前提？
- 多卡里有一张算得慢，你用气泡填流水线，还是整组对齐到最慢卡？

**推理回答：** 目标是长任务可恢复、成本按预览/成片分层、滥用可追溯。约束是墙钟长、状态大、伪造风险高。先按 GPU 分钟装箱并检查点 latent，再把水印和签名绑到分发物。验收看崩溃多付的 GPU 分钟、预览到成片是否同一主体、以及无内网时能否判定来源。

## DESIGN-026. 出图流水线高峰期已经等了 4 分钟，一张工单要吐 4 张 1024 宽的图。把 GPU 秒账单摊开：蒸馏步数、相同分辨率一起批、预览各自省下的是等候时长、计算开销，还是只是心理等候？

**答：** 文生图是异步任务：输入审核 → 排队 → 扩散逐步去噪 → 出图审核 → 对象存储和 CDN。感知等待靠先推低分辨率或少步预览；真成本靠同分辨率合批和少步/蒸馏模型降低每张 GPU 秒。示意：单张 1024 在一枚现代推理卡上常见是数秒到十余秒（随步数和骨干变化），4 张串行就是几十 GPU 秒；合批提高利用率，但不改变「每步一次骨干前向」。配额按 GPU 秒而不是按张，避免有人靠极端步数占满队列。

**深入展开：** 扩散在潜空间迭代：文本编码器把提示收成条件，噪声潜变量走例如 20–50 步（是否蒸馏会差很多）的 UNet 或 DiT，再经 VAE 解码。步数近似线性决定 GPU 时间；分辨率升到 1024 后空间维变大，只有同 shape 才能合批。调度按付费等级分队列，工作节点只拉同一潜变量形状的请求凑 batch；凑批等待要对交互档设上限（几十到一百毫秒量级），否则队头延迟换不来吞吐。预览路径用更少步或更小分辨率先出一张，推进度，用户取消就不跑满 4 张满步。安全双检：提示拦截（性、暴力、点名侵权）和出图分类，失败不落 CDN，并可加不可见水印便于追溯。存储分原图和缩略图，设保留期。缓存只对「相同提示 + 种子 + 模型版本」安全，近似提示缓存会串图。自动的图文相似度只能当漂移探针，上线门仍以人工偏好和安全漏放为主。

**后续追问：** 合批等待从 0 加到 200ms，P95 排队和 GPU 利用率通常谁先动；用户连点同一提示十次，你当缓存命中还是当滥用；局部重绘为什么必须复用原图潜变量和遮罩，而不是整张重跑。

**扩展问题：**
- 按高峰 100 QPS、每单 4 张、单张约 6 GPU 秒粗算卡数，并指出哪一项假设一错就会差一倍。
- 免费用户和付费用户共池时，怎样避免免费长队饿死付费短任务？
- 出图审核误杀率到约 5% 时，阈值往哪边拨，用什么人工抽检补？

**推理回答：** 目标是把四分钟干等拆成可取消预览和可计价的满质量出图。约束是每步前向贵、分辨率决定能否合批、安全必须挡在分发前。先算 GPU 秒和队列，再让预览、合批、步数分别打在感知等待和真实算力上。验收看 P95 等待、单张 GPU 秒和违规漏放，而不是看样张漂不漂亮。

## DESIGN-027. 对方刚停口，大约 800ms 内必须响起第一段可播音频——场景是保险理赔热线。时延额度怎么切？STT→LLM→TTS 这条级联，对比语音到语音模型，你怎么选？

**答：** 核心指标是语音到语音延迟：从判定用户说完到线路上出现 agent 第一个可播音频块。人类对话的自然间隙大约 200–500ms，800ms 能接得上，但几乎吃光「识别→推理→合成」三级联的首包预算。级联把三跳拆开，工具、话术和可观测性好；语音到语音模型少一到两跳、能留住语气，但政策措辞、工具调用和「只播已确认文本」更难控。实际系统多用级联打底并全程流式衔接，只把闲聊或高情绪轮次交给语音到语音，而不是等整句再开下一段。

**深入展开：** 先把 800ms 摊开才设计得下去：网关或端上的 VAD/轮次判定大约 50–150ms（太短抢话，太长像卡顿）；流式 STT 吐出足够稳定的前缀大约 150–300ms；已预热且命中前缀缓存的 LLM 首 token 大约 100–250ms；流式 TTS 首音频块大约 80–200ms；剩下给网络抖动和抖动缓冲。电话侧常见 SIP/RTP 或 WebRTC，编排器必须会话亲和，否则 KV cache 和轮次状态全丢。轮次检测不能只靠静音：用户报车牌、保单号时会停顿，要把「是否已构成可执行意图」和一段短静音窗合在一起。打断是硬路径：用户开口就取消进行中的 LLM/TTS，通知客户端丢掉未播缓冲，并按已播时长截断历史，只保留对方真正听到的半句，否则下一轮会回答自己没说完的话。查保单这类工具常要秒级，不能卡在静音里，应先合成「我帮您查一下保单」再异步回填。容量按并发通话数估算：STT/TTS 能小批，但 deadline 一紧，batch 稍大首包就会破 800ms。录音和转写按个人数据短留存，并提供关麦。

**后续追问：** 级联已经到 1.2s，你砍 TTS 首包、换小 LLM，还是改走语音到语音；用户报一长串保单号中间停了 400ms，怎样避免误切；打断发生时查保单的写备注已经发出，会话状态怎么回滚。

**扩展问题：**
- 线路噪声把「三」听成「四」，你在哪一层做复述确认，而不是直接进理赔工具？
- 口头确认「同意注销」时，怎样避免 TTS 抢话把确认句盖掉？
- 用模拟来电做回归，除了语音到语音延迟，还盯转写词错率、抢话率还是工具误触发？

**推理回答：** 从 800ms 内开口反推必须全流式，再按级联三跳的首包摊预算，超标才考虑语音到语音或跳过完整转写。硬约束是轮次和打断：错切、错史比再慢 200ms 更伤。验收看 P50/P95 语音到语音延迟、抢话率，以及打断后历史是否与已播音频对齐。

## DESIGN-028. 客厅里的音箱听到唤醒词后约 300 毫秒内就得反应，然后分流：关灯在本机做，查日历走云端。用户插话、确认转账、断网时，本机和云端各负责哪部分？哪些操作绝不能仅凭单次转写就放行？

**答：** 唤醒词和本地设备控制走端侧小模型，保证离线和亚秒响应；日历、闲聊、多轮推理走云端大模型。打断在播放链路处理：用户开口就停 TTS 并丢掉未播缓冲，不要等云端回合结束。转账、开门、删数据这类不可逆动作必须二次确认（再问一句或端上按键），确认用受限语法或点选，不能把一次 ASR 的「转吧」直接当授权。断网时本地技能仍可用，云技能明确说此刻查不了，而不是用过期缓存假装查过。

**深入展开：** 设备常驻唤醒（小体积、低误唤醒）、VAD，以及可选的端侧 ASR 处理短指令。误唤醒和漏唤醒要分开调：电视开大声时误唤醒上升，可用能量门或「连续两遍唤醒」。路由先查本地技能表（灯、温度、计时器），其余上传音频或已转好的文本。音箱是长待机、多用户、共享空间，和电话坐席式语音代理不同：声纹或当前账户决定日历可见性，儿童声默认锁住购物。延迟预算示意：唤醒约 300ms 内，本地技能约 1 秒内，云端首段音频目标仍在 1–2 秒量级，靠流式 ASR、生成和 TTS 衔接。唤醒前的环形缓冲不落盘，云端音频按最短必要保留。高风险走状态机：意图 → 槽位确认 → 用户明确肯定 → 才调支付工具，工具本身还有账户鉴权和限额。评估看每小时误唤醒、指令成功率、高风险误触发（目标接近 0），以及断网仍可用的技能列表。

**后续追问：** 两人同时说话，系统跟谁？本地模型把「关灯」听成「关闹钟」，云端有没有权纠正已经执行的本地动作？短视频广告里的唤醒词怎么在端上抑制？

**扩展问题：**
- 端侧约 300ms 的唤醒预算里，特征、分类器和后处理各能占多少？
- 同一家庭多账号，日程查询的身份绑在声纹、手机陪同还是每次询问？
- 如何用「高风险工具调用前是否存在确认轮」做发布检查？

**推理回答：** 目标是快、能离线、高风险零误执行，约束是端侧算力和共享空间隐私。按可逆与否、是否需要个人数据切端云；确认轮和工具鉴权是执行门，不是提示。用误唤醒、断网技能和高风险误触发验收。

## DESIGN-029. 课堂转写一下子涌进将近 2000 条 16kHz 流，p95 要在 1 秒量级打上时刻标记字幕；想凑满 GPU batch 再算，可抖动与断线正在把包丢掉。batch 大小、环形缓冲、重连时的检查点如何折中，至于对敏感词做遮罩该卡在字幕下发前的哪一环？

**答：** 实时转写的瓶颈是「攒 batch 的等待」和「单路延迟」打架。每路先入环形缓冲，按 200–400ms 分片带重叠送 GPU；batch 用短时窗凑齐当前就绪的分片，到点就开算，不要等满 2000 路。时间戳跟分片的媒体时钟走，不跟服务器墙钟走，否则抖动会让字幕乱跳。断线用 `(stream_id, media_time)` 做检查点，重连只补缺口，不把全文重转一遍。敏感词在稳定字幕上打码再下发，partial 可以晚一拍，避免半个词闪过后无法收回。

**深入展开：** 带宽上，2000 × 16kHz × 16bit 单声道大约 64MB/s，网络不是主矛盾，GPU 才是。流式识别要维持每路编码器状态或重叠上下文，2000 路状态常要分到多卡；动态批把同一时刻的分片叠在一起，窗太长（例如再等 300ms 凑批）p95 直接超过 1 秒，窗太短则利用率掉下去。用目标延迟倒推：分片约 250ms + 推理 300–500ms + 后处理约 50ms + 网络，余量很小，后处理必须便宜。课堂常有教师麦，可用指定声道，不必上沉重的在线说话人分离。客户端带时间戳和序号，服务端抖动缓冲只覆盖几十到一百毫秒。保留最后一条稳定结果的 media_time，重传该点之后的 PCM。打码用词表加模式（证件号等），必须发生在广播前；运营大屏只看打码后，原始文本是否落盘按课堂合规定。扩容按活跃路数而不是注册课数，下课立刻释放编码器状态。评估看 p95 出字延迟、抽样字错误率、断线后缺口秒数、漏打码率。

**后续追问：** 一堂课突然从 40 路学生麦变成 400 路，你是降采样、拒新路，还是只转教师路？推理从 400ms 涨到约 900ms 时，先砍 batch 等待还是先砍分片重叠？敏感词在 partial 里出现半截，你是延迟出字还是先出星号再修正？

**扩展问题：**
- 如何用「就绪分片数、延迟、利用率」三条曲线选批窗口，而不是固定一个 batch 大小？
- 同一路从 Wi-Fi 切到蜂窝网，序号回绕或时钟跳变怎样识别？
- 转写要进课后摘要索引时，打码后文本和原始文本哪一份可检索、权限怎么配？

**推理回答：** 目标是约 1 秒的字幕和可恢复的断线，约束是 2000 路状态和 GPU 批效率。用有截止时间的动态批和媒体时钟检查点，打码放在稳定结果出口。用 p95、缺口秒数和漏打码验收，而不是只看平均是否快于实时。

## DESIGN-030. 在线聊天的 TTFT 变成两秒，因为离线作业在共享推理池里塞进 8k 的 prefill。租户配额、KV 分页以及连续批处理该怎么切开，避免交互被饿死？

**答：** 把交互和离线拆成优先级不同的调度域：交互请求可插入连续批次，长 prefill 必须切块并与 decode 交错。KV 按固定 token 块分页，避免一条 8k 序列按最大长度预留后把显存撕碎。配额按并发序列数和每秒 token 双向限制，而不是只按 QPS。聊天的 SLA 是排队 + prefill + 首个 decode；离线看吞吐。权重冷加载是十秒到分钟级，交互池必须常驻预热副本。

**深入展开：** 连续批处理允许在 decode 步之间加入新序列、退出已结束序列，GPU 不再等整批一起结束。长 prefill 计算密集、会占满 SM；应限制单步 prefill token 数（chunked prefill），把剩余块和下一批 decode 交错，否则在线请求只能排队。分页把每层 KV 切成固定块（常见十几到几十 token）映射到非连续物理页，序列结束整页归还；系统提示相同的前缀页可以共享。多租户设 `max_running_seqs` 和 `max_tokens_per_min`，公平性用 token 级加权队列，防止「一条超长请求吃掉一千条短请求的预算」。示意显存：7B 量级半精度权重约十几 GB，KV 随 batch × 层 × 序列线性涨，8k 大 batch 往往先打满 KV 而不是权重。扩缩看可调度 token 槽和队列等待，不要看 CPU QPS。同一基座可挂多个 LoRA，避免每租户一份全量权重。指标拆 TTFT、每 token 时延、批大小、KV 页利用率、抢占次数。

**后续追问：** 交互和离线必须共卡时，prefill 切块大小如何同时拉动 TTFT 和吞吐；某租户突然打来大量 32k 上下文，你是拒收、改派长上下文池，还是驱逐已有 decode；前缀缓存命中率很低，更像是提示没字节对齐，还是 tokenizer 版本漂了。

**扩展问题：**
- 同一基座挂约 50 个 LoRA 时，调度是按适配器亲和性钉卡，还是每请求热切换？
- 新权重滚动发布时，怎样让已有流式连接写完再切，而不是断流？
- 只按 GPU 利用率扩容，为什么会在「全是长 decode、利用率看起来很高」时仍然把队列拉爆？

**推理回答：** 目标是交互 TTFT 受保护、离线吃剩余算力。约束是 prefill 与 decode 争用 SM 和 KV 页。先分优先级并切碎 prefill，再用分页和配额管住碎片和吵闹邻居。验收看分位 TTFT 和租户配额是否被突破，而不是看平均 GPU 利用率。

## DESIGN-031. 内部四十个应用各自握着不同厂家的密钥。合并成统一网关时，按策略切模型、身份脱敏、以及提示版本审计如何做，同时让各应用继续用原调用库？

**答：** 网关做成与现有调用库兼容的反向代理：应用只改服务地址和组织签发的凭证，供应商密钥留在网关保险箱。鉴权之后走策略：哪个应用、哪类数据可以打哪个模型。出站前做身份信息检测和脱敏，需要时在授权下回填；日志记录提示模板版本、模型版本和内容哈希，而不是全文明文。模型切换靠路由规则，对应用保持同一套接口形状。

**深入展开：** 热路径是：传输终止 → 应用身份 → 配额与预算 → 允许的模型、工具和数据分级 → 对邮箱、证件号、密钥等做规则加分类器脱敏 → 供应商适配 → 超时与重试 → 响应检查 → 审计落库。应用可传提示标识，或由网关按路由挂系统提示，版本写入审计以便回放。密钥轮换只发生在网关。各供应商在函数调用字段上的差异由适配器消化。脱敏过度会伤任务（把工单号当成证件），要用业务允许列表；授权人员应能回看原文。网关是同步热路径，脱敏模型必须小而快，或对低风险流量改为抽样，不能给每次补全加秒级延迟。供应商故障按策略切备用，但数据分级不允许的区外模型即使空闲也不切。可以用影子流量验路由，但不能把生产身份数据打到未签约的供应商。收口完成的标志是应用侧不再残留供应商密钥，以及几乎每条请求都能追到提示版本。

**后续追问：** 应用拒绝改服务地址，还能不能用透明代理或网格收口；审计要留约 180 天，原文和脱敏副本怎么分存；某个应用必须把未脱敏病历送进模型，豁免谁批、日志怎么打标。

**扩展问题：**
- 列出网关必须强制、不能下放到应用的三件事，并说明下放后会出哪种事故。
- 用户粘贴的文档里带提示注入，网关拦输入还是拦工具出站？
- 如何用“应用侧残留供应商密钥数”和“无版本号的提示占比”验收收口是否完成？

**推理回答：** 目标是密钥、策略和审计在单点强制；约束是四十个应用改不动代码。用兼容协议收口，把脱敏和路由放在出站前。用残留密钥和审计完整率验收。

## DESIGN-032. 三百家客户分别把知识库传上来、调整系统侧提示、换掉品牌视觉。等到第二周就有人贴出截图，助手把另一公司的内部打折策略念了出来。先查哪一层：缓存键、还是向量库、还是日志？租户隔离必须卡住的强制点有哪些？

**答：** 先当数据泄漏事故查，不要先改提示词。按请求 id 把「检索到的块、缓存是否命中、写入的日志」摊开：语义缓存如果只用问题文本做键、向量库如果共用一个未过滤的索引、embedding 批处理如果把不同租户的文本拼进同一请求，都可能串数。隔离必须是强制条件：每个块带 tenant_id，检索时预过滤；缓存键包含 tenant_id、模型版本、提示版本和索引版本；对象存储和日志按租户分桶或加密分区。共享的只是模型权重和机器，不是记忆。

**深入展开：** 数据面是：租户配置（提示、工具白名单、品牌、配额）→ 文档管道（解析、切块、embedding）→ 分租户索引 → 在线检索加生成。串租户的典型路径有四条：①语义缓存只哈希 query，两家都问「退货几天」就命中了带内部价的旧答案；②向量检索先取 top-k 再过滤 tenant，结果被滤空或滤漏；③后台任务用一个服务账号读全库做「全局相似问」；④评测或客服后台的重放没带租户上下文。修复是把谓词 `tenant_id = ?` 下推到索引（元数据过滤或按租户分 collection），缓存键至少 `hash(tenant, query, model, prompt_ver, index_ver)`，禁止跨租户负例直接进线上索引。自定义提示本身是注入面：租户可以写「忽略安全策略」，平台仍要在网关做输出审核和工具权限，不能把策略只放在可被覆盖的系统提示里。配额按租户的 QPS、token、日费用在网关预扣，一家的批量上传不能打满共享 embedding 队列。发布要有租户级草稿、评测、灰度、回滚；评测集不能混用别家文档。

**后续追问：** 按租户分 collection 和共享集合加元数据过滤，在 300 个租户、每家百万块时各自的运维成本是什么？租户 A 的管理员被邀请进租户 B 的工作区，日志里如何证明没有带走 A 的检索缓存？提示注入写在上传的 PDF 里而不是系统提示里，你拦在解析还是生成？

**扩展问题：**
- 同一公司下三个品牌机器人，知识部分共享、价格表必须隔离，租户模型怎么切？
- 语义缓存命中但源文档已删除或权限已收，如何保证不会吐出旧答案？
- 如何用「跨租户检索探针」做发布门禁：用 A 的账号问只有 B 有的专有名词，命中必须为零？

**推理回答：** 目标是零跨租户可见，约束是底层模型要共享以降本。先假设泄漏发生在检索、缓存或批处理，而不是「模型记混了」，用强制 tenant 谓词和带租户的缓存键堵住数据面；提示和品牌只是配置，不能当隔离边界。用跨租户探针和审计日志验收。

## DESIGN-033. 黄金集在周五把提示改完之后分数依旧很高，可周六跟工具调用相关的投诉却翻倍了。评测台漏掉哪几类切片之后，离线才会看起来满分、生产却翻车？

**答：** 黄金集多半是短问答、和提示一起老化，覆盖不到工具轨迹、新意图和真实长度分布。平台必须同时存版本化离线集、按线上流量分层抽样的完整轨迹（含检索和工具出入参）、按任务切片的自动指标、经人工校准的评审模型，以及发布门禁与线上对照实验。旧集分数不动只说明旧分布没回归，不说明新失败不存在。新客诉要在一两天内变成一条持有切片，否则评估集会和产品脱节。

**深入展开：** 一次运行锁定被测系统版本（提示、模型、检索、工具）→ 回放输入 → 记录轨迹 → 多评审器打分 → 按切片对比。能自动的先自动：JSON schema、必含字段、工具名是否合法、引用 ID 是否出现在检索结果里。开放质量用模型评审，但必须用一小撮人工金标校准，并轮换选项顺序、限制答案长度，压位置偏差和「更长即更好」。切片样本少时只报区间不报胜负：几十条的工具集上看几个点的波动，噪声大于信号。评测原文禁止进提示仓库和检索索引；线上抽样先脱敏再入库。成本上，全量模型评审可能是每天数万次调用，高频回归用百级核心集，每日影子抽样用千级，全量放在发版前。线下线上不一致常见有三类：流量分布漂了、评测里工具被 mock 得太干净、评审器喜欢新提示的口吻却看不见任务失败。

**后续追问：** 模型评审和人工的一致性低到什么程度就不能当门禁；总分持平但「退款工具」切片掉了一大截，你拦不拦发布；怎样防止评测原文被手抄进 few-shot。

**扩展问题：**
- 给出发版门禁表：哪些切片必须不降，哪些允许用延迟换分数。
- 线上新失败只有 7 条工单时，怎样扩成稳定切片，又不把原文泄漏进训练或提示？
- 评审模型和分析模型同族时，自我偏好会怎样歪曲对照实验，你用什么对照消掉？

**推理回答：** 目标是能解释线上变差，不是刷一张和提示一起保养的总分。约束是失败模式会迁移、评审会有偏、调用有成本。把评估对象定义成整条系统轨迹，用流量分层切片和校准评审对齐线上。验收看新客诉能否在两天内变成可回归的红灯，而不是看黄金集均值。

## DESIGN-034. 贴给助手的是体征读数加一段自由文本主诉，答复里一旦冒出确定病名就当事故。升级通道、指南检索、风险分层如何衔接，才能做到仅辅助、可审计，碰到急症就停聊？

**答：** 输出只允许是分诊建议、鉴别思路和带出处的指南摘录，禁止下确定诊断或开处方。先把生命体征和主诉收成结构化项并分层（立即升级 / 尽快就诊 / 常规）；命中预先写死的红旗规则就中断生成，只返回升级动作。知识必须来自机构核准的检索片段，每条建议挂文档和章节；检索为空则拒答。全程留审计：谁在何时看到了什么输入和输出。它辅助医务人员，不替代执业判断。

**深入展开：** 在线链路：核对访问患者上下文的权限 → 结构化（数值合法、主诉分槽）→ 硬规则红旗 → 通过才检索指南 → 模型只能引用已检索句 → 引用核对后交给医务人员确认，才能写入病历。剂量、过敏、相互作用走药学库工具，不许模型默写数字。红旗规则必须亚秒级、不依赖生成模型，例如胸痛叠加明显异常生命体征、气道威胁这类预先枚举的条件（以机构协议为准，这里只作分层示意）。离线把指南版本化，过期条文下线。隐私按最小必要：默认去掉直接标识，留存短，未授权病历不得进训练。信息不足就列出缺失项并停，不补「假设患者年轻所以风险低」。评估看漏升级率（比多升级更要紧）、引用可追溯率、以及有无「确定病名」违规输出，不看口吻像不像医生。紧急通道是呼叫/升级接口，不是继续对话。

**后续追问：** 生命体征缺血压时，你是拒答还是按主诉继续；两条指南打架，界面如何同时展示而不让模型挑一个「听起来更像」的；医务人员改写了建议，轨迹怎样变成新规则或检索语料，而不是直接微调进病名。

**扩展问题：**
- 列出至少五条必须写死、不许模型改写的红旗，以及它们如何单测。
- 引用片段里的数字被模型改写后，你在哪一层拦住写入病历？
- 代诉和患者自诉冲突时，风险层按哪边算，审计里如何同时保留两份原文？

**推理回答：** 目标是辅助分诊并给出可核依据，约束是漏急症的代价远高于多问一句。先用规则锁住升级，再用带引用的检索约束生成，最后必须经人确认。验收看漏升级率和无出处断言——系统根本不该输出确定病名。

## DESIGN-035. 信贷侧要从合同里抽出到期日、年利率和担保额，一个数字位出错就要整份卷宗重审。每个字段怎样才能指回源文框，金额和日期过账前必须做哪些勾稽核对？

**答：** 这是带审计的抽取流水线，不是「读完合同写个 JSON」。每个字段必须带页码和包围盒，人审点字段要能高亮原文；对不上坐标的值直接作废。数字入账前走规则交叉：利率落在产品允许区间、担保额不超过评估净值、到期日晚于签约日，金额阿拉伯数字与大写、封面与附表必须一致。低置信或校验失败进人工队列，高风险字段默认双人复核。全程加密，留存模型版本和原始影像，以便数月后复现同一结论。

**深入展开：** 扫描件进加密桶 → OCR 和版面分析（条款与表格分开）→ 字段方案（利率、金额、日期、当事人）→ 抽取 → 校验器 → 人审 → 核心系统。和通用文档抽取的差别是钱和日期不允许「差不多」：OCR 把 8 认成 3、把 7.2% 认成 72% 都是真实事故。抽取输出应是 `{value, raw_text, page, bbox, confidence}`，且 `value` 必须能从 `raw_text` 解析出来。交叉还包括还款表加总与本金、年利率与月利率的量纲换算，以及和外部系统对客户身份、抵质押物编号。表格跨页要先合并再抽，否则到期日会落到上一笔。吞吐按日峰值估：例如高峰约 2 万页，OCR 按页并行，人审只看失败件，否则人力线性爆炸。字段级 ACL、不可篡改审计日志、监管要求的保留期，生产影像不进提示日志。模型更新必须在金标集上回归关键字段的精确匹配，不能只看平均 F1。

**后续追问：** 包围盒对了但 OCR 原文就是错的，你信影像重跑还是信人工？补充协议改了利率，以哪一版为准、冲突如何升级？人审改了一个数，要不要写回训练，合规是否允许？

**扩展问题：**
- 如何用「关键字段精确匹配 + 校验器拦截率」做上线门槛，而不是用整篇准确率？
- 扫描件倾斜约 15 度、印章压住数字时，预处理和人工分流怎么接？
- 复现半年前一笔拒绝决定，需要冻结 OCR、抽取模型、校验规则和提示词中的哪几版？

**推理回答：** 目标是可追溯的关键字段，约束是一位数字的业务代价和监管复现。把坐标和交叉校验设成入账门禁，模型只提议。用精确匹配、拦截率和复现实验验收。

## DESIGN-036. 合同审查窗口只剩两天，300 份来自供应商的合同要对照公司禁改清单过完。可模型却将「建议可接受」表述成法律上的结论句。审查产出应整理成何种版式，才能单单标出偏差、签字权仍归律师？

**答：** 把任务收成“对照清单的差异检测”，禁止输出“可签署 / 违法 / 败诉风险高”这类结论句。每份合同解析成条款块，与编号红线逐条对齐，每条只输出：页码与段落坐标、原文摘录、命中的红线编号、差异类型（缺失 / 弱化 / 新增义务）、修订草稿、置信度。律师在工作台上接受、改写或驳回；系统默认不改合同正本。地区和客户类型只作检索过滤，不作为模型自行“适用某国法律”的依据。

**深入展开：** 离线链路：版面解析 → 按编号、标题、定义节切条款 → 条款向量加关键词索引；红线清单做成带编号的结构化规则，例如“责任上限不得低于 12 个月费用”“不得无限额赔偿”。在线链路：按红线条目检索候选段 → 抽取金额、期限、管辖、赔偿范围等槽位 → 规则引擎做确定性比较，模型只负责定位和改写建议。量级上，300 份、每份例如 20–80 页，两天窗口必须并行解析和按条检索，不能把整份合同塞进一次长上下文指望“读完再评”。没有原文坐标的命中视为无效，防止编造条款。扫描件切分失败应标“无法定位”并升级，不用邻近段凑。不同法域模板分区索引，禁止混召回。输出必须区分“与我方模板不一致”和“违反某项制定法”——后者除非清单写明且能引用，否则不生成。审计保留模型版本、清单版本、律师改判。合同按事项做访问隔离，缓存键带事项权限。

**后续追问：** 红线写的是“责任分配应合理”这种原则而不是可比较槽位，你还让模型打分吗；对方把扫描页当图片嵌进文件导致切分失败，流水线停在哪一层；律师改判后，对应红线规则要不要自动改，谁批准。

**扩展问题：**
- 同一数字在正文和附件里不一致，系统报一条冲突还是两条独立红线？
- 怎样阻止模型把“常见市场做法”写成对公司有约束力的法律意见？
- 用“律师改判率 / 无坐标命中率 / 漏报红线数”怎样验收，才不会把吞吐当成质量？

**推理回答：** 约束是虚假法律结论和越权签字的代价远高于漏标一句措辞。可比较槽位交给规则，定位和草稿交给模型，裁决留给律师。用坐标完整性和改判率验收，而不是用审完份数。

## DESIGN-037. 凌晨两点，一次短暂毛刺在值班频道里触发了 40 条「高优」推送，模型给每条的理由都是「这次真的需要人看」。与其在提示里多加一句「请少打扰」，怎样把重要程度、打扰代价和用户自定规则落成一套能执行的推送策略？

**答：** 通知是决策系统，不是文案生成。先用规则保住真正的 P0（付款失败、安全告警、法定时限），这些不经过「是否打扰」模型。其余事件打成结构化特征：类型、影响面、用户当前是否在会议或勿扰、历史关闭率、时间段，输出只能是立即发、延迟、合并进摘要、静默四选一。模型可以给折叠后的一组事件写一句解释，但不能单独拥有发送权；同一根因在冷却窗口内必须去重。

**深入展开：** 管道是：事件总线 → 按实体和故障指纹折叠（例如同一 `cluster=prod-3, symptom=cpu` 五分钟内只留一条）→ 特征（日历、勿扰、过去数日同类 dismiss 率）→ 策略引擎。打扰成本要显式加分：深夜、已连续推送 n 条、用户刚关闭同类，都提高发送阈值。LLM 适合把折叠后的一组收成一条摘要，不适合对原始 40 条逐条打分——逐条打分没有全局视图，每条都会显得重要。用户规则是硬过滤器：「数据库 pager 永远响」「营销类晚上 10 点后静默」，存在配置里而不是提示里。关闭、稍后、标记误报必须写回特征存储，否则过激会稳定复现。度量成对看：P0 漏发率（必须接近 0）、人均日通知数、关闭率、从通知到真正处理的时间。模型不可用时，P0 走规则直发，P2 进摘要队列，绝不能反过来「模型挂了就全发」。

**后续追问：** 用户设了勿扰，但 SLA 要求五分钟内唤醒，两条规则谁赢？合并窗口从 5 分钟加到 30 分钟，故障发现会晚多少，你怎么向值班解释？新员工没有关闭率历史，冷启动用团队基线还是偏保守多发？

**扩展问题：**
- 如何检测「模型把所有含 rollback 的事件都打成高优」这种策略漂移？
- 同一事件要过 Slack、短信、电话时，渠道升级条件怎样写死在状态机里？
- 用离线回放把昨夜 40 条重跑，策略应输出几条、分别是什么动作？

**推理回答：** 目标是 P0 不漏、夜间不被刷爆，约束是模型没有全局配额意识。先折叠再决策，把发送权放在策略引擎，LLM 只做合并后的解释。用漏发率和人均通知数成对验收。

## DESIGN-038. 刷卡授权这侧已经能用图上的特征和规则引擎，大约 20ms 就给出风险分数。大模型是去消化申述信与客服会话，还是放到刷卡授权的热路径里？如何防止它既撑爆时延额度，又沦为话术对抗用来绕过风控的入口？

**答：** LLM 留在热路径之外。授权继续走特征、规则和图模型；只有中高分案件或事后争议，才异步把非结构化文本抽成带偏移的证据和建议动作，交给分析员。模型不得单独改授权决定。用户和商户文本一律当不可信数据，用分隔和指令分层防止「请忽略风控规则」。热路径仍按毫秒计；抽取按分钟级案件处理即可。

**深入展开：** 授权链：设备与金额等特征、商户图上的邻居、规则和监督模型 → 分数和原因码，预算常见是十几到几十毫秒，塞不进一次生成往返（通常要数百毫秒到数秒）。异步支路在人工区或争议工单触发：抽取矛盾陈述、催转账话术、与交易日志对不上的时间线，写成高亮原文 span 和结构化标签，分析员看到的是证据，不是模型叙事。对抗面上截断超长粘贴、去掉「你现在是审计」这类角色指令，并禁止工具去改规则引擎。话术一变，规则和分类器要比生成模型先更新；每周看分数分布和案件主题是否漂。解释不得推断受保护属性；误拦率按客群切片看。抽取服务挂了，案件仍按原分数进人工队列，不得自动放行。评估看分析员是否采纳证据、漏放和误拦，不看解释是否流畅。

**后续追问：** 中分案件全量过 LLM 还是抽样，成本差一个数量级时怎么选；模型说「不像欺诈」但图分很高，界面默认展示哪边；如何用对抗话术集回归注入，却不把攻击文本写成训练正例。

**扩展问题：**
- 画出授权热路径和案件异步路径的时序，标出 LLM 允许失败的点。
- 聊天里夹了「把风险标为 0」这样的伪指令，你在预处理哪一步拆掉？
- 若业务强要实时解释，怎样用小抽取模型或模板原因码顶上，而不是把大模型塞进 20ms？

**推理回答：** 目标是给争议案件可核对的证据，不是替换毫秒级评分。约束是延迟、对抗文本和审计。热路径保持原模型，LLM 只做异步抽取且不当决策者。验收看热路径延迟不回退、注入改不了分、分析员采纳率，而不是看 LLM 单独准不准。

## DESIGN-039. 筛选链路要在一周内消化将近 10 万份简历，各职位只要「可面的前 50」。简历解析、规则门槛、用模型来排，这三步怎么切开，才不让校名或证件照暗中左右排名？

**答：** 先按吞吐拆队列：10 万/周在工作日大约每小时要消化数千份，解析和向量化必须异步，面试名单不能等全部解析完才出。硬门槛（年限、地点、必须持有的执照、工作授权）用规则，不过模型；模型只在过门槛的集合里做技能和经历匹配。给招聘官看之前去掉照片、性别标记、年龄和学校档次这类代理，排序特征用技能重叠、职责相近和可验证成果。AI 只产出推荐队列和理由，拒绝与录用留在人，并提供申诉入口。

**深入展开：** 投递 → 病毒扫描 → 解析（PDF、DOCX、图片 OCR）→ 结构化（公司、职级、技能、年限）→ 规则阀 → 岗位匹配 → 重排 → 人审。10 万份、每份解析加 embedding 若按数秒计，大约是一天弹性队列就能消化的量，瓶颈通常是坏文件重试。公平方面，训练和推理都不要把姓名、照片、院校档次当特征；配对测试只改姓名或学校，名次不应显著移动。岗位描述本身也可能带偏见用语，要对 JD 做一轮检查。阈值过高会漏掉转行者，过低则前 50 被关键词堆砌占满，所以同时看人审通过率和过门槛后的召回。保留期、候选人访问自己的数据、自动化决策披露按所属司法辖区处理。不要让模型直接写「你不够优秀」的拒信，理由必须映射到岗位条款。每周用标注集回归解析错误率、与人审的一致率，以及分组公平指标。

**后续追问：** 客户坚持「必须某档院校」这条硬门槛，产品是拒做、做成可关闭选项并打水印，还是直接拒绝该需求？同一候选人投 20 个岗位，解析做一次还是每次重跑？人审只看前 50，如何估计埋在 51–200 的损失？

**扩展问题：**
- 如何构造「只改敏感属性」的配对简历来测排序漂移？
- 解析把「熟悉某框架」丢了，候选人申诉后，索引和已发出的名次怎样订正？
- 岗位要 50 人短名单，但过硬门槛的只有 12 人，系统是放宽规则、提醒改 JD，还是让模型「找差不多的」？

**推理回答：** 目标是按时交出可面名单且经得起公平抽检，约束是吞吐和自动化决策风险。规则先剔硬条件，模型只排序，人做决定。用配对公平测试和人审通过率验收，而不是看「筛掉了多少」。

## DESIGN-040. 首屏必须在 100ms 量级返回，新帖仍要由语言模型来写话题和导语。召回通道、排序器、标注作业各自走实时还是走离线，如何防止迟到特征把排序结果变成一套生成管道？

**答：** 100ms 的在线路径只做轻量计算：读已物化的用户画像和实时特征，多路召回，排序，再加规则重排和多样性。主题、摘要、冷启动标签走近线：发帖后进标注队列，结果写入特征店，给之后的请求用。解释文案若要用语言模型，也只能对已经排好的头几条异步生成，不能挡首屏。推荐好不好仍看点击、停留和在线实验，不看标注模型的文笔。

**深入展开：** 时间片（示意）：召回 10–30ms 出数百到数千候选，精排 20–40ms，打散和降权已读数毫秒，剩下给网关和特征读取。刚发生的点击走特征流，迟到就用上一窗口快照，绝不在 100ms 里现场跑一遍大模型。近线标注目标是秒到分钟级出标签；高峰积压时，新帖先走内容向量和热门/探索通道，避免「没标签就不推」。只推已点品类会收窄，所以留探索配额。延迟超标应降级成热门加已缓存画像，而不是排队等标注。容量是两本账：精排按 QPS 乘候选数，标注按发帖速率估计算资源。特征店带版本，实验桶可以换排序模型，但应读同一套已落地的标签，免得实验被标注抖动污染。关掉标注服务后，主推荐链路仍须能出首屏，只是冷启动变差。

**后续追问：** 标注积压约 20 分钟、新帖曝光掉了，你加计算资源还是让未标注帖走纯向量召回；用户刚搜了露营，实时特征约 80ms 才到，你等还是用上一分钟画像加搜索词正排；解释文案生成失败，首屏是否仍出、卡片上留不留空位。

**扩展问题：**
- 语言模型把讽刺帖标成新闻，精排会怎样放大，你在规则层还是在标注质检层挡？
- 探索配额保证约 10% 非主品类，怎样避免低质新帖借「无标签」通道打上首屏？
- 弱网下 100ms 不够，服务端先出粗排、客户端再插一刀，特征一致性怎么保证？

**推理回答：** 100ms 否定了线上现跑大模型。生成式能力放到近线特征，在线只消费。错误形态是特征迟到和反馈收窄，降级路径必须不依赖标注。验收看 P95 耗时、新帖曝光延迟，以及关掉标注后主指标是否仍能降级运行。

## DESIGN-041. 周末积压下将近 4000 场会议、每场约一小时，周一 9 点到 11 点之间要交出会议纪要以及写明负责人的待办。排队、转写与摘要如何切片，才能赶上点，免得把「下周跟进」派给从未发言的人？

**答：** 这是一条有截止时间的离线流水线，不是实时对话。先按墙钟倒排：4000 小时音频要在约 2 小时内出结果，ASR 必须远快于实时并水平扩，摘要必须分段，不能把整场会塞进一次上下文。说话人分离和行动项是两条独立产物：转写可以错一个字，但责任人必须能指回某段带时间戳的发言，对不上就标「未指定」而不是猜。纪要默认只对参会者和日历组织者可见。

**深入展开：** 量级上，4000 × 1h 的 16kHz 单声道是数 TB 原始或转码后的数百 GB；先落对象存储，任务表记 meeting_id、日历 ACL、优先级（标了董事会的先跑）。ASR worker 按 5–15 分钟切片，片间重叠数秒以免一句被切断；说话人分离在切片级做，再用会议平台的发言人事件或声纹在会级对齐。一小时发言按每分钟约 120–160 词估算，转写大约 8k–15k token，一次摘要既贵又容易丢掉尾部决议。做法是切片摘要 → 会级归并（决议、未决、行动项）→ 对每条行动项校验「责任人必须出现在引用片段里」，失败则回退成「待确认」。吞吐：若单卡 ASR 能跑约 8–12× 实时（示意，视模型和精度），4000 小时大约要 300–500 卡·小时，2 小时墙钟就需要约 200 张卡量级的池，或接受分层 SLA（高管会 30 分钟出、其余当天）。摘要用中等上下文模型，不要对每句都调最大模型。同一 meeting_id 的产出覆盖写，避免重复推送「纪要已好」。录音和转写按会议保留期删除；日历标了私人的场次单独策略。

**后续追问：** 日历显示「张三」但声纹对上的是「李四」，你信平台事件还是声学？切片切在笑声和串台处，会级归并如何发现决议被拆成两半？11 点来不及的会，是先出行动项草稿还是先出粗糙全文转写？

**扩展问题：**
- 如何评估行动项：看「责任人 + 日期 + 动词」三元组对不对，而不是看摘要像不像人写的？
- 同一人连续开了三场会，摘要互相污染通常发生在哪一层缓存？
- 参会者会后申请删掉「我说的那句薪资」，转写、检索索引和已发出的邮件要怎样一起处理？

**推理回答：** 约束是墙钟和责任归属，目标是可引用的行动项，不是一篇通顺散文。从音频小时数反推 ASR 卡时，从 token 长度逼出分层摘要，把「人」从生成里拿出来做校验。用 SLA 分层和引用对齐率验收。

## DESIGN-042. 刚发完一版，十五分钟内报警条数冲到将近 800，助手却给每一条都填「可能是数据库」这种空话。变更记录、服务拓扑、指标侧的异常探测该如何接进来，才能给出一条有证据支撑的根因假说，而不是 800 段散文？

**答：** LLM 不负责发现异常，只负责在已经折叠的证据上写假设。先让时序检测器、日志聚类和健康检查各自产出异常点，再用服务拓扑和变更时间窗做关联，把 800 条收成少数故障域。只对折叠后的证据包调一次模型：要求输出假设、支持证据、反证和下一步命令；没有变更或拓扑命中时必须写「证据不足」，不许默认把数据库当背锅对象。

**深入展开：** 指标（错误率、饱和度、延迟分位）走季节性或基线检测，不要让模型看原始点列；日志做模板聚类，相同模板计数加一。拓扑用服务图、实例和依赖（库、队列、缓存），变更总线提供「谁在 T−15min 动过」。关联可以很朴素：同一被依赖服务的错误率先升、调用方超时后升，则先怀疑那条依赖；时间戳贴着一次 schema 迁移，就优先那次变更。证据包控制在几千 token：top 异常、两跳拓扑、最近 N 条变更、相关排障手册片段。生成带强制结构，引用必须是包里的 id。已知噪声（备份打满磁盘、金丝雀预期错误）要有抑制窗口。重启、回滚、扩容只能生成建议，执行走现有变更系统。评估看告警压缩比、根因是否被值班采纳、平均确认时间，以及「甩锅数据库」的误归因率。检测器必须亚分钟级，模型可以秒级——摘要再漂亮也救不了发现得太晚。

**后续追问：** 一次未登记的直连缓存导致拓扑缺边，关联会怎样误导？变更很多的发布窗口，如何避免「凡是发布都背锅」？值班已经手动回滚，助手是否还允许再建议一次回滚？

**扩展问题：**
- 如何区分症状告警和根因告警，折叠时谁留下、谁降成证据？
- 日志里出现「请重启该实例」这类注入式字符串，助手会不会当成指令？
- 用历史事故回放：只给当时的指标和变更，能否在约 5 分钟内给出与事后报告一致的故障域？

**推理回答：** 目标是缩短故障确认时间，约束是告警风暴和模型爱写通顺的错误原因。把检测和关联留在统计与拓扑，LLM 只消费折叠证据。用压缩比和误归因率验收，而不是看摘要好不好读。

## DESIGN-043. 合规定价场景里，大促那两天模型要把同一型号耳机对一部分客群溢价约 12%。既要创收，也得撑住事后稽核。成交价该由哪一层算出来，语言模型仅仅允许接触哪一段营销文案？

**答：** 成交价必须来自可审计的定价器：需求、库存、竞品价、成本、毛利下限、最大调幅，用规则或表格模型算出候选价，再过合规闸门。LLM 可以读促销文案、舆情和竞品页面说明，输出结构化信号（例如「竞品断货」「地区补贴即将到期」），不能直接改价。对人群的溢价若吃进了地域、设备、支付方式等代理变量，即使没有显式敏感属性，也要在仿真和公平性检查里挡下来。每次生效价写清输入快照、策略版本和审批人。

**深入展开：** 在线路径必须短：特征存储给出库存和实时需求 → 定价器在毫秒到几十毫秒内出候选（商详高峰是页面 QPS，不是一次生成调用能扛的）→ 闸门（地板价、天花板、单日最大变幅、同 SKU 对可比人群的价差上限）→ 缓存到商详。离线做弹性估计、竞品管道和策略仿真，把昨天的需求重放在新价上。LLM 放在近线：把非结构化输入收成标签和置信度再进特征，不进同步计价。12% 这种跳变应先仿真看转化和投诉，再灰度小流量。差别定价要能解释成库存或时段变化，而不是「因为你是某类用户」；给审计留查询接口。外部刷价和内部员工套利用频率限制和账号隔离。模型不可用时，定价器仍按规则和最近弹性出价——解释文案可以缺，价不能缺。

**后续追问：** 闸门挡住 12% 之后，是回到旧价，还是按最大允许调幅例如 3% 生效？竞品爬虫延迟约 2 小时，定价器要不要显式降低置信？大促夜谁有权锁价，锁的是单个 SKU 还是整类目？

**扩展问题：**
- 如何检测「设备类型」把部分地区稳定打到更高价？
- 解释模块写「参考了竞品」，但审计发现当时竞品特征是空的，怎样让解释和真实特征对齐？
- 同一用户 10 分钟内刷新，价跳了 4 次，体验和套利风险分别怎么收？

**推理回答：** 目标是增收且可抽检，约束是同步延迟、公平和监管。数字计算留在定价器和闸门，LLM 只产近线特征。用仿真、价差分布和解释与特征的一致性验收。
