# 多模态与语音

## MM-001. 纯文本机器人次日还要同时收进用户截图与通话录音。截图、录音各自应先编码成哪类表示，某一模态缺席时流水线如何继续可运行？

**答：** 截图走视觉编码器变成 patch 或区域向量，录音走声学前端变成帧级或段级特征，原有文本仍走 tokenizer；三者都要投影到语言模型能读的同一宽度（或同一套视觉/音频 token），但投影只是对齐，不是把像素和波形直接拼进一个矩阵。缺图或缺音频必须当正常输入：对应塔输出可学习占位，或根本不往上下文里写该模态的 token，而不是拿零向量去「假装看过」。时间戳留给录音，空间坐标留给截图，丢掉这些元数据后面就无法回答「第 12 秒说了什么 / 红框里的价」。

**深入展开：** 数据流是原始字节 → 模态专用预处理（图按模型输入边长缩放或切片；音频重采样到例如 16 kHz，再算大约 25 ms 窗、10–20 ms 帧移的 log-mel）→ 视觉骨干（ViT/CNN）和音频骨干（Conformer/Transformer 一类）→ 线性或浅 MLP 投到语言宽度 D（常见大约 1024–4096，以所用 LLM 为准）→ 与文本 token 拼成一条序列。一张边长约 336 的图可切出大约 500–600 个视觉 token；10 秒音频若约每 40 ms 一个 token，大约 250 个——两者同时进 8k 窗口会立刻挤掉多轮历史，所以长录音往往先分段池化或先转写，只把关键段的声学 token 留下。空间定位依赖 patch 网格或检测框 id；时间对齐依赖帧索引，不能只留一句全局摘要向量。传感器读数、订单表这类结构化输入不要硬塞进视觉塔，应走表编码器或先序列化成文本。图文语义打架（图是破损、用户口头说「完好」）应在生成后做一致性检查并要求指向区域/时间，而不是在编码阶段把两路特征平均掉。

**后续追问：** 投影层是每模态一套还是共享，缺模态时梯度怎么走；60 秒录音先 ASR 成字再进 LLM，还是保留部分声学 token 才能留下语气和重叠说话；图和录音结论相反时，你信 OCR、信转写还是强制追问。

**扩展问题：**
- 三个模态向量范数差一个数量级，投影之后要不要做长度归一化，不做会怎样污染注意力？
- 用户只发了图，系统提示却问「电话里怎么说的」，缺模态占位会不会被模型当成「用户保持沉默」的假证据？
- 怎样构造「单模态可答、双模态故意矛盾」的集，证明模型没有默默丢掉较弱的那一路？

**推理回答：** 目标是同一轮里用上图和声，约束是可缺模态、可追溯到区域或时间、上下文长度有限。所以先分塔编码再投影，交互只发生在语言侧读这些 token 之后；长音频按 token 预算决定转写还是留帧。验收看缺模态仍能答、冲突样例会被标出，以及视觉/音频 token 数有没有把对话历史挤爆。

## MM-002. 三线是图到文案检索、规格图上的视觉问答、根据一句文案生成促销图。双编码器、视觉编码器再接大语言模型、扩散主干各绑哪条？若强迫三线共用同一骨干，失败会先出现在哪一步？

**答：** 检索绑双塔：图塔和文塔独立编码，只在相似度处见面，向量可预计算、可进 ANN，线上是一次编码加近邻。看图问答绑视觉编码器 + 投影 + 自回归 LLM：需要跨栏推理和组句，语言侧必须反复读视觉 token。出图绑条件扩散（或同类生成骨干）：优化的是潜变量/像素轨迹，不是词表上的下一 token。三者的损失函数、输出接口和延迟形态都不同。用 LLM 隐状态均值去建商品索引，向量会随提示漂移、无法预计算；用双塔硬解码写不出带计算的答案；用扩散当检索只会得到「长得像」而不是「就是这条 SKU」。

**深入展开：** 双塔交互晚，算力可离线摊销，百万级商品库是它的主场；缺点是图和文只通过一个向量见面，组合约束（「红鞋且鞋底有孔」）偏弱，要靠交叉编码器重排补。VLM 把数百视觉 token 写进上下文做多步推理，适合「详情页第三栏功率是多少」；代价是每次问题都要 prefill 这些 token，缓存键必须包含图像版本，和纯文本会话不同。扩散在 VAE 潜空间里迭代去噪，文本经 cross-attention 注入，没有检索主键，只有一条生成轨迹。统一 token Transformer 适合多任务理解，但仍解不了「输出一张图」，除非另接生成头。硬共用的第一处崩点通常是接口：检索要稳定、可索引的向量，生成要随机轨迹，问答要条件语言分布——一个骨干无法同时当这三个头。浅层视觉前端可以复用，损失函数不能复用。

**后续追问：** 以图搜文案要不要在双塔后再加轻量交叉编码器；问答是否把 OCR 文本当第二路条件，而不是全靠视觉 token；出图的文本条件用对比学习的文本塔，还是先让 LLM 改写提示。

**扩展问题：**
- 统一 Transformer 把图块和字放进同一序列，和「冻视觉塔、只训投影」相比，对数据量和训练稳定性各有什么要求？
- 检索塔和 VLM 视觉塔若共享权重，回召和细粒度定位谁会先掉？
- 宣传图必须出现指定 SKU 实拍时，条件应该接到扩散上，还是先检索再贴图，为什么不能把检索塔硬改成生成器？

**推理回答：** 先按输出类型（近邻 id、文本答案、像素）选接口，再选能预计算还是必须自回归/迭代的骨干。共用只允许停在浅层视觉特征。验收是三条线各自的主指标：Recall@K、问答准确、条件符合度，外加「误用骨干」的反例是否被挡住。

## MM-003. 皮肤科分诊同时依赖两类输入：病灶照片与口述病情。可选架构有二，一是最前端就把像素和词向量串接，二是由两个专科模型分头给分再加权合成。若病人没传照片，哪种架构率先失灵？

**答：** 早期拼接（early fusion）把未对齐的视觉特征和文本特征在编码器前段连在一起，缺照片就出现洞或必须填零，没做过模态丢弃训练时这条路径先崩。晚期融合（late fusion）让皮肤视觉模型和主诉文本模型各自出病种分数再加权，缺图就只信文本专家，系统还能给分，但看不见“主诉写干燥、照片其实渗液”这种细粒度冲突。缺模态频繁的分诊应把晚期融合当可运行底线，再在两路都在时加一层交叉注意力或一致性头。

**深入展开：** 早期融合的数据流：图像 patch 与文本 token 直接进入同一自注意力，或在前几层就做特征拼接。它能学到“描述里的‘水疱’是否对上这片区域的高光和边缘”，代价是训练必须成对、推理图文长度耦合，计算随拼接序列变长。缺失处理只能靠训练期随机丢模态或学一个可学习的空图占位；上线若突然只来主诉，占位符从未见过真实边缘分布，分数会偏或崩溃。晚期融合的数据流：视觉塔输出皮肤病超类 logits，文本塔输出主诉分类，再用逻辑回归、学习加权或规则（有图则提高视觉权重）合并。工程上可独立扩缩、独立降级，对缺失鲁棒，但两路只在决策层见面，对不上像素级证据。混合做法：分塔编码后做若干层 cross-attention（中期融合），并显式训练“只有文本 / 只有图 / 双模态”三种输入。量级上，门诊里相当比例用户先打字后补图，或图糊到不可用，所以“双模态必须同时在”不能当默认。冲突样本要单独评：两路分数顶牛时，应输出不确定并转人工，而不是把权重固定成“永远信图”或“永远信主诉”。不要把早期融合理解成“更新、因此更好”——它只是交互更早、对缺失更脆。

**后续追问：** 训练做过 30% 图像丢弃，早期融合是否就足以作为唯一路径；两路分数一个 0.9 一个 0.2，你输出高分病种还是强制不确定；患者后补了一张别人的网络皮肤图，晚期融合的视觉专家会怎样被带偏，要不要加来源或质量门。

**扩展问题：**
- 画出缺图、缺字、双模态三种输入下，早期、晚期、中期融合各自还能不能出可校准分数。
- “主诉与皮损视觉矛盾”该做成融合前的独立头，还是指望早期自注意力自己发现？
- 如何用“缺图时仍可分诊的比例 / 图文冲突检出率 / 错误病种率”证明你选的融合点，而不是只报双模态齐全时的准确率？

**推理回答：** 约束是门诊模态经常不齐，错误诊断的代价高于少用一次跨注意力。先保证缺图可降级，再在双路齐全时加交互去抓冲突。用缺模态和冲突切片验收，而不是用“拼接得越早越先进”做决定。

## MM-004. 禁止拿原始像素差当距离，却仍要把同一只猫、换角度拍的照片排成近邻。请说明每张图应落成哪类向量；编码器一换，为何旧索引必须整库重做？

**答：** 用在大量图片上训练过的编码器（CNN、ViT，或图文对比模型的图像塔）把整图映射成固定维向量，训练目标是语义近则点积或余弦大，而不是像素 L2 小。两张猫图的边缘和背景可以完全不同，深层特征仍应落在邻近区域；猫和车则应分开。检索前先做长度归一化，再用余弦或内积，交给 ANN 索引。换编码器、换预处理或换池化层等于换了坐标系：旧向量里的「1.0」和新向量不是同一个方向，混排会静默乱序，必须按「模型版本 + 预处理」全量重嵌并重建索引。

**深入展开：** 像素是 H×W×3 的原始观测，平移、裁剪、曝光会让逐像素距离爆炸，语义却不变。网络逐层从边缘、纹理到部件再到整图语义，通常取最后一层 CLS 或全局平均池化，维度常见大约 512–1024（以具体骨干为准）。训练目标决定「近」的含义：闭集分类更偏物体类别，自监督对比更偏变换不变，图文对比更偏可被短语描述的场景——这一题只要求图像对图像可比，不要把文搜图当成同一套接口。百万张、768 维 float32 原始向量大约 3GB 量级，生产会量化并建 HNSW 或 IVF 一类近似近邻。边界：水印、统一边框、截图 UI 会变成捷径，近邻其实是「同一套模板」；主体只占一角时全局池化会稀释，往往要先检测再嵌。稳定性要用翻转、裁切、JPEG 后再测 Recall@K，而不是只看干净样张。同一索引里混入 10% 旧模型向量，近邻会表现为不可复现的「时近时远」。

**后续追问：** 维度从 256 加到 1024，召回和存储各自怎么变，有没有收益平台；只改输入分辨率、权重没换，要不要重建；百万库做精确两两比较为什么不可行，ANN 的召回-延迟你怎样验收。

**扩展问题：**
- 全局一个向量把「猫在沙发上」叠成一个点，何时改用多向量或区域向量，才能把主体和背景拆开？
- 如何构造「同一商品不同拍摄」正例和「不同商品同背景棚」负例，检查 embedding 是不是在走背景捷径？
- 线上读到旧模型 10% 存量时，最近邻列表会呈现怎样的污染，怎样用版本字段拒绝混读？

**推理回答：** 目标是语义近邻不是像素近邻，所以表示必须由训练目标定义的编码器给出，度量用归一化余弦。坐标系一换，索引主键必须带模型版本。验收看变换下的 Recall@K，以及换模后旧索引是否被硬拒绝。

## MM-005. 图中有 4 只被挡住一半的杯子，模型却答 2。如何判定它是靠问句的语言统计在猜，还是真的在画面里计数？出题时要故意埋入哪些干扰？

**答：** 视觉问答要求答案由图像证据支撑，而不是由问句的语言统计补全。「杯子」在语料里常和「两个」共现，模型不看遮挡也会偏 2。要区分这两种行为，评测必须让「只看问题」的基线失败：改图不改问，或问句带误导名词。线上则要求模型给出计数所用的区域（框或点），框对不上物体就当错，即使数字碰巧对。

**深入展开：** 语言先验是视觉问答的经典漏洞：训练集里「什么颜色的香蕉」大量是黄的，模型看见问题就会答黄。计数、存在、空间关系更重：遮挡、截断、镜面反射会让检测漏目标，模型却用「常见数量」补。陷阱集至少包括：①同问不同图，金标答案不同（2 / 4 / 0）；②问句写「杯子」图里是碗，看是否被名词带走；③问「左边那只什么颜色」但左边没有物体；④读字题：图上的数字和问句暗示不一致。指标：封闭计数用准确率，开放描述另算；定位用框与实例的匹配，漏检一只就算错。生产里更稳的做法是先检测或分割出候选，再让语言模型在候选集合上计数或比较，也更好做可视化调试。高分辨率切片对小物体计数很关键，整图缩到短边约 224–336 一类分辨率时，后排杯子会消失。不要用「模型很大所以会看图」当论证，要用「遮住图只留问题」的对照：若准确率几乎不掉，系统就不是在做视觉问答。

**后续追问：** 计数要用检测再数框，还是让模型直接报数字，两种误差形态有何不同；多图比较（「哪一张里杯子更多」）会引入什么新的先验；用户问主观题（「好不好看」）时还要不要强制框。

**扩展问题：**
- 设计一个「遮图对照」实验，怎样解释结果才能证明系统依赖了像素？
- 遮挡超过一半的实例，你期望模型数进去、标不确定，还是拒绝计数？
- 视觉问答和看图说话、图文检索的评测为什么不能共用同一套分数？

**推理回答：** 目标是答案随像素变，而不是随问句的词频变。约束是语言先验很强、遮挡会毁掉检测。用对照实验和强制证据框把「猜」和「看」分开，计数尽量走可见实例。验收看陷阱集准确率和遮图后是否崩盘——崩盘反而是健康信号。

## MM-006. 视觉塔必须冻住，商品图指令对又只有八千。适配该打在把视觉接到语言的投影层，还是打在语言侧 LoRA？如何阻止它背商品说明书却不看图？

**答：** 八千对这个量级应先训视觉到语言的投影层（线性层或浅 MLP），再用低秩适配器动语言侧，不要解冻视觉编码器。投影层负责把域内外观对上 LLM 词空间；LoRA 负责学会“先看图再填槽”的答题格式。防背文案的关键不是再堆商品说明书，而是让同一段文本配不同图时答案必须变：训练里去掉已含答案的目录字段，评测用换图不换问。

**深入展开：** 常见 VLM 数据流是 ViT 出视觉 token → 投影到 LLM 隐空间 → 与问题 token 拼接 → 自回归答。八千对远不够更新以亿计的视觉权重：解冻编码器时，学习率即使比语言侧低一个数量级，也容易把通用边缘、材质、文字笔画洗掉，换成店铺背景过拟合。投影层参数通常只有百万到千万级，用例如 1e-4 量级学习率、一到三个 epoch 就能把域内颜色和包装轮廓对齐；语言侧 LoRA 秩例如 8–64，学习率再低半档到一档，只改注意力和 MLP 的增量。若任务只是换领域词表（把“物体”说成“SKU 属性”），有时只训投影就够；若要稳定输出 JSON 字段、拒答模糊图，才需要语言侧适配。背文案的机制是：样本里用户问题或系统提示已带“蓝色、两件套”，交叉熵在文本侧就能降损，视觉 token 的梯度接近噪声。构造方法：同一商品文案配颜色/数量变体图，正确答案只写图上可见属性；插入“图文不一致则指出不一致”样本。验收必须有“固定问题、替换图片、答案应翻转”切片，而不是只看开放描述的流畅度。边界：投影层学不动细小吊牌字时，优先加高分辨率切片或 OCR 工具，而不是解冻整塔；工具能抽的字段不要靠微调背进权重。

**后续追问：** 投影层已经对齐、模型仍不会按你们的字段顺序填表，这时加 LoRA 还是改解码约束；八千对里有两千对是同一张主图配不同话术，有效视觉多样性还剩多少；解冻视觉塔最后两块、学习率再降十倍，你用哪几个冻结对照实验决定值不值。

**扩展问题：**
- 设计一条“换图不换问”评测：列出至少三类必须翻转的属性（颜色、件数、瑕疵位置）。
- 训练提示里仍残留价签 OCR 全文时，LoRA 会学到什么捷径，怎样从数据管线截掉？
- 如何用“图文冲突样本准确率 / 换图翻转率 / 基座通用 VQA 掉点”证明你冻对了层，而不是把通用视觉能力换成本地背诵？

**推理回答：** 目标是域内看图答题，约束是样本少且视觉塔不可动。参数量大、通用特征已够用的模块冻结，只训对齐接口和输出格式。用“答案必须随图变”定义成功，避免文本捷径把微调做成说明书记忆。

## MM-007. 类目一周涨一茬，分类头你又不想每周回炉。对比对齐做完后，零样本打标其实是在图像向量和什么之间比距离？

**答：** CLIP 一类双塔用海量图文对做对比学习：同一对的图像向量和文本向量拉近，批次内其它配对推远，于是短句和图片落在同一度量空间。零样本分类并不是长出一个新类目头，而是把「一类一条提示短语」编成文本向量，与图像向量做余弦，取最接近的短语当标签。新类目只改提示词表，不必回炉视觉塔；这比「每类收集几千张图再训线性头」更跟得上开放词表，但对措辞敏感，细粒度属性和计数仍然弱。

**深入展开：** 训练一步（结构示意）：batch 里 N 张图、N 条标题，两塔各出 N 个归一化向量，得到 N×N 相似度矩阵，对角线为正例，用图→文和文→图对称交叉熵更新，温度把正负间隔拉开。推理不再需要这张训练矩阵，只剩「一幅图对 K 条类名」的 K 次点积，K 从几十到几万都远小于重训一遍分类头。它后来被当成即插即用的对齐器：以文搜图、以图搜文、给生成模型当条件或过滤、给 VLM 当视觉初始化——重要之处是开放词表接口，不是某一期的分类分数。边界：配对语料若偏电商图，医疗片或纯 UI 截图会偏；「红色」「圆形」这类属性容易被物体词盖住；脏标题会把捷径写进空间。生产上通常冻结两塔、只迭代提示模板，并用一小份固定类目集做回归，而不是默认微调整塔。

**后续追问：** 类名用中文两三个字，和「一张……的照片」整句模板，零样本差通常出在哪里；batch 太小、负例不够硬，对比学习会怎样塌；检索用这套空间、出图用另一套文本编码器，两个空间不一致时谁说了算。

**扩展问题：**
- 开放类目里两个近义提示抢同一张图，你用多模板平均，还是再接一个小型重排器？
- 训练对里混进大量标题党，损失或过滤上要怎样降权，才不会让空间跟着广告词走？
- 为什么这套空间适合检索和零样本，却通常不能直接当像素级分割头用？

**推理回答：** 约束是类目开放、不能每周重训头。把分类改写成「图向量对类名文本向量」的最近邻，训练用批次对比把两塔对齐。验收看新增类目是否零样本可用、提示模板敏感性，以及旧类目上相对闭集线性头的差距，而不是只报一个综合准确率。

## MM-008. 跨模态检索：鞋底照片打商品页。若图像和文本各用互不相认的编码器，距离会在哪一环失去意义？双塔对齐修哪一段，后期重排又修哪一段？短货号为何仍需 OCR？

**答：** 跨模态搜索要求查询模态和被检索模态能比距离。图文双塔（对比学习把配对样本拉近）让「鞋底照片」和「橡胶外底、防滑纹」这类文案落在同一空间，近邻检索才能用照片打商品页。若图片和文本各用互不相认的编码器，距离没有意义，召回会断在「根本比不了」。双塔解决粗召回；颜色、尺码、防伪纹这类细差异交给裁剪后的局部特征和交叉重排。鞋底图往往几乎没有可读品牌字，但鞋盒、吊牌上有，OCR 出的货号应走倒排保送，否则短货号在句向量里不稳定。

**深入展开：** 训练目标是配对（图, 文）的对比损失，批内其他样本当负例；推理时两塔可分开算，图库离线出向量，查询只跑图塔或文塔。空间必须同一次训练、同一温度和同一归一化，混用两个版本的向量等于换坐标系。商品检索的脏数据：白底棚拍和用户实拍分布差很大，只用棚拍训出的空间，实拍鞋底会漂向「纹理特写」而不是货号。补救是在索引里同时放：整图向量、主体裁剪向量（鞋、鞋底）、以及 OCR 或标题的稀疏索引。重排：对 top-50 用更重的图文匹配模型或属性核对（颜色、闭合方式），不要指望几百维的全局向量分清两条几乎一样的鞋。评测必须用跨模态切片：文搜图、图搜文、图搜图，单模态分类准确率说明不了这事。换塔之后旧向量全部作废，要重建。量级示意：十万货号 × 每款 5 张图是五十万向量，图索引通常够用；真正难的是长尾款只有一张图、文案只有一串料号。

**后续追问：** 用户拍的是包装盒而库里只有鞋面图，双塔会落到哪类近邻，要不要加包装图进索引；文案只有货号时，对比学习几乎没有语义可对齐，你怎样构造训练对；图搜图和文搜图是否共用一张图向量。

**扩展问题：**
- 为什么换了图像塔版本就必须重建索引，能不能对旧向量做线性映射凑合？
- 只用开放世界图文空间、不做商品微调，会在哪些类目上系统性把竞品排到前面？
- 跨模态召回该报 Recall@K 还是也要报「同款不同色」的属性准确率？

**推理回答：** 目标是照片能打到正确商品页。约束是未对齐空间不可比、短货号语义弱、细粒度外观超出全局向量。先用双塔做可比较的粗召回，OCR 保送货号，重排抓细差异。验收看图搜同款的 Recall@K 和易混竞品是否被重排压下去。

## MM-009. VLM 对一张价签高度只有几十像素的 4K 商品长图答复看不清。从像素变成模型可读 token 的路径上，细部最常在哪几步被抹掉？

**答：** 视觉语言模型不会把原图像素直接交给 LLM，而是缩放或切片 → 视觉编码器出 patch 特征 → 连接器（MLP、Q-Former 或 perceiver 一类重采样）压成较少的视觉 token → 与提示拼进语言模型。4K 长图上的价格往往只有几十像素高，第一步把整图压到例如 336² 或 448² 就会把数字糊成纹理；即便切片，片间重叠不够或每片 token 有上限，跨栏的小数点照样丢。OCR 或检测框是补小字的旁路，不是默认路径——没开的话，模型只能靠被池化过的语义特征去猜价格。

**深入展开：** 以常见 ViT 为例：输入切成 P×P 的 patch（如 14×14），边长 336 大约 24×24=576 个 patch，每个 patch 只看见自己那一块。价格若在缩放阶段已经低于可分辨笔画宽度，编码器从第一层就没有高频。连接器常把数百 patch 收到几十到两百个语言侧 token，这是第二次有损压缩：品类、主体颜色能活，小字数字先死。高分辨率做法是按网格切片（2×2 或更多）各跑一遍编码器，再加一张缩略全图提供版式；视觉 token 数近似按切片倍数涨，prefill 变贵。对「必须读字」的请求，更稳的路由是：长图按屏切片 → OCR 把文字以文本 token 注入 → 视觉 token 只负责图标、颜色和栏位关系。边界：图标含义、相对位置、是否有红叉，仍要靠视觉塔，不能全部改成 OCR。问「这是什么品类」和「第三行券后价」不该走同一分辨率。

**后续追问：** 只加切片不加 OCR，扫描件手写价够不够看；576 个 patch 收到 64 个 token，你用什么标准选这个压缩比；同一张图的粗粒度和细粒度问题，是否按问题类型路由不同视觉前端。

**扩展问题：**
- 切片后左右两栏价格被张冠李戴，怎样在视觉 token 旁带上区域 id 或坐标，避免语言模型只靠阅读顺序猜栏位？
- 连接器若被训成「摘要整图」，细粒度定位是先坏在注意力图对不准，还是坏在语言侧开始编数字？
- 怎样用「小字数字」和「大物体识别」两套集，证明瓶颈在几何压缩而不是解码温度？

**推理回答：** 标价是高频小目标，失败点应落在进 LLM 之前的几何压缩，而不是采样随机性。沿 resize → patch → 重采样逐步标信息瓶颈，再决定切片、OCR 或按问题路由分辨率。验收用小字读取准确率和视觉 token 数/prefill 时延，而不是开放式描述是否通顺。

## MM-010. 纯按阅读序做 OCR 会把税额塞进总额，因为金额印在右下角、挨着章。怎样把块坐标、单元格网格、字段名框与值框的链接送进模型，才能按定位框取数，而不是把行首尾相接？

**答：** 版式文档的阅读顺序不等于字段语义：总额、税额、账号常在页脚或印章旁，按行拼接会把邻近数字吸进错误槽位。文档理解要把每个文字块留下 `(text, x, y, w, h, page)`，表格留下单元格网格，再用「字段名框 ↔ 值框」的链接预测，而不是把整页 OCR 当一篇从左到右的散文。视觉特征（线框、底纹、印章）和语言（「价税合计」「Amount Due」）一起用，缺任一边都会在多栏和中英混排上翻车。

**深入展开：** 流水线：扫描件或 PDF → 版面分析（段落、表格、图章、手写）→ 文字识别 → 结构。原生 PDF 有文本层时优先用文本层坐标，扫描件才走 OCR，两者混用要统一坐标系（点或像素，并记录分辨率）。表格不要线性化成「第 3 行第 2 个数字」就丢网格：跨行表头、合并单元格必须保留行列跨度。字段抽取是图上的链接问题：左标签右值、上标签下值，或远处的「合计」对应右下角大号字体。模型输入可以是 token 加二维位置编码，或把页渲染成图再要求输出 JSON 和每个字段的框。校验规则比模型更该先写：总额不小于税额、币种符号与栏位一致、账号校验位；校验失败就标低置信送人工，不要把「像数字的字符串」直接过账。边界：印章压字、热敏纸褪色、多栏杂志版式、跨页表格，都会让纯文本阅读序失效。和「把整页图丢给通用视觉语言模型」相比，显式布局在字段级审计和批量发票上更稳，通用模型适合版式极不规整、字段集经常变的长尾。

**后续追问：** 文本层和 OCR 对同一字段不一致时信谁；跨页表格的表头在上一页，链接特征怎样跨页构造；手写金额和打印金额同时存在，以哪边为准。

**扩展问题：**
- 为什么「先识别成文再让语言模型填 JSON」在双栏发票上会系统性把右栏数字装进左栏字段？
- 字段链接的评测该报字段级 F1 还是也要报框的交并比，只报 F1 会掩盖什么？
- 版式突变（新模板）时，你做少量样本适配，还是先加规则校验挡错抽？

**推理回答：** 目标是按业务字段抽出对的数，并能指到框。约束是阅读序不等于版式语义，邻近数字会抢槽位。把坐标和表格网格当成一等输入，用链接预测加规则校验。验收看字段级准确率和框是否落在正确金额上，而不是看整页转录的字面重合。

## MM-011. 倒排检索只命中带「设置」字样的结果画面，可用户真正在问：点开设置前一刻改过哪一项。光标走过的轨迹、标题栏文字变化，怎样收成镜头间的前因边，而不是把约三十秒的前后画面整包丢给视觉模型去翻？

**答：** 这句问的是设置点击的前因，不是含「设置」的画面。把窗口标题变化、光标停驻和点击收成事件节点，在「进入设置」这个节点上沿时间向前接一条前因边，指向最近一次改值事件（开关、下拉、输入提交）。检索走这条边，只把前因节点的关键帧和控件裁剪送给视觉模型；前后三十秒整段像素既贵，又会把模型重新吸到结果页上的「设置」二字。

**深入展开：** 倒排（OCR / 转写）是词袋：设置页标题、菜单项、状态栏「已保存设置」全是高权重命中，正好是结果态。前因要另建一张事件图。节点示例：`(t, type, payload)`，`type` 取 `title_change`、`click`、`text_commit`、`toggle`、`focus`。窗口标题用辅助功能树或每隔大约 0.5–1 s 裁标题栏 OCR，比整帧视觉模型便宜几个数量级；光标采样 `(x,y,t)`，按下并短停视为点击，坐标吸附到当时的控件框。边有两类：`precedes`——在交互时钟（扣除发呆）上，改值事件与随后的「标题变为设置 / 齿轮点击」之间没有别的改值；`cursor_from_to`——光标离开控件 A 后指向设置入口。查询先定位目标事件 `e*`（标题切到设置，或齿轮上的点击），再取入边那一个（或少数几个）前因节点，把该节点的关键帧、控件裁剪、提交前后 OCR 送给模型问「改的是哪一项、值从何到何」。不要开墙钟 ±30 s：里面可能有二十秒呆滞，帧数按 1–2 fps 也有几十张，视觉 token 线性涨，注意力仍会落在结果页。空闲不延长因果窗，交互时间不够（例如大约 5–15 s 的有效操作）就承认「没有可引用的前因」，而不是用更长视频去猜。没有系统点击钩子时，用光标残影加按钮按下高亮估 `click`，用标题序列保底；两条都空则拒绝定位，不要退回整段。两处都叫「设置」时，用光标落点所在窗口和标题边消歧，不用再搜一遍词。

**后续追问：** 用户改完一项后去倒了杯水，两分钟后才点设置，交互时钟和墙钟谁当因果窗；标题 OCR 把「设置」读成近形字，`e*` 怎么用齿轮图标或 URL 栏补；前因边上有连续三次拨动同一开关，你报最后一次还是三次都报。

**扩展问题：**
- 只建词倒排、不建事件边时，哪些「之前刚改了什么」问法会稳定地指向结果页？
- 事件图里如何把「打开设置」和「在设置里改项」分成两个节点，避免前因边指到设置页自己？
- 评测定位误差时，成功标准是前因控件框的交并比，还是答案文本里出现了正确字段名？

**推理回答：** 目标是引用「点击设置之前的那一次改值」，约束是词倒排只会找到结果态、长视频会让模型再读到「设置」。所以镜头之间要有显式前因边，检索是图上的一步前向，视觉模型只看被指向的那一小块。验收看前因控件是否被框中，而不是看返回帧里有没有「设置」这个词。

## MM-012. 提示坚称照片是猫、实拍却是狗，输出仍是猫。怎样用消融区分视觉 token 根本没参与前向，与已经参与却被文本先验压掉这两种情况？

**答：** 先做三次前向，只改图像、不改那句误导提示：原图、纯噪声或全黑图、换成明显不同的第三种动物。三次答案都是“猫”，图像通道基本没进计算或权重为零；原图和噪声仍说猫、换成斑马却改口，说明视觉信号在，但被提示里的名词压过。没进计算就修接入（字节、特殊 token、视觉塔输出）；被盖住就改提示与训练，逼模型先报可见证据，并喂图文冲突样本。

**深入展开：** 工程漏接的指纹：请求体只有 URL 没有字节、占位符数量和视觉塔输出长度不一致、视觉塔输出方差接近 0、图像 token 段的注意力质量接近 0。这时换任何图都不会动 logits。先验压过视觉的指纹：视觉塔输出有结构，注意力也打在主体上，但解码一开始就吃到“猫”这个词，LLM 侧把图当插图、把提示当事实。消融必须在同一随机种子、同一解码参数下做，并记录图像 token 均值/方差和首个答案 token 的 logprob。修复分叉：漏接则在网关断言“图像特征非空且长度匹配”，上线门禁用无图对照。先验问题则把误导句从系统提示里拿掉，用户句改成“只根据像素回答，描述与图冲突时指出冲突”；训练加入“错误文本标签 + 正确图”对，损失必须让模型说出图上的物体而不是复述标签。评测集要单独做冲突切片，占开放 VQA 准确率再高也不算过。边界：极低分辨率或主体裁没了，三次消融会看起来像“没进计算”，先检查裁剪。不要用“请认真看图”这类空提示当修复，它不改变 token 是否存在，也不改变名词先验的对数几率。

**后续追问：** 噪声图仍答猫、但注意力图打在图像 token 上，你还坚称没进前向吗，还是认为视觉特征不可区分；冲突样本只占训练集 1%，会不会反而让模型学会“提示经常撒谎”而在一致样本上拒答；多图输入里只有第二张是狗，模型仍跟第一句“都是猫”，是位置编码问题还是提示范围问题。

**扩展问题：**
- 列出网关上线前必须打的四个断言（有字节、长度匹配、特征方差、无图对照答案应变）。
- 为什么把正确答案写进用户提示再问“图里是什么”，微调之后冲突准确率往往会更差？
- 如何用“无图对照一致率 / 冲突切片准确率 / 一致图文准确率”证明修的是接线还是先验，而不是把模型改成一律不信用户？

**推理回答：** 目标是像素能否定错误文本，约束是 LLM 把提示名词当高先验。用只换图的消融切开“没信号”和“有信号但输给文本”。接线问题用断言堵住，先验问题用冲突数据和证据先行，验收必须单独看冲突切片。

## MM-013. 件数与颜色都错——两箱蓝零件被盘点助手写成三箱红配件。怎样对照把分辨率、语言先验、属性没绑到物体这三种原因拆开，并且各自该动哪一段？

**答：** 三路对照就能分开：把货架那一块裁出来单独问，裁对了而整图错，是全局分辨率或注意力被背景稀释；去掉“零件/配件”这类品类词后颜色仍红，是视觉看错，一去掉就变蓝，是语言先验；训练集里该品类常和“红”共现、却很少要求“指着箱子说颜色”，是属性没绑到物体上。止血分别是：高清切片或检测框、强制先列举可见证据再计数、用同物不同色的对比样本重训或加检测工具，不要只改一句“请如实描述”。

**深入展开：** VLM 描述错误很少是单一 bug。分辨率路径：整图缩到例如 336–672 时，远处纸箱只占几个 patch，颜色被邻近货架平均，计数卷积核看不到箱缝；裁切后箱子变成几十个 patch，同一模型常会改口。语言先验路径：解码是在 LLM 里做的，提示或系统人设提到仓库常用红箱，最大似然会写出更常见的“红色配件三箱”；把误导性品类词删掉或改成中性“图中容器是什么颜色、几只”，若答案翻转即可定罪。绑定路径：字幕数据常写“货架上有红色和蓝色零件”，模型和“红”共现，却从未学“左边那只的颜色”；表现是单属性提问偶发对、组合提问必错。工具层：检测器出框 → 框内主色（色相直方图或小分类器）→ 框计数，语言模型只负责把已核实槽位写成句子，切断“凭先验填槽”。提示层要求：先列框和颜色，再求和，禁止一上来给叙事性总结。评测集要按属性组合切片（数、色、左右），并包含易共现的错误搭配，不能用整句 CIDEr 这类流畅度指标当事实性。边界：反光金属会让色相不可靠，应允许“无法判断颜色”；重叠堆叠的计数上界要声明，不要逼模型猜被挡住的箱子。

**后续追问：** 裁切后颜色对了、数量仍多一，你加分割边缘还是改提问为“只数贴着蓝色标签的箱子”；语言先验和绑定同时存在时，只加冲突样本够不够，要不要动投影层；检测器漏了一箱，整条流水线是回退纯 VLM 还是直接说数不清。

**扩展问题：**
- 写一个最小消融表：整图、中心裁切、去品类词、换同构图不同色，四格答案如何对应三种根因。
- 为什么提高描述流畅度的解码温度，往往会让数量错误更稳而不是更正？
- 如何用“颜色准确率、计数误差、组合属性准确率”分开展示修复，避免一个总描述分把仍在瞎数的模型刷绿？

**推理回答：** 目标是货架属性可核对，约束是 VLM 会用文本常识补视觉洞。先用裁切和去词消融定位洞在像素、先验还是绑定，再对那一层加切片、工具或对比样本。用分属性指标验收，不把通顺的错误描述当修复成功。

## MM-014. 重试过程中一次丢来八张几乎相同的界面图，真正新弹窗只出现在末张。感知哈希和 OCR 错误码，去重该走哪条？视觉语言模型该跑完全部八张还是只跑变化裁剪？怎样既控花费、又不会漏掉末帧故障？

**答：** 先用对齐后的分块感知哈希找「哪一块像素真的变了」，再用 OCR 串解释那一块是旧码重拍还是新对话框；两路单独做主键都会漏。视觉语言模型只吃增量裁剪（通常就是最后一张的新框），禁止八路整图并行。全局哈希过松会把小弹窗吞进同一簇，过紧会把 JPEG 重压当成八张新图；只比错误码会漏掉「页眉码没变、中央新罩了一层」。

**深入展开：** 连传八张是同一操作的重试突发，不是八个独立工单。流水线：①短合并窗（例如 300–800 ms）收齐突发，避免第一张一到就点火；②去掉状态栏时钟、电量后再做感知哈希，否则每张都因时间数字不同而「全新」；③对剩余区域切成例如 4×4 块，块级哈希和簇代表做异或——新对话框会点亮中央若干块，重试按钮闪动只点亮一小块；④OCR 只跑点亮块和页眉错误码槽，得到 `codes[]` 与新出现的短语。去重键是 `(cluster_id, block_delta_sig, new_ocr_tokens)`，不是单张全局 pHash，也不是单凭 `E_TIMEOUT`。VLM 的输入是增量框（加少量上下文边），不是八张短边 1024 的整屏；示意上八张整图各数百到两千视觉 token，八路就是单张的八倍预填充，增量框常常只需一路的一小块。边界：弹窗只占画面大约一成时，64 位全局哈希的汉明距离可能仍落在「近似重复」阈值内，真故障被折叠；阈值收到极小，同一屏的压缩噪声会打满账单。暗色主题、半透明蒙层会让块哈希全盘变化，这时应先做仿射对齐再比，或退回「最后一张整图 + 前序只抽码」。VLM 描述不得写回工单根因字段，只解释增量框里多了什么；前七张的代表图留一张作对照即可。评测必须包含「七张同码 + 第八张新层」和「八张仅时钟不同」两条，分别打漏检和空跑。

**后续追问：** 第八张其实是上一张的裁切放大，块对齐失败时你整图重跑还是先做特征点配准；合并窗内第九张又来了，已发出的增量推理怎样取消或合并；OCR 把新对话框读成乱码、块哈希却有差异，VLM 还跑不跑。

**扩展问题：**
- 画出从收齐突发到只发出一次 VLM 的数据流，标出全局哈希、块哈希、OCR 新词各自能单独否决「跳过」的条件。
- 为什么「错误码集合相等」不能当唯一跳过条件，举一种码不变但故障变了的界面。
- 怎样用视觉 token 数和漏检率一对指标证明「只跑增量」比「八路全跑」便宜且更安全？

**推理回答：** 目标是八张只为最后出现的新层付一次视觉推理，约束是全局外观几乎不变、故障却可能只活在一小块里。所以先对齐再分块找增量，OCR 负责给增量命名，VLM 只看差集。验收看空跑次数和「最后一帧新层」是否被留下，而不是看出站了几张图。

## MM-015. 多模态门禁如果只跑文本问答集，图文打架和糊图全缺席，就会出现文字项满分、看图翻车。至少还要切哪几类样本进去？

**答：** 文本问答集测的是语言先验，测不到「图和字打架时信谁」，也测不到 OCR 在糊图上的崩法。门禁至少要有：视觉定位（点出区域再答）、跨模态一致性（图文冲突必须发现）、OCR 或版面数字、低质量输入（模糊、强压缩、裁切）、以及安全与文化敏感图。每条样本带期望证据类型（框、页、时间戳），只对文字给分会放过「答案碰巧对、看的是错图」。

**深入展开：** 切片设计：①图文一致的常规题，建立基线；②冲突题：标题写 3 只、图里 4 只，期望模型指出不一致或按图作答并声明；③OCR 压力：小字、印章反白、表格跨页；④定位：问「左上角徽章是什么」，答案必须能回溯到框；⑤质量降级：同一金标图做模糊、高压缩、截断，看悬崖在哪；⑥语言先验陷阱：问题写成「图中的狗在做什么」但图里是猫，看模型会不会顺着「狗」编。指标不要只用开放生成的字面重合：封闭属性用准确率，定位用交并比或「框是否包含关键对象」，冲突题用「是否显式标记不一致」，安全用漏放和误杀。线上再加模态拆开的日志：无图请求、有图但 OCR 空、视觉模型超时，分别看失败率。评测图不得进训练和提示仓库。量级上，每个关键切片几十到一两百条带证据的题，比几千条无图问答更能挡住回归；切片太小只报区间，不拿一分之差做发版依据。

**后续追问：** 冲突题的标准答案是「以图为准」还是「报告冲突」，产品没拍板时评测怎么写；用另一个视觉语言模型当裁判，会不会和被测模型同族一起偏；糊图切片的模糊核要按传感器标定，还是随便做一次高斯模糊。

**扩展问题：**
- 列出一份发版门禁表：哪些切片必须不降，哪些允许用延迟换分数。
- 怎样从线上「用户说答错了」的工单反做成带框金标，又避免原图泄漏进训练？
- 只有文本分数、没有定位分数时，哪些幻觉会伪装成正确？

**推理回答：** 目标是预测「看见图的真实失败」，不是刷一张纯文本总分。约束是语言先验会在无图评测上得分，冲突和糊图才是线上的雷。按证据类型切片，强制引用框或页，用冲突题当一票否决。验收看切片红灯能否在发版前亮起。

## MM-016. 商品图问答日均两百万，预填充和 GPU 费用已经顶满。要保价签小字，你按什么顺序去动这三档：输入分辨率、每图视觉 token 数、模型档？

**答：** 先按查询是否真要读小字做分辨率路由，再砍每张图的视觉 token，最后才把“认颜色、数件数”这类题改走小模型；不要一上来全局降到短边 336。预填充成本几乎随视觉 token 数线性到超线性增长，重复商品图应缓存编码器输出。价签、规格字是最后才能动的信息，所以高分辨率只留给检测出文字的区域，而不是整图一律放大。

**深入展开：** 示意量级（需用本模型实测）：短边约 1344、patch 14 时，未池化约 96×96=9216 个 patch，2×2 合并后仍有约 2300 个视觉 token；日均 2×10^6 次意味着每天数十亿视觉 token 的预填充。注意力和 MLP 都吃这段前缀，所以 p95 变差往往先来自长预填充和队列，而不是多解几个输出 token。可执行顺序：①意图路由——“什么颜色/几件”走低分辨率或轻量分类头；“价签/型号/成分”才升级。②文字区域检测后只对那几块高清切片，背景用低分辨率全局图保留构图。③同一 CDN 哈希的图缓存视觉 token 或投影结果，缓存键绑编码器版本和切片策略。④简单意图降到小 VLM 或“检测+OCR+规则”，重模型只接 escalation。全局降分辨率会先糊掉 8–12pt 价签，OCR 编辑距离先炸，用户却仍觉得“图还看得见”。延迟账单要拆开：图像解码与缩放、视觉编码、预填充、解码、安全检查；砍预算时对着占比最大且对小字无贡献的项。边界：缓存必须随裁剪框和旋转失效；用户新拍的模糊图不能复用旧高清 embedding。不要用“平均分辨率下降”当成功，那会掩盖文字通道被牺牲。

**后续追问：** 路由模型把“这件多少钱”误判成外观题、走了低分辨率，哪一层必须兜底；缓存命中但商家刚换了主图像素、URL 未变，你靠内容哈希还是发布时间失效；小模型数件数够用、一遇到反光价签就瞎读，escalation 规则怎么写才不会把账单打回原形。

**扩展问题：**
- 给一条 800 毫秒端到端预算，按“解码 / 视觉编码 / 预填充 / 生成”拆一版示意占比，并标出你准备砍的两段。
- 为什么“整图降到 336”比“全局 336 + 价签切片 1024”更伤成交转化？
- 如何用“价签字段准确率、视觉 token 数 p95、单位请求 GPU 秒”成对证明省下的是背景像素，不是文字？

**推理回答：** 目标是单位请求更便宜、用户仍能读价，约束是视觉前缀主导预填充。按“对小字的信息贡献 / token”排序压缩，重复计算用缓存消掉。用字段准确率和 token 账单一起验收，禁止只报平均分辨率。

## MM-017. 营收这条线在每周例报里每月换皮重画，颜色方案、对数坐标都换了，源 CSV 纹丝未动。有人指着这根红色曲线问去年同一时期的值。检索时主键该挂在渲染出来的图上，还是挂在底下那张数据表上？一身新皮肤之后，哪条索引会率先把同一条指标拆成两幅互相认不出的图？

**答：** 数字必须挂在数据表（或绘图规范里的 `series_id`）上，渲染图只是当月的视觉编码，不能当检索主键。用户说「这根红线」时，先用本月图例或图表 spec 把颜色反查到指标，再回 CSV 做同比；红像素本身不是键。换肤后视觉索引会先把同一条营收打散成两张图：对数轴改曲率、配色改直方图，近邻漂向「别的红对数图」，而不是上月那张。

**深入展开：** 入库把一件事拆成两层。底层是稳定行：`(metric_id, grain, period, value, unit)`，来自未改动的 CSV；表层是当月渲染：配色通道、线性/对数尺度、线型、图例位置，写成一份可反查的编码表，例如 `color=#E11 → metric_id=revenue_net`。问「这根红线去年同期」的数据流是：定位本月图 → 读图例或 spec 完成指示语消解 → 用 `metric_id` 和 `period-1y` 回表取值。视觉 embedding 看的是像素家族：线性轴上的缓坡和对数轴上的折角、蓝线和红线，对对比学习编码器来说常常比「同一指标换了皮肤」更像两张不同的图；月份一换肤，旧 PNG 的近邻会滑向无关的红对数图，召回先裂成两簇。轴刻度 OCR 也稳不住：线性刻度「0 / 50 / 100」换成对数「1 / 10 / 100」后，文本向量跟着漂，只是比纯外观慢一步。边界：用户拿着上月幻灯片来问「和这张一样的红线」，那是「按图找图」，视觉索引才是对的入口，但命中后仍要跳到 `series_id`，不能把旧色号写死成指标名。图表库若能导出 Vega/ECharts 一类规范，编码表直接从 spec 生成，比对着 PNG 做色块聚类稳；只有位图时，图例色块和线的对应允许有一份当月缓存，换肤必须整表作废。量级上，一份周报十几条系列、每月一张新 PNG，视觉库会按月份线性膨胀，表索引始终是那十几条主键。

**后续追问：** 图例被裁掉、只剩一根红线时，你拒绝消解还是用当月默认色表赌；同一月里收入和退货都是红的，反查冲突怎样暴露给用户；只换对数轴、配色不动，视觉近邻大概先在哪一类图上找错邻居。

**扩展问题：**
- 怎样用「同 CSV、不同皮肤」的成对样本验收：表存在 `metric_id` 上应召回，视觉存在旧 PNG 上允许失败？
- 用户说「红线」其实指的是警戒阈水平线而不是序列，编码表缺 `mark_type` 会怎样误绑？
- 换肤作业和索引刷新谁先谁后，才能避免十分钟窗口里新图配旧色表？

**推理回答：** 目标是换肤后仍能回答同一指标的同比，约束是「红」属于当月编码、折线形状随尺度变。所以主键落在表和 `series_id`，颜色只做一次性反查；视觉索引只服务「长得像这张图」的入口。哪条路先把同指标打成两张图，看谁把外观写进了键——一定是视觉路先裂。

## MM-018. 占用还没顶格，四十页合同截图却一股脑进窗后开始串页。单页发票问答原本准确。为何应先按页召回，而不是把上下文继续拉长？

**答：** 窗口没满只说明还能塞 token，不说明注意力还能在四十页扫描件里做跨页对齐。每页视觉 token 是文本页的几十倍，四十页会把有用的条款淹没在页眉、印章和空白里，模型开始把第 3 页金额安到第 18 页标题上。应先按页（再按栏/块）做检索，只把命中的几页做成高清切片送进 VLM，答案强制带页码；加长上下文既贵又不能修复“看错页”。

**深入展开：** 单页成功只证明编码器能读一张版面：印章、表格线、发票字段。多页失败的数据流瓶颈通常在选择，不在“再多几千文本 token”。示意：每页截图经切片后产生例如 800–3000 个视觉 token，40 页就是约 3 万到 12 万视觉 token，即便名义窗口吃得下，softmax 注意力也会把质量摊薄，后页和前页的弱相关补丁互相抢。串页的典型模式：问“违约金上限”，模型引用了目录里出现过的数字，或把附件表头接到正文条款。正确链路：页面渲染 → 页级文本（OCR/嵌入式 PDF 字）+ 页级视觉 embedding 建索引 → 问题检索 top 页（例如 3–8 页）→ 对命中页做版面分块（标题、表、脚注）→ 必要时再高清问 VLM → 输出必须带页码和框。跨页表（上页表头、下页续表）靠页间“续表/见附件 B”规则或把相邻页当成同一检索命中展开，而不是一次吞全集。层级摘要（文档一句话、每页一句话）只用于导航，不能代替引用页的像素。边界：纯加长上下文会让成本随页数线性涨、准确率不涨；检索漏页比窗口略短更致命，所以召回要偏松、再用 VLM 精读。不要和“单页版面解析”混为一谈：版面工具解决的是一页内阅读顺序，检索解决的是页间选择。

**后续追问：** 检索只靠页级 OCR、扫描件字烂，视觉页 embedding 要不要双通道；命中了第 7 页但答案在第 8 页续表，你的展开策略是固定 ±1 页还是看“见表/附件”触发；窗口其实只剩 2k，仍要塞 8 页高清切片时，先降未命中页还是先降页内背景块。

**扩展问题：**
- 为什么“上下文使用率 60%”不能当作多页文档已经读完的证据？
- 设计页级命中评测：问题对应的金标页在 top-5 的比例，和最终答案页码一致率为什么要分开报？
- 附件扫描分辨率低于正文时，检索和精读的分辨率策略应怎样分开，避免把预算花在目录页上？

**推理回答：** 目标是跨页数字还能对上出处，约束是视觉 token 贵且注意力不随窗口广告线性变强。先检索再精读，把上下文留给证据页。用页码命中和串页错误率验收，而不是用窗口填充率。

## MM-019. 512×512 的图要从高斯噪声里采样出来。加噪前向和去噪反向各自在学什么？多步采样为什么常常先压进潜空间，而不是在像素平面上迭代？

**答：** 训练时的正向过程按时间表把干净图逐步加成近似高斯噪声，网络学的是反向：在给定时间步和可选文本条件下预测噪声或干净图，从而能从纯噪声迭代还原。生成时没有原图，只从噪声出发，每步更新一次状态，走完采样器规定的步数（示意：十几步到几十、上百步，取决于采样器，不是固定产品规格）。潜空间扩散先用 VAE 一类模型把像素压到更小的特征图再去噪，网格边长常按大约 8 倍缩小（以具体 VAE 为准，当作结构示意），注意力和卷积扫过的位置少一个数量级，多步采样的显存和时延才到可服务的量级。

**深入展开：** 像素空间里 512×512×3 的状态很大，每步都要在全分辨率上做卷积或注意力；潜空间用较低空间分辨率、较多通道承载同样语义，去噪器才能在单卡上重复跑。文本条件由文本编码器出序列，经 cross-attention 注入去噪骨干；无分类器引导把「有条件」和「无条件」两次预测按系数组合，系数过高会过饱和、过低则不跟提示——这是采样期控制，不是另学一套内容模型。DDIM 或各类 ODE 采样器改的是步数-质量曲线，内容仍由去噪器决定。边界：潜空间受 VAE 重建上限约束，小字和精确边缘会先糊，这不是多加去噪步就能单独修好的；步数太少先坏结构，不是把引导系数加大能补的。不要和自回归图像 token 模型混淆：扩散是对整幅状态做迭代 refinement，不是从左上角按光栅顺序写像素。

**后续追问：** 引导系数从 1 加到很高，过饱和长什么样，和「没跟上提示」如何区分；潜空间再压一档，人脸和印刷文字谁先不可用；同样步数下，随机采样和确定性采样谁更多样。

**扩展问题：**
- 训练为什么对时间步均匀（或按策略）随机采样，而不是只训最后几步去噪？
- 条件从短句换成空间掩码或边缘图，注入点更适合 cross-attention 还是通道拼接？
- 怎样用重建误差把「VAE 丢掉了笔画」和「去噪器没跟上提示」分成两个故障？

**推理回答：** 用可逆噪声链定义生成：正向提供训练对，反向定义采样。算力约束把状态从像素挪到潜空间，文本只作为每步条件。验收分开看 VAE 重建、提示符合度、步数-质量曲线，避免用一张「好不好看」把三件事混在一起。

## MM-020. 五十张同提示出图把机位和配色几乎锁死，美学分却不低。请先动引导、随机种子、训练集去重里的哪一项？用什么指标刻画「锐但构图撞车」？

**答：** 先降分类器自由引导（CFG）：过高引导把轨迹推进提示下最典型的那一张“好看客厅”，所以又锐又撞车。再把种子改成独立随机，并用图像 embedding 做近邻拒收，挡住同一轨迹的轻微抖动。训练去重放在下一轮数据迭代，它修的是权重里背过的构图，不救已经冻死的采样分布。量化撞车用五十张两两相似度的高分对数或聚类数，美学分只作质量下限，不作为放行理由。

**深入展开：** CFG 把有条件与无条件噪声预测做差并放大。示意：尺度从约 5–7 升到 10–15 时，提示遵循和局部锐度常升，可走的模式变少，输出挤向训练里最常见的机位和配色。五十张若还共用一个种子或只用种子 ±1，等于在同一条随机轨迹附近抖动，多样性统计会假低。操作顺序：把 CFG 降回中等 → 每张独立种子 → 用和训练无关的图像编码器算两两余弦，超过例如 0.90 的丢掉重抽（阈值按品类校准，人像和 SKU 图不可同一条）。若降 CFG 后变糊、变不跟提示，再在中等引导下加多样性惩罚（批内 embedding 互斥）或换采样器，而不是把引导加回去。训练侧：重复海报、同一套棚拍会在权重里形成吸引盆；去重按感知哈希加 embedding 近邻，再重训或继续训练才能搬走盆底。线上先动采样，因为重训是小时到天，而五十张撞车是解码超参问题的高概率解释。评测同时报：平均美学或人工可用率（质量下限）、两两相似度 90 分位、独立聚类数、以及提示关键物体的出现率（防止为了多样性把主体丢掉）。边界：SKU 广告本来就要同一机位，这时“撞车”是需求，应改用指定角度条件而不是盲目降 CFG。不要用文本编码器温度乱抖来“制造多样性”，那会先毁掉品牌字，而不是换机位。

**后续追问：** CFG 降到 4 之后出现残缺肢体，你回升引导还是加负向提示和人体条件；近邻拒收导致重抽次数爆炸，是阈值太严还是提示本身只有一种合法构图；去重后重训，旧的高美学吸引盆还在，你靠提高重复样本的惩罚还是加入新机位数据。

**扩展问题：**
- 画出 CFG 与“提示遵循 / 两两相似度”的示意权衡，标出你愿意停的工作点，而不是只追美学最大值。
- 五十张里有四十张只是裁切不同，embedding 拒收和感知哈希谁先该拦截？
- 如何证明多样性上升没有换来品牌色漂移：除了聚类数还要看哪一个颜色直方图约束？

**推理回答：** 目标是可发布且不要五十张重复，约束是高引导和重复训练数据都会造吸引盆。先改可逆的采样超参，再改数据。用相似度和质量成对指标定义“清晰但撞车”，避免被单维美学分绑架。

## MM-021. 审核路径中 OCR 应处哪一层、画面分类应处哪一层、跨模态合成应处哪一层？为何正文干净、配图用极小字写违规口号时，纯文本分类器会整条放行？

**答：** 文本分类器只看见用户填写的正文，看不见像素里的字和符号，所以“干净 caption + 脏图”会整条放行。OCR 必须作为图像通道的强制前置，和画面分类并行；两者的标签在融合层合成一条风险，而不是等文本通过后再“顺便看看图”。跨模态合成（无害句子配违禁标志、反话配仇恨符号）放在单模态分数之后、人工队列之前，低置信或高严重度必须升级。

**深入展开：** 数据流按层排：①分模态抽取——正文进文本模型；图像进通用视觉风险头（裸露、暴力、违禁标志）以及 OCR，OCR 文本再走与正文同一套或更严的词表与分类器；视频则抽关键帧加音轨转写。②单模态决策可先拦截“已确定的高危画面或高危 OCR”，避免融合层把铁证平均掉。③融合层输入包括正文分数、OCR 分数、画面分数、以及“正文与画面是否同指一个违禁对象”的一致性特征；常见逃逸是正文写“风景”、图上印口号，或两段各自擦边、拼起来越线。融合不要用简单与（会漏单通道命中），也不要无校准的或（误杀会爆）；用校准后的最大风险或带权重的 stacking，并给每通道留独立否决。④分数落在灰带或涉及人身、违法教唆时进人工，模型只提供区域框、OCR 摘录和通道分数，不代替终裁。量级上，OCR 对海报、截图、二次压缩 meme 会掉字，要按“有字区域”而不是整图去识别；漏检比多检更危险的类目应偏向召回。边界：用户关了 caption 不等于没有文本通道；贴纸、对联式竖排、谐音错别字要进评测集。音频辱骂和画面无害是另一条对称逃逸，链路应对称处理。审计留下各通道原始分，才能复盘是 OCR 漏了还是融合把分冲淡了。

**后续追问：** OCR 把口号认成乱码、画面头又只训练了裸露没训练标志，融合层还能不能救；正文是反讽、配图是违禁符号，你让哪一个通道拥有否决权；人工驳回后，是回灌 OCR 样本、画面头，还是只改融合权重。

**扩展问题：**
- 构造三种“单通道都擦边、组合后越线”的样本，说明融合特征至少要看哪两个通道的共现。
- 为什么“先审文本、通过后再审图”会系统漏掉图中文字攻击？
- 如何用“图中文字漏放率 / 纯风景误杀率 / 人工改判率”证明 OCR 前置有效，而不是把所有图都丢进最贵的多模态大模型？

**推理回答：** 约束是逃逸发生在通道缝上，不是正文分类阈值设错。强制看见像素里的字，单通道保留否决，融合只处理组合含义。用漏放和误杀成对验收，并把灰带留给人，而不是追求一条万能多模态分数。

## MM-022. 字幕相对画面滞后 400 ms，会议助理仍须同时收音并盯住共享桌面。声画同步、边收边推断、半成品答复打补丁该如何穿插，才不把时延积在「攒齐一帧才开口」？

**答：** 实时多模态的瓶颈通常不在「模型会不会看图」，而在音画时钟、流式裁剪和错误回修。共享屏幕按 1–5 fps 抽关键帧就够做「用户指着哪张表」，不必等满帧率每一帧；音频按 20–50 ms 帧做语音识别，字幕相对画面晚几百毫秒是常态，融合要在时间轴上开窗而不是等对齐完美。交互回复必须能先出部分结果（「我看到的是销售表」），等下一帧或最终字幕再补丁修正，而不是攒满一个完整话轮再推理。

**深入展开：** 时钟：音频设备时钟、通话播放时钟、屏幕采集时钟各自会漂，要以一个主时钟打 `t_audio, t_frame`，融合窗按观测延迟动态放大——字幕稳定晚 400 ms，就把文本事件和 0–600 ms 前的帧配对，而不是和「当前帧」。算力：高清每一帧都跑视觉语言模型会把 GPU 打满且挤掉识别；应对屏幕做场景切换检测（像素直方图或编码关键帧），只在切页、滚动停止时送一帧，中间复用上一帧的区域描述。流式：识别的 partial 可以触发低自信检索，final 到达再改写；对当前帧的描述写成可替换插槽，下一帧若还是同一页就做增量比较，避免整段重说。错误累积：早期 partial 把「营收」听成近音词，若已写入长期记忆会污染后面——部分结果要标临时，终稿才能进会话事实库。监控按模态拆：识别延迟、帧处理延迟、融合等待、语言模型首 token，只看平均端到端会把屏幕卡顿藏起来。质量和实时的取舍：指着数字读数需要较高分辨率切片，闲聊只需低分辨率整帧；两者用两条通路，不要共用一个「最高画质」开关。

**后续追问：** 网络把帧突发丢成 2 秒空洞时，你冻结最后一帧、宣布「画面中断」，还是只用音频；融合窗开到 1 秒会怎样把已经翻页的旧表和新字幕配在一起；部分结果已经念出口，回修是插一句更正还是只在字幕里改。

**扩展问题：**
- 给一条会议助手的延迟预算表，标出采集、传输、识别、抽帧、看图、融合、语言模型、语音合成各能占多少，哪一项最该被砍。
- 为什么监控必须按模态拆开，只看端到端分位延迟会漏掉哪类事故？
- 屏幕是代码编辑器而不是幻灯片时，抽帧策略和 OCR 策略要怎样改？

**推理回答：** 目标是边看边听还能在秒级内插话，而不是离线分析录像。约束是时钟不同步、满帧看图太贵、部分结果会错。用主时钟开窗融合，抽帧跟着场景走，部分结果可回修。验收看分模态延迟和「指着表读错页」的事故率。

## MM-023. 型号 X390 在嘈杂售后通话中被端到端 ASR 念成英文单词串。请按错误类型划分：频谱前端能修什么、编码器上下文能修什么、词表约束能修什么？

**答：** 波形先切短帧、做成频谱或 log-mel（示意：16 kHz，窗大约 25 ms，帧移大约 10 ms），让网络看见共振峰而不是原始采样点——这一层修的是「听不清音」，修不了「X390 应写成符号」。编码器在整段或流式窗口上做上下文，用前后音补含糊辅音、稳住语言切换。解码器、CTC 或 RNN-T 在词表上出子词；Whisper 一类 encoder-decoder 靠大规模弱监督（转写、翻译、多语言、噪声）变鲁棒，但仍会把字母数字型号念成英文词。SKU 这类封闭符号主要靠热词偏置、自定义词表和逆文本规范化，把「X three nine zero」收成「X390」，而不是换一个更大的通用声学模型。

**深入展开：** 数据流：VAD 切段 → 特征 → 编码器隐状态 → 解码。Encoder-decoder 适合准实时整段，长段要切片并抑制静音上的幻觉重复；RNN-T/CTC 更适合低延迟流式。特殊任务 token 可以切转写/翻译/语言识别，所以多语言噪声场景稳，但不等于认你们的零件号。时间戳来自对齐或专用时间头，说话人要另加 diarization。生产还要标点、ITN、置信度和领域词表。边界：8 kHz 电话会先伤辅音；中英代码切换在缺少混合数据时会黏错语言；encoder-decoder 在噪声或空段上会编整句，要用语音活动或压缩比把空段丢掉。热词加太猛会把普通词也改成型号，必须用领域测试集看误伤。Partial 结果在用户还在说时会跳，下游应区分 partial 和 final，不要把未定稿当事实锁进对话状态。

**后续追问：** 热词偏置的强度怎么调，才不会把「我要修」改成某个 SKU；流式 partial 和 final 不一致时，给 LLM 的到底锁哪一版；训练特征是 16 kHz、线路是 8 kHz，你只重采样还是换前端。

**扩展问题：**
- 同一段录音既要转写又要翻译，用任务 token 一次做完，和「先转写再翻译」相比，错误会堆在哪一层？
- 怎样保留时间戳，才能把「型号出现在第 12 秒」对齐回波形，而不是只交一整段纯文本？
- 为什么专业词错误率和通用 WER 必须拆开报，才能看出瓶颈在词表而不是声学？

**推理回答：** 先把错误分类：声学糊、语言切错、实体格式错。频谱和编码器对付前两类，型号这类符号优先用词表和 ITN。验收看总体 WER、SKU/实体错误率、时间戳偏移和幻觉句率，而不是只看一段通顺转写。

## MM-024. 五十步采样耗时八秒，交互预览却必须两秒内给出 512 图。指出潜空间、步数蒸馏、低分辨率草图各自砍掉哪一段等待；图中文字会最先毁在哪一项上？

**答：** 八秒里绝大部分是五十次去噪骨干前向，不是解码器。步数蒸馏（或一致性少步模型）把五十步收到例如 4–8 步，是唯一能按倍数贴近两秒的手段；潜空间扩散减的是每一步的空间尺寸，若你已经在潜空间上工作，它不是新杠杆；低分辨率草图先出 256 预览，把可交互的第一张图提前，精修放在用户未点“重出”时后台做。图中小字、logo 边缘对步数最敏感，会先于整体结构一起糊掉，所以预览可以少步，含包装文字的定稿不能只靠一步采样。

**深入展开：** 示意拆账（用本机实测替换）：文本编码约几十毫秒且可按提示缓存；五十步 × 每步约一百多毫秒量级 ≈ 七秒以上；VAE 解码约几十到一两百毫秒；可选安全检查再加一段。所以“换更快解码器”几乎不动八秒。蒸馏：用多步教师教少步学生逼近同一条去噪轨迹，交互档用 4–8 步出 512，质量档仍留 20+ 步或再超分。若当前还在像素空间扩散，先迁潜空间，每步算力按潜空间下采样倍数的平方降，这是架构级一次性收益。草图链路：256、少步、可先给界面；用户停顿再把同一噪声种子或同一潜变量升到 512 精修，避免预览和定稿完全不像。编译、算子融合、FP8/INT8 吃的是每步常数项，在步数仍为五十时不够把 8 秒打到 2 秒。文字失败模式：少步轨迹拟合不好高频笔画，品牌名先成色块；这时应在包装区保留更多步或先用矢量/渲染文字再贴回，而不是全局再加步把预览拖回 8 秒。边界：batch>1 的吞吐优化帮不了“单用户点一下”的延迟；安全检查若同步跑，要和首帧预览并行，不能串在两秒预算里独占。加速后必须复测提示遵循和文字可读，禁止只报秒数。

**后续追问：** 8 步蒸馏图够锐、包装上的 6 个字母仍错，你加局部步数、改 Cond 还是把文字移出扩散；草图 256 和精修 512 若噪声种子不一致，用户会投诉“点一下图换了一个”，种子和潜变量怎样传；量化后某步出现棋盘伪影，你回退精度还是只对 VAE 保持高精。

**扩展问题：**
- 在“文本编码 / 去噪循环 / 解码 / 安全检查”四段上标出蒸馏、潜空间、草图各自作用的段落，以及对 2 秒目标贡献接近零的段落。
- 为什么交互预览可以 4 步、含监管要求的成品质检图不行同一套步数？
- 如何用“time-to-first-preview、定稿文字可读率、提示关键物体保持率”证明加速没有把包装信息丢掉？

**推理回答：** 目标是两秒内可判断构图，约束是去噪步数线性决定延迟、文字是高频。先砍步数，潜空间只当还没迁时的架构收益，草图用来拆“先看见”和“再看清”。用首预览时间和文字切片一起验收，避免只优化秒数。

## MM-025. 地毯必须是指定 SKU，并铺在画面下半；沙发必须贴死左墙。只靠文字提示则版面每次游走。空间条件以何粒度介入？参考图适配以何粒度介入？分区重绘以何粒度介入？

**答：** 纯文本只有语义，没有度量坐标，所以“靠左墙/下半区”会在采样里游走。先上空间条件（边缘、深度、姿态或分割图）把家具占位钉在像素坐标上；再上参考图适配器把指定 SKU 的纹理和颜色锁到地毯区域；最后用蒙版做分区重绘，只改地毯、不动已经合格的沙发。顺序不能反：先贴参考纹理再调布局，花纹会印在错误物体上，重绘也救不回整体透视。

**深入展开：** 扩散过程的每一步都在 Cond 和噪声之间折中。文本 Cond 经过交叉注意力，对“沙发”“地毯”这类开放词有效，对“距左墙 20 像素、地毯 SKU 的循环花纹”几乎没有约束力；提高引导强度只会更靠近“一张典型客厅图”，不会更靠近你的平面图。空间条件网络把 canny/深度/分割在每一层注入去噪骨干，布局误差变成可回传的像素损失，适合钉墙、钉地平线和家具轮廓。参考适配把一张或几张 SKU 图编成额外的键值，往交叉注意力里插，锁的是外观不是位置——所以必须先有区域。分区重绘：已有满意的沙发和墙，只在地毯蒙版内重噪、并在蒙版内加强参考 Cond，避免整图重抽把左墙沙发抽丢。多阶段比单次“超长提示”稳：版式图或盒式布局 → 条件生成 → SKU 局部重绘 → 可选超分。评测用布局 IoU（沙发是否在左三分之一）、SKU 检索命中（地毯 embedding 是否靠近货盘图）、以及未蒙版区域的像素稳定性。边界：空间图和提示打架时（分割说左、文本说右）必须定义优先级，通常空间条件赢，否则又漂。参考图含场景背景时会把整张客厅风格带进来，应先抠产品再适配。不要假设某一次引导系数或某营销模型能替代空间 Cond。

**后续追问：** 只有一张用户手机拍的凌乱客厅、没有分割图，你先估深度再条件生成，还是先让模型出一张布局草图再当 Cond；SKU 参考是平铺图、场景要透视折叠，适配器做不到时是否改成蒙版内纹理映射；三件家具都要钉位置，一张分割图条件够不够，还是要分三次重绘防互相挤占。

**扩展问题：**
- 说明为什么把 guidance 从 7 加到 12 几乎不降低“沙发跑到房间右侧”的频率。
- 参考适配和分区重绘都开、但蒙版比真地毯大一圈时，墙脚会先出现哪类泄漏？
- 如何用“布局 IoU / SKU 近邻命中 / 未编辑区 LPIPS”证明可控性提升来自条件，而不是多抽了二十次碰运气？

**推理回答：** 目标是像素级摆位加指定商品外观，约束是文本条件没有坐标。按粒度从布局到身份到局部修补叠加条件，后一级不准破坏前一级。用几何和货盘匹配验收，不把更听话的散文提示当成控制。

## MM-026. 产品五秒短片里，主体颜色在半途换了，手数在帧间对不齐。一次吃时空 patch 的 DiT 优先锁定哪类时间一致性？先出关键帧再插值又优先锁定哪类？两者代价差在何处？

**答：** 中途变色是身份/外观在时间上没锁住，优先用一次时空去噪（Diffusion Transformer 吃时空 patch）或“首帧/参考图条件”把外观绑死；手数对不上是细结构在帧间闪烁，补帧和激进少步采样会先把它放大，应缩短插值跨度或在关键关节上加重时空注意力。一次生成贵在整段潜空间一起算；先出首尾关键帧再插值便宜，但两帧外观稍有偏差，中间就会渐变成另一种颜色或另一只手。

**深入展开：** 文本生成视频的主流路线是：把视频压到潜空间，按时空块（例如若干帧×空间 patch）做扩散或 DiT 去噪；也有级联（先低分辨率低帧率，再空间/时间超分），以及自回归视频 token。五秒、例如 8–16 fps，即使时间上压缩，token 数也是单图的十几倍到几十倍，整段注意力显存和时延上一个台阶。身份漂移：模型每帧各自靠近“一只鞋”的文本均值，没有跨帧的外观码，颜色就会游走；时空自注意力或把第一帧 latent 当条件，等于给整段一条外观锚。肢体拓扑错误：手指属于高频、小面积结构，时间上采样步少或光流/潜空间插值跨度大时，中间帧会“长出/融化”一根手指。关键帧+补帧适合镜头几乎静止的产品转台：先用图像模型钉住主体和 logo，再做小运动；主体要举手、绕圈，插值器没有物理约束，手数错误会更明显。级联超分能修清晰度，修不了已经错的拓扑。评测不要只看单帧清晰：抽帧做主体颜色直方图稳定性、关键点追踪的中断次数、以及“指定 hex 色在后半段是否仍在”。边界：加长视频用滑窗会在窗口接缝再次变色，需要重叠和对齐；音频同步是另一条时间轴，不能假设画面一致就口型一致。不要用无法核对的“电影感”宣传口径代替上述可重复切片。

**后续追问：** 只有产品静物旋转、几乎没有手指，你还会不会上完整时空 DiT；参考图条件把颜色锁住了，但 logo 文字在第 3 秒糊成色块，你加时间超分还是改用图像层先渲染包装；少步蒸馏之后身份稳了、手指更烂，步数和引导强度哪边先退。

**扩展问题：**
- 同一条提示下，对比“整段 16 帧一次去噪”和“2 关键帧 + 14 帧插值”在颜色漂移和手指错误上的典型失败，哪条链路该对哪种错误负责？
- 滑窗生成 20 秒时，窗口重叠多少才能避免接缝处换配色？
- 如何用“主体主色 ΔE 随时间的方差 / 关节追踪中断次数”验收时间一致性，而不是只打单帧美学分？

**推理回答：** 目标是五秒内同一件商品还在、结构别崩，约束是视频 token 比图像贵一个数量级。先按失败类型选时间建模：外观用长上下文或参考锚，细结构避免大跨度瞎插。用跨帧可测统计验收，成本只花在运动真的需要的那段时空注意力上。

## MM-027. token 仍在往外流，多音字「行」读作 háng 或者读作 xíng，此刻无法判定；句尾标点尚不知是句号或者问号。lookahead 应留在哪一层？消化文本的是 TTS 的哪一段？

**答：** 文本转语音通常分三段：文本规范化与读音（数字、缩写、多音字），声学模型（音素或字符 → 梅尔谱或潜语音表示），声码器（谱/潜 → 波形）。现代系统常把后两段合得更紧，但规范化仍然要先做，否则「2025」和「Dr.」会按字面乱读。Lookahead 应留在规范化和韵律决策之前：等一个短窗口（示意：几个词到一个子句）再锁定读音和句调，声码器按帧向外吐 PCM。逐 token 就念会把多音字和问句语调读错；等整段写完再合成，又会把开口延迟吃满。这里管的是「已经切好的文本块如何变成声」，不是 Agent 怎么切句。

**深入展开：** 规范化以规则和词典为主：货币、电话、日期、中文多音（行/数/重）、中英混排和品牌 SKU。声学侧可以是带显式对齐的并行模型，或流式编码器；自回归声学往往更稳但首包更慢。声码器（GAN、流模型或扩散声码一类）决定毛刺和帧延迟，帧长常见大约 10–20 ms。实时契约是：输入必须是「读音已可定」的文本块，输出是可拼接的音频帧，块边界处不能突然换音高或换说话人。质量看可懂度、自然度、说话人一致和首包时延，并单独看仿声滥用。边界：热词和 SKU 应热更新词典，不要等重训声学；文本里没有强调标记时，声学模型会把整段念平。跨块若完全不共享隐状态，会出现「每句换一种情绪」。排错要用音素级强制对齐：规范层错会稳定复现同一错读，声学层错则随说话人/韵律抖动。

**后续追问：** 下一个词还没到、多音无法消歧时，你延后开口、用词典默认音，还是先念一个再在下一块修正（通常不能修正）；声码器帧 10–20 ms 时，首包至少攒几帧才不破音；要和预录提示音同音色，你锁说话人嵌入还是锁同一套声码器权重。

**扩展问题：**
- 「订单 2025」和「2025 年」两套数字规则怎样避免互相覆盖？
- 流式块之间不重叠上下文时，为什么听感会变成一句一个口气？
- 如何用强制对齐把「读错」定位到规范层还是声学层，避免一上来就换整个 TTS 模型？

**推理回答：** 目标是开口快且读对，约束是读音和语调依赖右文。把不确定性留在规范化/韵律的短 lookahead，把声码器做成帧级流式。验收分三层：规范正确率、听感/音素错误、首包时延，不要用整句主观分掩盖首包策略。

## MM-028. 同一条 RTP 上情绪陪练做到一半要改走可审级联，后半段突然要转账。为避免听感换人、并挡住转账句绕过文本闸，音色、已播文本、工具权限在热切换时该怎样交接？

**答：** RTP 会话不重谈，只在句界把发送队列从端到端解码器改接到「文本政策 → TTS」的级联。交接三件东西：同一副说话人嵌入和响度曲线，保证不像换人；播放指针之前的已播文本写入级联上下文，未出口的端到端 token 整段丢弃；转账工具只在切换后挂上，且每一句出声前必须有可日志的文本过闸。端到端音频头必须从扬声器摘掉，否则确认句会以无文本波形出去。

**深入展开：** 触发靠旁路而不是等端到端自己「决定收手」：一路轻量转写或意图头并行看着「转账 / 付款 / 汇」一类槽位，命中后在当前句或音素边界停止向 RTP 写入新包，时间戳和序号保持连续，避免听筒里的咔嗒。快照至少含 `played_text`、`playback_offset`、`speaker_emb`、可选的语速/音高风格、以及此刻工具白名单。级联侧用同一嵌入和同一采样率（例如 16 kHz 或 24 kHz，两边必须一致）合成第一句过渡，包界做大约一两包的交叉淡化；编解码从离散语音码切到 PCM 再进同一载荷类型时，要重采样和响度对齐，这是「换人感」最常见的来源。已播文本按播放进度裁，不能把端到端已生成但没念出口的半句交给级联再念一遍，也不要让级联从头自我介绍。工具权限是硬切：陪练段没有转账工具；切换后才注入转账 schema，并且放音路径变成 `LLM 文本 → 限额/收款方/二次确认闸 → TTS → RTP`。禁止两路音频竞速选听感更好的那一路——那正是绕过文本闸的写法。情绪不要靠继续跑端到端骨干来「保韵律」，最多把风格向量交给级联 TTS 的可控韵律接口。转账结束后若回到陪练，同样在句界切回，并立刻卸掉支付工具。边界：意图头假阳性会把一次普通抱怨切到冷冰冰的核对流程，要允许用户一句话切回，且切回后不得留下半套转账参数；假阴性则继续用端到端说话，支付工具仍是关的，这比漏闸更可接受。

**后续追问：** 端到端正在念半句共情、意图头已经亮，你截在词界、等句号，还是先淡出再由级联重说这半句；级联第一句若必须播「将为你核对应转金额」，怎样沿用陪练的语速又不把金额念成聊天口吻；切换瞬间用户插话，已播偏移和未决工具调用谁先冻结。

**扩展问题：**
- 画出 RTP 发送端在切换前后的订阅关系：谁有权往 jitter 缓冲推包，谁被强制退订。
- 哪些日志字段能向审计证明「每一句转账相关语音都有过闸文本」，缺哪一列就不算可审？
- 两端采样率或响度差大约 3 dB 时用户会听到什么，验收时用句界拼接样本还是用整通录音？

**推理回答：** 目标是同一条通话里先保陪练韵律、后保转账可审，且听筒不断、声线不断。约束是端到端波形没有可拦截文本、重谈 RTP 会制造换人感。所以只在应用层句界换骨干，音色和已播文本随播放指针走，工具和文本闸跟级联绑定。验收听拼接是否像同一个人，并抽查转账句是否句句有过闸文本。

## MM-029. 同一会话第四轮开口只要 0.7 秒，对比第一轮冷启动的 1.6 秒。ASR 热词跨轮留不留、LLM 那份前缀 KV 留不留、TTS 的说话人嵌入留不留，哪几项每轮必须丢掉，才不会把上一轮卡号读进这一轮，也才能交代大约 900 毫秒差额从哪来？

**答：** 大约 900 毫秒是第一通在给「不含用户槽位」的部件加热：ASR 会话与解码图、LLM 里系统提示和工具定义的前缀 KV、TTS 说话人嵌入和声码器。这些可以跨轮常驻。必须每轮作废的是上一通的音频环缓、从卡号等槽位注入的 ASR 偏置、以及按旧文本建的合成缓存；对话 KV 里的卡号跨度不能再当可复读前缀。第四通变快，是因为静态前缀命中了，不是因为模型开始记住卡号。

**深入展开：** 把冷热差按部件拆开（示意，用本机追踪替换，不是某家承诺）：第一通可能含 ASR 图加载或 CUDA graph 捕获大约 150–300 ms、无前缀缓存时 LLM 预填充系统段大约 300–500 ms、说话人嵌入未命中和首包编译大约 80–200 ms，再加建链。第四通这些都还在进程里，新用户话只需增量预填充，首包 TTS 直接用已加载的嵌入，墙钟掉到大约 0.7 秒量级是说得通的。常驻白名单：TTS 嵌入只编码音色，不含词；LLM KV 只钉不可变前缀（人设、工具 JSON、安全段），缓存键带 `system_hash`；ASR 只留语种、产品名和本会话的品牌热词。作废名单：麦克风环形缓冲和端点状态，免得上一通尾音接到这一通；任何从已识别卡号、验证码、地址生成的热词或解码偏置，在该槽位提交或轮次结束时删除，否则偏置会让「查余额」更像再听出那串数字；TTS 按文本哈希的音频缓存不得跨含支付槽位的轮次复用。对话历史可以留在 KV 里好把指代接上，但卡号 span 要打 `redact`：生成侧看不到完整数字，TTS 文本再过一层掩码，用户说「再说一遍」也只能复述掩码后的形式。不要把上一通的 ASR 格子或对齐路径留到下一通当「语言模型上下文」。量测按轮次打点：`asr_session_warm`、`llm_prefix_hit`、`tts_spk_hit`，三盏灯全亮应对上那大约 900 ms；若第四通仍慢，先查前缀键被时间戳或轮次 id 污染，而不是再扩热词。这里解释的是跨轮状态的去留，不是把停口到出声再摊成一条串行预算。

**后续追问：** 用户这一通说「就是刚才那张卡」，模型需要指代、播报又不许出全号，KV 里留标记位还是留后四位；热词表按租户常驻，两个用户先后占用同一 ASR 会话进程，表怎样换；前缀 KV 命中但工具列表在第三通才启用，你整段作废还是只补一段新前缀。

**扩展问题：**
- 列出一张跨轮常驻表，三列分别是部件、是否允许含用户槽位、作废触发点。
- 怎样用第四通的 `prefix_hit` 和 `hotword_bias_size` 证明变快来自静态缓存，而不是卡号被写进了偏置？
- 说话人嵌入若误把上一通的韵律一起缓存，这一通尚未开口就会带上旧情绪，你在嵌入里丢掉哪些维？

**推理回答：** 目标是解释同会话里大约 900 ms 的冷热差，同时切断卡号的跨轮通道。约束是能加速的状态偏偏也是最容易夹带槽位的状态。所以只常驻音色、静态前缀和产品热词，槽位偏置与可复读音频每轮作废。验收看热身命中灯和「下一通是否还能吐出旧卡号」，两件事一起过才算。

## MM-030. 电话不能陷入静音，订座接口却要 8 到 12 秒才返回。进度口播、后台跑的任务、超时用的话术该如何串起来，避免模型在结果落地前把进行中说成已成功？

**答：** 把「掩盖等待」和「缩短等待」拆开：开口确认、按节拍换一句进度、工具不阻塞对话，这三条只避免沉默；真正缩短靠只读工具的提前启动、结果缓存和并行调用。订座是写操作，绝不能在用户说完前执行。实现上把工具打成独立任务，LLM 继续说话，结果以事件回到状态机；在结果落地前，系统提示必须写明「订座未完成」，禁止模型把进行中说成已成功。超时（例如约 12–15 秒仍无回包）要取消任务、如实告知并给出可执行下一步，而不是报 Error 或编造确认号。

**深入展开：** 示意节拍（仅作理解）：0 s「我去帮你锁座位。」→ 4 s「还在和餐厅系统确认，稍等。」→ 8 s「还差一点。」；5 s 返回就取消后续计时器，句界后直接报结果。进度句必须互不相同，且不要承诺秒数，除非这个工具有稳定的历史耗时。后台继续对话的例子：订座跑着时问「确认短信发哪个号码？」，用户回答后结果到达，再合并成一句「座位锁好了，短信会发到你刚说的号码」。状态机至少记 `tool_id, started_at, status, args, result|null`；LLM 看到的工具区只能是这些字段，未完成就没有 confirmation number。可用独立任务每 4 秒检查一次，到上限取消并返回空结果，由话术层说「餐厅系统这会儿没响应，要我再试一次，还是改发短信给经理？」。缓存适合航班状态、营业时间；预加载适合进线时就能确定的用户画像；并行适合互相独立的只读查询。写工具并行要小心双写。超时后的话术必须带下一步，不能停在「出错了」。

**后续追问：** 用户在结果到达前改口「还是改成三人」，未完成的写调用怎么取消、补偿；进度句由 LLM 现写还是用模板，现写会不会把「还在查」说成「已经订上了」；只读工具 p95 从 400 ms 漂到 3 s 时，你靠什么信号自动打开进度模式。

**扩展问题：**
- 哪些工具允许用户还没说完就提前发起，哪些绝对禁止，画出一条按副作用划分的线。
- 后台任务完成时 Agent 正在回答另一个问题，你插播、等句尾，还是压进下一轮？
- 超时后重试会不会造成重复下单，幂等键放在哪一层？

**推理回答：** 目标是线路不断、结果不谎报。约束是写工具有副作用、耗时不可控、模型会补全未见过的字段。先把工具变成可观察的后台任务，用未完成状态锁住话术，再用超时和幂等兜底。验收看最长沉默、超时率、虚假「已订好」事故和任务完成率。

## MM-031. 轮次静音窗还没宣布用户说完，你已拿此刻稳定转写去请求 LLM。说完确认后，怎样比较请求时的文本和最终转写，从而选择播放缓冲或丢弃重打，把第一次出字的时间藏进这段等待？

**答：** 普通链路串行：先等端点，再请求 LLM，再 TTS。抢跑式生成（常叫 preemptive generation；与解码器里用小模型猜 token 的 speculative decoding 不是一件事）在尚未确认说完时，就用当前稳定转写请求 LLM，结果只进缓冲、绝不播放。端点确认后比较「请求时的文本 + 当时的对话状态和工具列表」和「本轮最终转写及状态」：一致则立刻把缓冲交给 TTS，等于把 TTFT 叠进本来就要等的静音；不一致则取消飞行中的请求、丢缓冲，用最终文本重打。用户听不到错误半句，代价是作废那一次的 token。

**深入展开：** 示意：静音窗 500 ms，TTFT 400 ms。串行要 900 ms 才轮到 TTS；抢跑把 400 ms 叠进 500 ms，命中时大约省一次 TTFT，省幅上限就是静音窗本身。用户说「订两个人的位子…」后停顿，缓冲里已有「请问几点」；用户补「…晚上八点靠窗」，输入变了，必须取消并清空，再对 final 发起。除文本外，历史、可见工具、检索片段在等待中若变了，缓冲同样作废。不要在每个 interim partial 上开火：partial 抖动会制造请求风暴，常见策略是只在 ASR 的 final segment，或足够稳定的 partial 上启动。带副作用的工具不能抢跑执行：模型最多提议调用，下单和转账必须等轮次确认后由编排器执行。TTS 也可以预合成首句，但猜错会同时浪费 LLM 和 TTS，很多系统默认只抢跑 LLM。一句话里停顿三次，就可能产生三次被丢弃的请求，计费要按「命中率 × 节省毫秒」和「作废 token 占比」一起看。

**后续追问：** 和投机解码的区别用一句话怎么讲；高并发时抢跑把 GPU 打满，是否反而抬高所有人的 TTFT；最终转写只多了一个语气词，你做规范化后再比，还是要求字符串完全相等。

**扩展问题：**
- 短指令、订票适合默认打开，口述长邮件或讲故事为什么更该关？
- 只读查询能否随抢跑一起发出，写操作的暂存区怎样设计才不会下出脏单？
- 用户一句话停顿三次时，怎样估计被丢弃请求的 token 成本，并设并发上限避免拖垮共享推理池？

**推理回答：** 端点等待和 TTFT 没有数据依赖，可以重叠；正确性靠「确认前不播放」和「输入指纹比对」。失败模式是 interim 抖动和带副作用的工具。验收看命中率、每轮节省的毫秒、作废 token 占比和 voice-to-voice p95。

## MM-032. 用户念卡号时停顿半秒就被助手抢了话；下一通电话里问题已经问完，助手却迟迟不接。只看静音的规则会在哪类话上失手？再叠加「这句话意思已完整」的分数，又会在哪类话上失手？

**答：** 轮次控制要连续判断三件事：用户是否说完、现在该不该开口、开口时对方是否又在说话。纯静音阈值把「卡号中的思考停顿」和「问句结束后的间隙」当成同一种声学事件，所以短阈值抢半截数字，长阈值让已经闭合的问句干等。语义轮次检测读当前转写（有时加能量或基频），输出「这句话已经可执行」的分数：未结束的卡号、地址、枚举给低分继续等；「你们几点开门」给高分，可以在很短静音后就接。生产上是级联：VAD 发现间隙，语义分数决定还要不要续等，而不是二选一。

**深入展开：** VAD 只回答有没有人声，对内容一无所知；电话噪声、呼吸、键盘都会让它抖。静音窗示意 400–800 ms，短了抢话，长了冷场。语义头要学的是句法/意图是否完整，不是再做一次转写；它会在 ASR 把「开门」听成「开门吗」时误判完整，也会在口语省略句末语气词时普遍偏低。Backchannel（「嗯」「uh-huh」）不是新轮次，应加最短语音时长或过滤填充词，否则 Agent 会把附和当成插话。半双工流水线必须把这套判定写明白；全双工模型把听和说叠在一起，轮次变成隐式行为，日志更难拆。报号、读身份证这类位数已知的场景，应加规则先验（位数未满禁止结束），不要把决定权全交给分数。嘈杂线路要把 VAD 灵敏度和静音窗一起放宽，用一点延迟换少抢话。此处只判定「用户说完没有」，不处理「Agent 说话时用户插嘴」的声学回声问题。

**后续追问：** 中文口语常省略句末语气，语义分数会不会整体偏低，要不要按语言校准阈值；阈值和语义头谁先上线，怎样用抢话率、冷场率做开关；用户被误切后，已经发出的半句和对话历史怎样回滚。

**扩展问题：**
- 离线怎样标「可接话 / 应继续等」，才能避免用静音时长本身当训练标签、把错误学回去？
- 固定约 700 ms 在车载噪声里会增加抢话还是冷场，语义头单独能否补上？
- 16 位卡号长度已知时，规则约束和语义模型谁优先，位数已满但仍在复述校验数字呢？

**推理回答：** 把「说完」拆成声学间隙和语义完整两个独立信号，用抢卡号和问句冷场两种产品失败证明单信号不够。组合策略给出两个可调旋钮。验收看误切率、漏切率，以及数字串、地址类场景的专项。

## MM-033. 扬声器外放时 Agent 话没说完就自我截断，用户一声咳嗽同样掐掉播音。声学回声对消和插话确认时段怎么定，才能让真插话几乎立刻停播，回声或「嗯」不过度触发？

**答：** 自我打断来自扬声器漏进麦克风，VAD 把 Agent 自己的声音当成用户开口。先做声学回声消除：用正在播放的参考信号估计回声路径，从麦克风里减掉，再跑 VAD。确认打断不要「任何人声就停」：要求最短语音时长（例如约 300–500 ms）或持续 STT 攒到两三个词，咳嗽、「嗯嗯」和残余回声大多过不了这道门。确认后按扬声器 → 播放缓冲 → TTS → LLM 的顺序全停，对话历史只写用户实际听到的字，因为 LLM 出字远快于播放。

**深入展开：** AEC 的参考必须是真正送到 DAC 的那一路，含重采样和音量曲线，否则估计器对不上。免提、车载、笔记本外放的回声尾音可达几十到一两百毫秒，确认窗要比尾音更长，否则残余峰值会被当成打断。策略从快到稳：能量门（快、误停多）→ 最短时长 → 词数门（需一条始终在跑的流式 STT）。嘈杂电话线路应把窗加长；耳机、近讲麦可以更短。停播顺序反了会留下鬼影：LLM 已停但缓冲里还有 200–400 ms 音频。历史对齐要用播放进度映射回文本（按字或按音素时间戳），未播出的半句从 assistant 消息里剪掉，否则下一轮模型会引用用户没听见的价格。速度上可以先把播放增益打到接近 0，确认后再拆任务；若 STT 判定是附和，把增益拉回，用户几乎听不出停顿。即便底层换成全双工语音模型，仍需要一条「用户语音 vs 本机回放」的判决，不能假设模型自己分得清。

**后续追问：** 如何用回灌参考信号的回放测试 AEC，残差到什么量级才敢收紧确认窗；播放时间戳和 TTS 文本如何对齐到字；用户说「等一下」是打断换题还是让 Agent 暂停，状态机怎么分。

**扩展问题：**
- 评测集里回声、咳嗽、肯定性附和、重叠说话各要占多少，只用干净录音为什么会低估误停？
- 被打断后是立刻接「你说」，还是先用半秒确认再开口，两种做法分别伤延迟还是伤礼貌？
- 小缓冲降打断延迟时，TTS 的句子队列和尚未合成的后续句怎样一起作废？

**推理回答：** 目标是真插话很快停、假信号不停。约束是回声和附和在波形上都很像短语音。先用 AEC 拿掉自己的声音，再用时长或词数门过滤噪声，最后保证停干净且历史只反映已听内容。验收看打断响应时间、误打断率、自我打断率和打断后引用一致性。

## MM-034. 用户等了一会儿没听到声音，接连问了两遍「喂？」——查订单这个接口的 p95 有 2.8 秒。垫场的话该在第几秒开口，提前录好还是即时合成，才能让人觉得等得短，又不会盖住随后到来的正式答复？

**答：** 填充语压的是感知等待，不是接口墙钟：用户停话后大约 800–1200 ms 仍听不到任何声音，就容易以为掉线并插话。对已知慢工具（p95 超过约 1 秒）在发起调用时立刻播一句短确认；耗时不确定的路径再加计时兜底——例如停话后约 1 秒还没有可播的首句，就播库存里的下一句。音频优先用与 Agent 同音色的预录或预合成列表，避免再走一遍 TTS 排队；真正答案的首包到达后立刻切到正文，填充语播到一半也要能在句界停，防止叠音。

**深入展开：** 时间线示意（仅作理解，不是某产品规格）：endpoint 确认后约 300 ms 内拿到 STT final 且 LLM 决定要查单，此时开口「我帮你查一下订单。」约 1.5–2 秒；工具在后台并行，p95 2.8 秒返回时填充语刚好收尾，残留沉默可压到一两百毫秒。三种音频来源的取舍：预录最快、零合成抖动，但文案不能带订单号，且必须和线上 TTS 的音色、采样率、响度对齐，否则用户会觉得换人了；固定列表现合成，改文案不用重录，但每次多几十到两百毫秒 TTS；让 LLM 在 tool call 前先吐一句 preamble，最贴问题（「我去查 4521」），可是首 token 本身就要几百毫秒，慢工具场景里可能来不及当「第一声」。列表至少准备 4–6 句并轮换，禁止连续两轮同一句。填充语必须以 assistant 消息写入对话历史，否则下一轮 LLM 不知道自己已经说过，会再生成一句「我帮你查一下」。用户在填充语中途插话：停播、history 只留已播出的字、若查询对象已被新话更正则取消工具。承诺类措辞（「我帮你下单」）比查询类（「我去查一下」）危险，因为工具可能失败。

**后续追问：** 缓存命中只要 100 ms 还要不要填充语；计时阈值从 600 ms 拧到 1500 ms，「喂」插话率和「废话太多」投诉会怎样对打；填充语和真正答案的 TTS 流如何做交叉淡化，避免两个声音叠在一起。

**扩展问题：**
- 为什么「我帮你订好了」这类完成态填充语比「我去查一下」更危险？
- 工具要 10 秒才回时，一句填充语之后的进度句如何排班，才不会像报站？
- 预录填充语和线上 TTS 采样率或响度不一致时，用户会听到什么，怎样做验收？

**推理回答：** 目标是把「掉线感」压下去，约束是工具墙钟消不掉、线路又不能双声道叠播。先按工具 p95 决定要不要开口，再选音频来源让第一声尽量早，最后用历史写入和句界切分保证不重复、不叠音。验收看首个可听响应时间、填充语后残留沉默、用户说「喂」的比例，而不是只看接口耗时。

## MM-035. 用户得先听见第一句，而 LLM 还在写第三句。流式 token 送入 TTS 前，chunker 应按何种边界切片？第一块提早切开，对比等到整句再送，对开口时延和读音各有什么影响？

**答：** 若等整段回复再送 TTS，用户听到的沉默大约是全部生成时间加 TTS 首包。句级分块让第一句一闭合就进合成，后续句在播放中继续生成，流水线重叠。Chunker 缓冲 token，按标点或句法边界出块，而不是每来一个 token 就送——TTS 需要右文才能定读音和句调。首块和后续块策略应分开：首块偏向早切（逗号或短从句）以压 time-to-first-audio，后续块偏向整句以保自然度。早切省的是开口等待，付的是问句读成陈述、多音字看错后文。

**深入展开：** 时间示意：TTFT 0.3 s，此后大约每 0.1 s 十个 token，TTS 拿到块后 0.2 s 出声，回复三句各约 10 个 token。等齐三句再合成，开口大约 0.3+0.3+0.2=0.8 s，而且回复一加长就线性变差；第一句闭合就送，开口大约是「第一句写完 + 0.2 s」。中文不能套用「句点加空格」：句号后常常没有空格，要按「。！？」和分句词切。「3.5」「10 a.m.」「Dr.」需要缩写表，避免在点号处误切。Markdown 的星号和标题符号送 TTS 前要剥掉。用户打断必须清空未播队列，否则旧句会继续念完。只能吃独立句的 TTS 必须整句切；能跨块保留上下文的流式 TTS 才允许更小的首块。列表和「第一、第二」若按句硬切，听感会变成互不相关的三条命令。

**后续追问：** 中英混排时小数点和英文句号怎么消歧；首块最短词数设成多少，才不会把「好的」单独念成一句平调；打断发生时，chunker 缓冲、TTS 队列和已播文字怎样对齐。

**扩展问题：**
- 首块切在第一个逗号，后半句被当成新句重起音高，你用跨块上下文补，还是禁止用逗号切首块？
- 并列项和步骤清单按句切，会不会丢掉「还在枚举」的语调，chunker 要不要识别列表结构？
- 怎样用错误断句率和 time-to-first-audio 画一条可调曲线，而不是给所有语言拍一个固定标点规则？

**推理回答：** 瓶颈是「整段生成」与「TTS 要右文」的矛盾，所以按句（以及更早的首块）切开，让合成和续写重叠。规则必须按书写系统来，打断要清空队列。验收看首包时延、误断句造成的读音/语调错误，以及打断后残留播放时长。
