# 模型原理：Transformer 与语言模型

[← 返回目录](../README.md)

## ARCH-001. 八类闭集的工单路由为何更稳妥地交给判别模型，而要写出训练语料里不曾逐字出现的文案段落时为何只能上生成式模型？

**答：** 判别模型学的是 P(标签|输入)，输出落在固定类别里，校准和拒识都好比。生成式模型学的是数据分布，再从中采样出与训练相似、但不必逐字复制的新样本，所以能组合出从未出现过的句子。路由的正确答案在闭集中，用开放生成反而引入格式漂移和胡编类别；写文案的答案空间是开放序列，判别器给不出一段话。

**深入展开：** 文本上常见自回归分解（逐 token 预测下一个）；图像上常见从噪声逐步还原的扩散，以及更早的 GAN/VAE。工程上，生成是概率采样，同一提示可得到不同样本，必须处理幻觉（流畅但不真）、可控性、版权和安全。判别模型的典型失败是边界样本分错、概率校准差；生成模型的典型失败是编造事实、长度失控、越权内容。生产里常拆开：用判别或受限分类做路由和审核，用生成模型写回复。评估也不能共用——准确率/AUC 够分类，生成还要看事实一致性、多样性和人工抽检。

**后续追问：** 生成式模型为什么能用很流畅的句子编出一个不存在的订单号；若坚持用生成模型做分类，温度和约束解码怎样压格式风险；什么时候“让生成模型打标签”仍然合理。

**扩展问题：**
- 对比自回归和扩散在并行度、长度控制和中途可编辑性上的差别。
- 同一提示多次调用对不齐时，你改采样、加缓存，还是换成判别头？
- 列出明确不该开放生成、应交给规则或分类器的生产任务。

**推理回答：** 先看输出空间是闭集标签还是开放序列。闭集优先判别，开放内容才用生成。再比失败成本：分错类可重试；一段虚假条款的成本高得多，所以生成链路必须加护栏和评测集。

## ARCH-002. 各产品线不再单独训练小模型、改为共享同一套基础模型之后，工程账本上哪些会消失、哪些会新增？

**答：** 少掉的是为每个分类/抽取任务单独采标、训权重、维护训练集群的主路径；多出来的是围绕同一个通用模型搭产品系统：提示与上下文装配、检索与工具、评估集、安全过滤、路由和按 token 计费。基础模型把能力上限从“这份标注集能撑起什么分类器”改成“这段上下文能约束住什么生成”，但模型本身不是产品——权限、拒答和失败兜底仍要业务自己做。某条业务不该硬套的典型信号是：需要校准概率、设备端硬延迟、或输出必须可审计地确定性复现。

**深入展开：** 基础模型在海量混合语料上做自监督预训练（常见是下一 token 预测），得到可迁移的表示和生成先验，再用提示、RAG、工具或轻量微调适配下游。工程重心从“特征工程 + 每任务一份 checkpoint”转到“上下文预算 + 版本漂移 + 幻觉/注入事故”。成本结构也换了：主账单往往是推理 token 次数 × 单价，而不是每月重训 20 个小模型的 GPU 小时；但评估人力不会消失，反而要从离线 accuracy 扩到轨迹日志（提示、检索片段、工具出入参、输出）。失败模式也不同：小分类器会在分布外给一个错误标签，基础模型会流利地编一段看起来像政策的话。可观测性因此必须能回放一次完整请求，而不是只看任务分数仪表盘。

**后续追问：** 提示、检索、SFT 三种适配分别在什么数据量和延迟约束下划算；模型供应商改版后如何做回归以免“沉默变差”；哪些业务指标能证明切换基础模型后总拥有成本下降，而不是只看 GPU 利用率。

**扩展问题：**
- 一条只有几千条稳定标注、标签空间封闭的质检任务，继续用小分类器的理由是什么？
- 基础模型接入后，权限边界应该画在提示层、检索层还是工具沙箱层？
- 如何用影子流量对比“旧小模型 vs 基础模型 + RAG”，避免只看单条漂亮回复？

**推理回答：** 从目标“复用一个通用先验、少训多套权重”和约束“正确性、权限、可回滚”出发，先列出消失的训练流水线与新增的推理期控制面，再按失败形态决定哪些业务必须留下专用模型。验证看三件事：任务分数是否不降、单次请求是否可回放、token 成本是否可按业务线拆账。

## ARCH-003. 病案原文不能出园区、每周还要服务两千万 token，什么条件下应放弃外部闭源 API？

**答：** 先看数据驻留：病历原文、提示、日志只要有一项不能出园区，外部闭源 API 直接出局，与模型是否更强无关。若合规能过，再算账——两千万 token/周通常还撑不起专卡自托管的电费、空闲率和值班成本，闭源 API 往往更便宜。要拒绝 API，需要同时具备合规红线、可接受的质量缺口、以及团队能独立做评测、补丁和故障响应；更常见的落点是路由：带病历的请求走内网开放权重，脱敏后的少数难题才考虑受控外部模型。

**深入展开：** “开放权重”只保证拿得到参数和 tokenizer，不保证许可证允许商用，也不保证能审计对齐数据和安全策略。闭源 API 的收益是持续升级、工具链和合同 SLA，代价是输出不可复现、限流与价格不由你控、提示是否被用于改进取决于合同条款。量级示意：2×10⁷ token/周约合每年 10⁹ token；若按“每百万 token 数美元”的公开价估算，年模型费常常落在数百到数千美元，低于一台上交级 GPU 的折旧。但若必须园区内首 token <200 ms、必须离线微调、或审计要求逐条可回放，控制权比标价更贵。边界：能下载权重不等于能上线，商用限制、输出水印、以及运维人员缺口都会把“开放”方案卡死。选型应并列质量评测、p95 延迟、单位 token 成本、数据驻留、微调权和退出锁定，而不是只比公开聊天榜。

**后续追问：** 开放权重和开放训练数据分别对应哪一层法律风险？厂商提供专有云私有化时，还算不算你要拒绝的闭源，还要不要自托管？质量差几个评测点时，用检索和工具能否补上？

**扩展问题：**
- 周调用涨到 20 亿 token 时，自托管 7B / 70B 与继续用 API 的成本交叉点怎么估？
- 如何构造病历评测集，才能证明内网 14B 模型在本任务上可替代外部大模型？
- 多模型路由若把未脱敏字段打到外网，监控该抓哪些请求元数据？

**推理回答：** 约束排序是驻留/合规 → 任务质量下限 → 延迟与微调需求 → 成本。先用红线淘汰不能出园的 API，再用 token 量估算总拥有成本，避免“为了自主而在量还不够时自托管”。用分项评测、拒答率、延迟和审计日志验收，而不是用品牌印象。

## ARCH-004. 长度为 4k 的训练样本可以在一次前向里把整段交叉熵并行算完，但要写出 200 个 token 仍然得按时间步走完 200 步。同一种自回归因式分解，两边的可并行程度为何会完全两样？

**答：** 自回归把序列的联合概率拆成 ∏_t P(x_t | x_<t)。训练时真实前缀已经写在样本里，因果 mask 只是挡住“看未来”，每个位置可以同时预测下一个 token，一次前向就能对整段求交叉熵。生成时下一步的输入就是上一步刚采样出的 token，这是真实的数据依赖，mask 消不掉，所以 decode 步数随输出长度线性增长。

**深入展开：** 训练一次前向的主导形状是 [batch, T, d]，矩阵乘按 T 并行铺开；decode 每步有效序列长度是 1，算力利用率掉一截。KV cache 把已算过的 K、V 留下来，让第 t 步不必重算前 t−1 步的投影，计算从 O(t) 降到“只算新位置”，但读 cache 的访存仍随 t 涨，长输出后往往变成带宽瓶颈。首 token 延迟由整段 prompt 的 prefill 决定，后续 token 延迟由单步 decode 加 cache 读取决定。第 k 步一旦采错，错误 token 进入所有后续条件，误差沿链累积。投机解码、一次预测多个未来位置，都是在不改这条链式法则的前提下减少串行步数；并行去噪类模型则直接换掉这条分解。

**后续追问：** 因果 mask 为什么只能解放训练、帮不了生成？teacher forcing 和暴露偏差各指哪一段数据流？KV cache 省的是计算、显存还是两者互换？若训练目标改成一次预测后 4 个 token，串行步数和校准误差会怎样变？

**扩展问题：**
- 假设 prefill 2k、decode 512，粗算端到端延迟里串行步占多少，以及 cache 被踢出后延迟如何跳变。
- 按图像 patch 或语音帧做自回归生成时，这个串行瓶颈还在吗？常用哪些办法一次推进多步？
- 若训练也改成在模型自己吐出的前缀上算 loss（关掉 teacher forcing），吞吐和早期崩溃风险如何变化？

**推理回答：** 从链式法则看，条件里的 x_<t 在训练时是数据集提供的常数，在生成时是上一步的随机输出。常数条件可以整段并行；随机输出会在计算图上拉出逐步边，并行度从 T 掉到 1。所有加速手段要么缓存中间态，要么一次预测多个未来位置，要么放弃这条分解。

## ARCH-005. 一段听起来完全像真人坐席的答复却引用了错误政策，这是权重坏了，还是语言模型生成方式本身就会产出这种现象？

**答：** 这更像机制特性。大语言模型把输入切成 token，经 Transformer 算出词表上的下一 token 分布，再按贪心或采样写出续写；训练目标是让续写像训练语料里的客服口吻，不是去查一张保证正确的条款表。语法完美、政策错误，说明高似然的“客服腔”被采样出来了，事实约束从未进入目标函数。权重损坏更常表现为 NaN、乱码或突然崩溃，而不是通顺的张冠李戴。约束应加在检索（注入现行条款）、解码（无依据则拒答或强制引用）和后处理（规则/工具核对），而不是先重装权重。

**深入展开：** 数据流是 tokenize → embedding → L 层因果自注意力与前馈 → LM head 得到形状约为 `[vocab]` 的 logits → temperature / top-k / top-p 采样。词表规模常见在数万到数十万；模型没有单独的“真值头”。温度只改变分布的锋利程度，不把错误条款改成正确条款。当上下文缺条款、或检索到过期/竞品片段时，模型会用预训练里见过的类似话术填洞，流畅度反而升高。和分类器不同，这里没有闭合标签集，所以“看起来像正确答案的字符串”本身就是合法样本。线上要把“是否引用了条款片段、引用编号能否在知识库命中”做成日志字段，而不是只看 BLEU 或人工印象。

**后续追问：** 同样的幻觉，升高温度和关掉 RAG 各会怎样改变发生率；如果条款每周更新，微调权重和检索更新哪条路径的滞后更短；如何用“无依据必须拒答”的黄金集区分模型能力和系统装配问题。

**扩展问题：**
- 把解码改成只允许从条款原文复制 span，会牺牲哪些口语化能力？
- 多轮对话里过期条款残留在历史消息中，模型会优先信历史还是信新检索？
- 怎样用工具调用“查询政策 API”替代让模型默写政策？

**推理回答：** 先对齐训练目标（下一 token 似然）和推理接口（条件语言模型），再判断故障形态是“流利但无依据”还是“数值崩溃”。前者按“缺约束”修系统，后者才查 checkpoint 与数值。用条款核对通过率和拒答率验收，而不是用通顺度。

## ARCH-006. 中英夹杂的同一份代码在 A 模型上大约 800 token、在 B 上大约 1400，怎样向产品说明这并非胡乱计价？

**答：** Token 数由该模型自己的词表和切分规则定义，不是字符数或单词数。中英混排、标识符、空格和符号在不同词表里的合并程度差很多：偏英语的词表常把汉字和符号落到更短的片段甚至字节，同样 100 行代码可能从约 800 涨到约 1400（具体以实际 tokenizer 为准）。所以 B 不一定在“多收钱”，但同一段用户可见文本会吃掉 B 更多的上下文窗口，截断和计费都必须按在线那个 tokenizer 计，不能按字符预算。要对齐的是“这段请求在该模型下的 token 账单”，以及单价、质量是否一起报给产品。

**深入展开：** 英文粗算有时用“大约每 4 个字符 1 个 token”做数量级，中文若词表偏英文，常见到接近 1 字 1 token 或更碎；代码里的驼峰、缩进、运算符会进一步打散。角色分隔符、BOS/EOS 等特殊 token 每轮还会加一截固定开销。上下文窗口同时装系统提示、历史、检索和预留输出，800 vs 1400 意味着检索和多轮历史少了约 600 token 的预算，先触顶的是窗口而不是产品感觉上的“字数”。计费一般是（输入 token + 输出 token）× 单价，两端 tokenizer 不一致时，用 A 的计数去核对 B 的发票必然对不上。边界：字节回退时一个 Unicode 字符可能变成多个 token；反过来，领域词若进了词表会被压成 1 个。上线前用生产样本直方图看 p50/p95 token，而不是用一段英文散文的经验系数。

**后续追问：** 如何向财务解释“同一功能、两个模型、token 差一倍”仍然可能合理；截断策略按字符还是按 token，各自会切坏什么语言；特殊 token 和工具 schema 在账单里通常算输入的哪一段。

**扩展问题：**
- 为什么不能把模型 A 的 token id 序列直接喂给模型 B？
- 若要把中文 token 效率做成验收门槛，应该采样哪些真实工单而不是新闻语料？
- 压缩提示（去空格、缩写代码）在节省 token 的同时会怎样伤害模型读代码的能力？

**推理回答：** 从“计费单位 = 该模型 tokenizer 的输出长度”出发，先排除字符对齐的错觉，再用同一字符串在两个 tokenizer 上的实际计数和窗口剩余来解释差价与截断。验收是可复现的 encode 脚本和 p95 直方图，不是口头换算。

## ARCH-007. 一个同时接待中文、日文、英文的客服台：把原始字符串整段交给 SentencePiece，还是先按空白分词再走 WordPiece？举两个会切坏的例子来定夺。

**答：** 三语客服应优先让 SentencePiece 直接吃不预分词的原始字符串（BPE 或 Unigram 均可），因为中日文词与词之间常常没有空格，先按空格切会把整句中文当成一个“超级词”，后续 WordPiece 只能在句内硬拆或直接爆长度。WordPiece 预分词的典型翻车是：`退货政策如下：` 被当成单 token 块、或英文 `don't` / `SKU-123` 被空格和标点规则切得和训练时不一致。SentencePiece 的典型翻车是：语料偏中文时，英文代码和 URL 被切得很碎，p95 token 飙高。我的选择是 SentencePiece，回滚指标是英语/代码工单的 p95 token 和乱切率超过预算就重训或加代码专用正则预切。

**深入展开：** WordPiece 与 BPE 都学子词，但合并更偏向提升语言模型似然；BERT 类编码器常用，续片往往带 `##` 标记，且历史实现依赖“先按空白/标点得到词”。SentencePiece 把空格当成普通字符（常显示为 `▁`），不要求语言有分词器，更适合中日韩。Unigram 方案是从大词表剪枝使似然最大，而不是贪心合并。无论哪种，服务期必须用与训练完全同一份词表和预处理器，换 tokenizer 等于换模型。拍板时准备两个失败样本就够：一句无空格的日文地址（方案甲极易整块或乱切）、一段带下划线的英文订单号（方案乙在中文为主的词表上可能按字节碎切）。用这两类样本的 token 序列和还原字符串做金样，而不是用“对中文更友好”这种空话。

**后续追问：** 若流量 90% 中文、10% 代码，要不要做双 tokenizer 路由；WordPiece 的 `##` 和 SentencePiece 的 `▁` 在 embedding 里各编码了什么边界信息；重训 tokenizer 后旧的 SFT 语料必须怎样重编码。

**扩展问题：**
- 用户输入带零宽字符或全角空格时，两种流水线谁先被绕过安全关键字？
- 工具 JSON 里的键名被切碎，会怎样提高错误的工具调用率？
- 为什么“先用通用分词器再映射到模型词表”几乎总会掉点？

**推理回答：** 约束是中日无空格、英文和工单号又必须稳定切分，所以先淘汰依赖空白预分词的方案，再用 p95 token 和金样还原守住 SentencePiece 的英文退化。验收是固定样本的 encode/decode 往返和分类流量的分位数，不是语种直觉。

## ARCH-008. 随机遮盖 15% 位置来取代 next-token 预训练之后，模型为何更适合当句编码器，却几乎没法做流式对话？

**答：** 随机掩码让被遮位置看见左右上下文，学到的是双向填空，池化后的句向量对对称相似度任务更合适。聊天要的是 p(x_t | x_<t) 的因果分解，并且能一个 token 一个 token 往外吐；掩码目标没有这条链，强行生成只能反复“选位置、填掩码、再掩”，不能流式。换预训练目标等于换注意力掩码和输出头的形状，不是换一层皮。

**深入展开：** 自回归：输入 [t₀ … t_{n−1}]，目标 [t₁ … t_n]，因果掩码，每个位置都有损失，一次前向监督密度高。掩码语言建模：典型随机抽约 15% token 换成 mask / 随机 / 原词，只在这些位置算损失，每个预测吃满双向上下文。推理循环完全不同：自回归用 KV cache，每步投影 O(1)、注意力 O(t)；掩码模型若做生成，必须先定长度再迭代改写未定位置，步数与质量绑在一起，也无法在首 token 出现时就推给用户。量级：同样 8B、4K 序列，自回归有效预测位置是 4096，15% 掩码大约 614，单位 token 的梯度更稀，但每条信号带的双向上下文更全。边界：span 破坏、前缀语言模型（前缀双向、后缀因果）是中间谱；生产上常见拆法是掩码/双向模型做检索，自回归模型做生成。不要把“能补句子中的空”理解成“会聊天”。

**后续追问：** 15% 为什么不能随便改成 50%？自回归模型做句向量时 last-token 和 mean pooling 谁更弱、怎么补？非自回归迭代解码和真正的 decode 循环，延迟差在哪一项？

**扩展问题：**
- 若用 15% 掩码模型做翻译，要加什么结构才能自回归解码？
- 同一语料上，自回归和掩码目标达到同一验证损失，通常谁更耗 token？
- 聊天模型的提示中间被插入 mask token，前向会出什么行为？

**推理回答：** 从产品形态反推所需概率因式：流式聊天要因果条件概率，句向量要双向交互。对照两种目标的掩码、损失位置和推理循环，就能解释“向量变好、聊天变没”。用检索指标和“能否流式吐 token”两项验收。

## ARCH-009. 同事提议把正在服务的聊天模型骨干从 Transformer 换成 LSTM 以节省显存。你会拿哪些计算论据去回应，循环结构又在哪些场景仍然占优？

**答：** 训练阶段 Transformer 在因果 mask 下可对序列位置并行做矩阵乘，LSTM 必须按时间步串行，海量 token 的墙钟时间通常不可接受。长程依赖上，注意力一步就能让位置 i 读到位置 j，LSTM 要把信息沿隐状态传递 O(距离) 步，容易丢远距离约束。推理阶段对方的“省显存”有一部分是对的：LSTM 每层只存 O(d) 隐状态，Transformer 的 KV cache 是 O(序列长度 × d) 每层；但现代解码靠 KV 避免重算历史，逐步生成并不比 LSTM 多一轮循环，只是缓存更大。循环网络仍更合适的场合是：内存只有几十 MB 的端侧、序列极短的控制策略、或你明确接受弱长程建模来换恒定状态体积。

**深入展开：** 典型 decoder-only 块是 embedding（外加位置注入）→ 重复 L 次（归一化 → 多头自注意力 → 残差 → 归一化 → 前馈 → 残差）→ 最终归一化 → LM head。注意力里与序列两两相关的项大约按 O(n²d) 增长，投影和 FFN 按 O(nd²)。例如宽度约 4096、约 32 层的 7B 量级模型，训练 4k 上下文时 Transformer 能把 GPU 吃满在大 GEMM 上；同宽度 LSTM 的时间步依赖会让利用率掉下去。推理时若上下文到数千 token，KV 才是显存大头，这时该用 GQA、量化、窗口注意力来砍缓存，而不是退回 LSTM——后者省了 KV，却付不出同等规模的预训练代价，也难复用现有生态的并行核。边界：序列长度 1–2、状态必须恒定大小时，循环层作为轻量控制器仍然合理。

**后续追问：** 同样 7B 量级，训练吞吐和推理 KV 显存分别谁占优，能不能用一页估算写出来；线性注意力或状态空间模型相对 LSTM/Transformer 各砍了哪一项复杂度；如果必须上端侧，蒸馏小 Transformer 和上 LSTM 你怎么用延迟-质量曲线选。

**扩展问题：**
- 只把 FFN 换成循环混合、注意力仍保留，还能不能吃到并行训练的好处？
- KV cache 量化到 INT8 后，和 LSTM 的状态体积大概还差一个什么量级？
- 因果 Transformer 的逐步解码既然也是串行的，训练时的并行优势还在不在？

**推理回答：** 把“省显存”拆成训练峰值显存、推理 KV、墙钟吞吐三项，分别用并行度和复杂度对照，避免用推理期的 KV 体积去否定训练期为什么必须用 Transformer。端侧再单独用内存上限重评。用可复现的吞吐和显存日志，而不是架构偏好。

## ARCH-010. 目标词表大约三万时，BPE 的合并次序为何常把高频英文词收成一两段，却把只出现三次的分子式切得很碎？

**答：** BPE 从字符或字节出发，反复把当前语料里出现次数最多的相邻片段合并进词表，直到大约 3 万（或你设定的）词表规模。出现十万次的词，其内部字对会很早被合并，常常收成 1–2 个子词；只出现三次的分子式，字对计数永远排在 “th”“ing” 这类大众对后面，几乎轮不到合并，于是拆得很碎。领域一切换，最先该查的是术语的 fertility（每词 token 数）：碎切既浪费窗口，也让模型难以把整个术语当成稳定单元。

**深入展开：** 训练：统计 pair 频次 → 合并第一名 → 更新语料中的相邻关系 → 重复。编码时按学到的合并规则从左到右贪心匹配（实现细节因库而异，但结果由同一套合并表决定）。例如 `unhappiness` 若整体高频，可能先出现 `ness`、`happy`，再合成更长片段；`C6H12O6` 这种稀有交错数字/字母对，频次只有个位数，词表里往往只留下单字符级碎片。字节级 BPE 能避免 UNK，但稀有 Unicode 和公式仍可能按字节切开，一个可见字符对应多个 token。词表越大越能“记住”中频领域词，但也更占 embedding 矩阵（约 `vocab × d`）。边界：BPE 不保证切分符合形态学，`un-happiness` 和 `unhappi-ness` 都可能出现，取决于语料统计而不是语法书。

**后续追问：** 合并准则改成最大化语言模型似然（WordPiece 一类）时，稀有术语的命运会不会更好；继续增大词表到十万级，对 embedding 显存和中文/代码 fertility 各有什么交换；如何用领域词表覆盖率决定要不要为垂直语料重训 tokenizer。

**扩展问题：**
- 为什么训练好的 BPE 不能在推理期按新语料在线合并？
- 数字被切成单个数位时，加减运算的出错模式通常是什么？
- 同一词表在英文散文和日志 JSON 上的 fertility 差一个数量级时，上下文预算该按谁定？

**推理回答：** 从目标“固定词表下尽量压缩高频片段、又不要 UNK”推出合并只奖励频次，于是稀有分子式必然碎。用领域词列表量 fertility 和未知字节比例来验收，而不是看几个常见英文词是否整词命中。

## ARCH-011. 药名被 tokenizer 拆成六七段、术语一扎堆就占掉半截上下文、分类分数往下掉。已收敛的权重能不能只往词表追加新行，还是先量化平均子词数再选改法？

**答：** 先统计术语的平均子词数（fertility）、它们占输入 token 的比例，以及把同一术语人为并成更短序列后任务是否回升，确认是切分问题而不是标签噪声。已训完的模型不能只改 tokenizer：新 token 没有对齐的 embedding 和 LM head，需要初始化（例如子词向量平均）再继续预训练，或至少训开 embedding。从零训领域词表切分最干净但成本最高；byte-level 没有 OOV，序列仍可能很长。不改权重的做法是推理前把标准药名归一成已有的短序列，或把术语表放进检索。

**深入展开：** 中文药名、化学式、产品 SKU 在通用 BPE/Unigram 里往往没有整词，fertility=6～8 时，128 个术语就能吃掉近千 token，8k 窗口里有效句子被挤掉，分类器看到的是碎片共现而不是实体。直接扩词表而不训，新行是随机或零向量，训练分布外，生成会把该 id 当噪声。初始化用组成子词的均值能让第一轮就“像一个词”，但仍要有足够步数让注意力学会当原子用。词表变大，softmax 和 embedding 显存按词表线性涨，只为几百个药名扩到翻倍通常不划算，更合理的是加一小块领域词再续训。轻量归一化（别名→通用名、去空格、统一商品名）常常先于改词表。验收看术语 fertility、窗口占用、以及实体级 F1，不要只看整句准确率。

**后续追问：** 新 token 的 embedding 用子词平均、用零、还是用一个已有近义词拷贝，哪种在续训前几步更稳？只扩词表、不改分词规则，推理时旧文本会不会被切成和新 id 并存的两套形式？多语言药名（中文、拉丁名、商品名）要并成一个 token 还是三个？

**扩展问题：**
- 写一个统计脚本：输入术语表和 tokenizer，输出平均 fertility 和它们占总 token 的比例。
- 若只能续训 embedding、冻结其余层，哪些任务会回升、哪些（如生成药名）仍会碎？
- 领域词表和通用词表混用时，如何避免把普通中文词误合并导致歧义？

**推理回答：** 目标是减少术语占用并恢复实体可识别性，约束是已有 embedding 对齐不能随便拆。先用 fertility 和占用比例证明切分是根因，再按“改分词必须改权重并对齐”排除“只改词表文件”的捷径，最后按预算在归一化、加小词表续训、重训词表之间选。验证看术语 token 数和实体分数一起动，而不是只看词表大小。

## ARCH-012. 「不可退货」被向量检索排到「可以退货」旁边，根因是相似度公式算错了，还是句向量训练目标从未要求拆开否定？

**答：** 主因通常是训练目标，不是余弦本身算错。句向量对比学习拉近的是释义和主题相近的文本，“可以退货”与“不可退货”共享几乎全部词汇和场景，只差一个否定，几何上完全可以很近。余弦只是在这个空间里量角度，它不实现逻辑蕴涵。改公式（换成点积或 L2）很少能拆开否定对；更有效的是混合检索、带否定意识的重排、以及商品/政策版本等元数据硬过滤。也不要把检索 embedding 和 LLM 输入那张 token embedding 表当成同一个对象。

**深入展开：** LLM 内部的 token embedding 是 `[vocab, D]` 查找表，给第一层提供位置上的向量；RAG 用的句向量通常来自双塔/指令微调编码器，对整段做池化。后者优化的是“查询与正文档近、与负文档远”，负例很少按逻辑非来采，于是反义句会变成假近邻。分块若把“不可”切到下一块，向量更会只看见“退货”。经验维度常见为数百到一千多，相似度没有校准成概率。处理顺序建议：先用政策 ID、生效日期做过滤，再用稀疏（如 BM25）抓住“不/勿/禁止”这类词面，最后用 cross-encoder 重排看是否真的回答该问。若在双塔里硬灌否定对，要小心把所有带“不”的句子推开，造成召回塌缩。embedding 近 ≠ 事实对，只能当候选生成器。

**后续追问：** 指令型 embedding（查询和文档加不同前缀）能否缓解否定问题，还是仍然要重排；块大小从 200 字换到 800 字时，否定被截断的概率怎么变；何时该放弃向量、只对政策库做符号检索。

**扩展问题：**
- 同一模型的 token embedding 和拿最后一层均值当句向量，为什么几乎都不能直接当检索器？
- 多语言退货政策里，否定词素不同，双语近邻会不会比单语更糟？
- 如何用一组“仅差否定”的对抗查询做回归，防止 embedding 升级后召回看起来更好、逻辑上更差？

**推理回答：** 从 embedding 真正优化的配对目标出发，判断否定对不是离群 bug 而是目标外现象，于是把修复放在过滤和重排，而不是先改余弦。用对抗查询的准确率@k 和误召回率验收。

## ARCH-013. 窗口从 2k 撑到 8k 之后，注意力层里一次吃完整段提示的计算量和逐步解码时读 KV 的流量大约各乘几倍？优先收缩提示词，还是优先换注意力写法？

**答：** 长度×4。一层里注意力的二次项（QKᵀ 与对 V 的加权）按 n² 走，prefill 大约×16；QKV 投影和 FFN 按 n 走，大约×4。Decode 每步只多 1 条 query，计算近似随 n 线性，但要读的 KV 体积也 ×4，带宽往往先爆。自注意力的二次只在 prefill（以及错误地重算全序列时）完整出现，正确 decode 把历史摊进缓存。决策上先砍或摘要提示通常最便宜，因为 n 同时喂二次项和 KV；提示已是最小必要集仍不够时，再上 GQA/量化或窗口注意力，而不是先换主干。

**深入展开：** 设头维度 Dh、头数 H、`D=H·Dh`。Prefill 注意力 FLOPs 粗算 `~ 2n²D` 量级（再加投影 `~ 4nD²` 量级，含 QKV 与输出投影的常数因实现而异）。n: 2k→8k，二次项×16、投影×4，长上下文时二次项会从次要变成主导。KV 字节约为 `2 × L × n × H_kv × Dh × sizeof`；若 `H_kv=H` 则每 token 每层约 `4D` 字节（K 和 V，按字节宽度再乘）。例如宽度 4096、32 层、fp16、全头缓存，每 token 大约 0.5MB 量级，8k 就到数 GB——这是数量级示意，以实际 `H_kv` 和精度为准。GQA 把 `H_kv` 降到例如 8 对 32 头，KV 约 ÷4，decode 读带宽同比例降。滑动窗口把有效 k_len 卡死，牺牲远距离一次性可见性，适合局部依赖强的日志，不适合“条款在开头、问题在结尾”的客服。

**后续追问：** 用户平均历史是 1k 还是 8k，对“先砍提示 vs 先 GQA”的拐点在哪；窗口注意力漏掉系统提示时，你会把系统提示钉在可注意的锚点还是重复插入；prefill 二次项可用块稀疏/线性注意力替，decode 带宽能不能一起降。

**扩展问题：**
- 批大小从 1 增到 32 时，decode 是更容易算力打满还是 KV 带宽打满？
- 8k 上下文里“中间段落被忽略”，是 n² 算力问题还是注意力分配问题？
- 同一层里 FFN 的 O(n) 和注意力 O(n²) 在什么 n 和 D 下交叉？

**推理回答：** 把目标写成“把 n×4 的质量用上、但延迟/显存不×16”，拆二次计算与线性带宽两条曲线，优先减小 n（提示）再减小每 token 的 KV（GQA/量化）。用 prefill ms、decode tok/s 和 KV 占用三条曲线验证，而不是只看窗口广告数字。

## ARCH-014. 双向检索编码和对话续写若由同一服务承担，单独上线 decoder-only 为什么不够？

**答：** Decoder-only 用因果掩码，位置 i 看不到 i 之后的 token，做句向量时只能靠读完后的末 token 或单向 pooling，对称相似度通常弱于同规模双向 encoder。生成正好相反：encoder-only 没有自回归头，无法逐 token 解码；encoder-decoder 能做条件生成，但要维持编码、解码两套栈，聊天这种“上下文和回复同一条因果链”的负载更重。检索要双向、生成要因果，注意力模式是反的，硬共用一套因果权重会在其中一边交明显的质量税。

**深入展开：** Encoder-only：每层全双向自注意力，目标多为掩码还原或对比学习，输出 [B, S, d] 后用 CLS / mean pooling 得到向量，没有 decode 循环，也没有按生成步增长的 KV cache。Decoder-only：因果掩码 + next-token，prefill 后 decode 复用 KV，适合对话和工具循环。Encoder-decoder：encoder 双向编码源序列，decoder 对已生成目标做因果自注意力，并对 encoder 记忆做交叉注意力；翻译、摘要里源与目标不对齐时，交叉注意力比“把源和目标拼成一条因果序列”更稳。量级：检索 QPS 往往远高于生成 QPS，用约 1–3 亿参数的双向 encoder 打向量、用 7B 级 decoder 做生成，比让 7B 因果模型两边兼职更划算；同深度 encoder-decoder 的参数约是单栈的两倍，或每栈减半深度。边界：给因果模型加 embedding 微调（对比损失 + “压缩这句话”指令）可以接近双向效果，但要另挂头或 LoRA，本质上仍是两套行为，不是免费兼职。

**后续追问：** 前缀双向、后缀因果的 Prefix-LM 能不能一个权重兼两职？交叉注意力的 K/V 要不要 cache，和自注意力 KV cache 有何不同？用因果模型 last-token 做检索，失败样例通常长什么样？

**扩展问题：**
- 文档块 512 token、查询 20 token，双向 encoder 与因果 decoder 的注意力计算量差多少？
- 若必须单模型上线，用 encoder-decoder 做多轮聊天会在延迟和 KV 上付出什么？
- 检索向量维和生成模型 hidden 不一致时，服务要在哪一层做投影？

**推理回答：** 从任务要的信息方向出发：检索要对称双向，生成要因果可缓存。三种栈的掩码和输出头决定谁能做哪件事。再比较“一个大因果模型兼职”和“小双向 encoder + 生成模型”的 QPS 与质量，得出不要只用 decoder-only。用检索召回和对话评分成对验收。

## ARCH-015. RoPE、GQA、KV cache 与因果 mask，在 decoder-only 推理图里哪些拿掉会算错，哪些只改变快慢？

**答：** 删了会破坏自回归正确性的是：token embedding、因果 mask（或等价的“只能看过去”约束）、堆叠的注意力+前馈+残差+归一化、以及 LM head。若权重带着 RoPE 训、推理时删掉，Q/K 不再匹配训练分布，输出直接算错，这是正确性错误不是质量微调；只有从一开始就不加显式位置编码、只靠因果 mask 的模型（NoPE）仍能跑，但句序、抄写和长度外推会明显变差。KV cache 与 FlashAttention 是推理实现：数学上应与重算等价，删了只慢、不该改答案。GQA/MQA 是训练期就定下的头共享方案，推理时不能当开关乱切，把一种当另一种加载会形状对不上或 silently 错切；但 MHA 检查点可以按组对 K/V 头做均值池化合成 GQA，再短训一小段（原预训练算力的一小部分，见 GQA 论文，Ainslie et al. 2023）。把这四类混称为“架构必备”会误导排障：mask 错了是对错问题，cache 错了首先是快慢和是否数值等价问题。

**深入展开：** 形状契约：隐状态 `[B, S, D]`，拆头后 Q 为 `[B, H, S, Dh]`，K/V 在 GQA 下可能是 `[B, H_kv, S, Dh]` 且 `H_kv < H`。Prefill 需要下三角 mask，避免位置 i 读到 i 之后；decode 若只对当前 1 个 query 与已缓存 K 做点积，mask 已由缓存内容隐含。残差让深层可训练；现代实现常见 Pre-Norm + RMSNorm，FFN 常见带门控的 SwiGLU，这些是表达力/稳定性选择，不是“没有就不能做 next-token”。Weight tying（LM head 与 embedding 共享）可选。MoE 替换的是 FFN，同样不是骨架必备。故障对照：漏因果 mask → 训练损失虚低、推理对不上训练；漏 KV cache → 输出应近似不变但每步重算整段；带着 RoPE 训的权重推理漏 RoPE → 输出直接错；从零训的 NoPE（无 RoPE/ALiBi/相对偏置）→ 对调句子、数第 k 项变差；把 GQA 模型当 MHA 加载 → 直接报错或 silently 错切权重。

**后续追问：** Pre-Norm 换成 Post-Norm 会先伤训练稳定还是推理数值；没有显式位置编码、只靠因果 mask 的模型（有时称为 NoPE）能走到多长；如何用“同一输入开关 cache”做逐 token logits 对比，证明 cache 实现等价。

**扩展问题：**
- 多头是表达力选项还是正确性选项？单头 decoder 能完成哪些任务、崩在哪些任务？
- 只对 MHA 的 K/V 头做组内均值池化、不再短训就当 GQA 用，质量会掉在哪，短训又能挽回什么？
- 归一化放在注意力前还是后，对梯度尺度和可堆叠层数有何不同？

**推理回答：** 按“没有它，next-token 条件分布是否还定义正确 / 是否仍可训练 / 是否只影响吞吐”三层打标签，再用一种具体故障现象反证分类没有混层。验收用：mask 单测、cache 开关的 logits 对齐、位置相关任务的消融。

## ARCH-016. 保持 d_model 不变，把 32 个注意力头收成 1 个更宽的头，表达能力与 KV 带宽各自会在何处受损？

**答：** 单头时所有位置只共享一套注意力分布，只能形成一种“谁看谁”的模式；多头把同一隐藏维度切成多个子空间，例如 32×128，各头可同时抓句法、指代、邻近位置等不同关系，再拼回原维度。QKV 投影的参数量几乎不随这种重排改变。推理 KV cache 的字节数由 KV 头数 × head_dim 决定：若仍是每查询头一套 KV，头数从 32 收到 1，带宽大约降 32 倍，但表达力通常明显变差。这正是后来用 GQA/MQA——多套 Q、少套 KV——做折中的原因。

**深入展开：** 每个头 h 计算 softmax(QₕKₕᵀ/√dₖ)Vₕ，concat 后再乘 Wᴼ。dₖ = d_model / n_heads，例如 4096/32=128。头之间不共享注意力矩阵，才能并行学多种对齐。头不是越多越好：head_dim 太小（例如小于 32）点积分辨率差；头太多则容易冗余。GQA 让一组查询头共享 K/V，缓存按 KV 头数而不是查询头数增长：32 个查询头、8 个 KV 头时，缓存大约是纯 MHA 的 1/4。线上若把 32 头改成 8 头 GQA，但权重不是按 GQA 训的，属于架构不匹配；指代变差时先确认训练配置，而不是只怪头数。

**后续追问：** 为什么常见 head_dim 取 64 或 128 而不是 16；MQA 在长上下文下能省多少带宽、通常伤哪类对齐任务；怎样可视化确认不同头是否真的学到不同模式。

**扩展问题：**
- 写出 MHA、GQA、MQA 下每 token 的 KV 字节公式，并代入 32 查询头、8 个 KV 头、dₖ=128、FP16。
- 某个头发散或几乎不工作，对总输出的影响如何被 Wᴼ 吸收？
- 若推理带宽是硬约束，质量评估至少应覆盖哪些任务再决定头结构？

**推理回答：** 约束是 d_model 固定，可变的是“几套注意力分布”和“几套 KV”。表达力看独立对齐的个数，带宽看 KV 头数×维度×精度。先拆这两条，再在 MHA 与 GQA 之间选，并用指代、长距检索和吞吐一起验收。

## ARCH-017. 解码进行到第 t 个位置时，Q、K、V 分别是几行？分数若误用查询与查询的转置相乘，哪些线性层会沦为死权重？

**答：** 正确 decode 时，当前层 Q 只有 1 行（当前 token），K 和 V 各有 t 行（历史加当前），分别是该层归一化隐状态经 `W_Q, W_K, W_V` 线性变换再按头拆开。分数应为 `QKᵀ / √Dh`，形状 `[B, H, 1, t]`，再对 V 加权。若训练图里误用 `QQᵀ` 当分数且 V 仍来自 `W_V`，则 `W_K` 不进入计算图，梯度应接近 0，成为死权重；`W_Q` 会同时充当查询和“伪键”，检索结构被破坏。注意：从零训练时若只是把 K 和 V 的名字对调，那只是重参数化，loss 仍可能下降——所以要用“谁没进点积”而不是“名字接反”来定义这个 bug。

**深入展开：** 形状契约：

```
Q: [B, H, q_len, Dh]   # decode: q_len=1；prefill/训练: q_len=S
K: [B, H_kv, k_len, Dh]
V: [B, H_kv, k_len, Dh]
scores: [B, H, q_len, k_len]
```

Q 表达“当前位置要找什么”，K 表达“各历史位置的索引”，V 表达“被聚合的内容”。`1/√Dh` 用来压点积尺度，避免 softmax 饱和。训练时若错误写成 `QQᵀ`，分数形状仍是 `[B, H, S, S]`，单测形状可能通过，必须查 `W_K` 的梯度范数或参数是否更新。GQA 下 `H_kv < H`，K/V 行数仍是 `k_len`，只是头数更少，查询头要分组共享。边界：prefill 的 Q 也是 S 行，但那是一次性并行，不是 decode 每步都把 Q 做成 t 行；有人在 decode 误算全序列 Q 却只切了错误的一行分数，会表现为错位关注和多余算力。

**后续追问：** 把 V 和 K 在训练中对调为什么常常“还能收敛”；没有独立 `W_Q/W_K/W_V`、直接用同一 x 做注意力（早期变体）损失了什么；如何用一张注意力图判断模型在抄上下文还是在用当前 query 检索。

**扩展问题：**
- Dh 从 64 增到 256 而不缩放点积，softmax 会先出现什么数值现象？
- 交叉注意力里 Q 的行数跟谁走、K/V 的行数跟谁走？
- 若只对 K 做 RoPE、忘了对 Q 做，相对位置还会不会成立？

**推理回答：** 先用“当前步新增 1 个位置”写出行数契约，再把错误公式代入计算图看谁的梯度消失。验收是形状断言加 `W_K` 梯度探针，而不是看 loss 是否还能下降。

## ARCH-018. 怎样用 Q·K 点积的方差，判断 head 宽度拉到 256（原先 64）后 softmax 塌成 one-hot 时该不该除以 √dₖ？

**答：** 先估算 Q·K 的尺度。若各维大致零均值、方差约 1 且近似独立，未缩放点积的方差约为 dₖ：dₖ 从 64 到 256，标准差大约从 8 涨到 16。过大的正负分数会把 softmax 推进饱和区，权重接近 one-hot，对 logits 的梯度接近 0。除以 √dₖ 后方差回到约 1，注意力才停在可训练的斜率上。

**深入展开：** 设 q,k ∈ ℝ^{dₖ}，q·k = Σᵢ qᵢkᵢ。独立、零均值、方差为 1 时 Var(q·k)=dₖ，所以除以 √dₖ 是把送进 softmax 的分数标准差拉回常数级。实际 Q、K 经过线性层后方差未必是 1，有的实现还会再乘可学习缩放，或对 Q/K 做 RMSNorm，因此“必须除 √dₖ”不是唯一稳法；但 dₖ 变大又完全不缩放时，饱和是最常见的失败。softmax(x)ᵢ 的梯度含 pᵢ(1−pᵢ)，p→0 或 1 时梯度消失。层内注意力熵接近 0 表示塌缩；再看对 QK 的梯度范数即可交叉验证。常见 head_dim 是 64 或 128；64→256 若不改缩放，等效把温度降到大约原来的一半，训练更脆。

**后续追问：** Q、K 已经按头做了 RMSNorm 时还要不要固定除 √dₖ；可学习缩放和 √dₖ 同时存在时谁主导；怎样用注意力熵和梯度直方图区分“缩放不足”和“学习率过大”。

**扩展问题：**
- 在独立同方差假设下写出 Var(q·k)，并说明除以 √dₖ 后方差变成多少。
- 若实际激活方差是 σ² 而不是 1，缩放因子应改成什么？
- 怎样用一次前向打印某层注意力 logits 的分位数，确认是否已经饱和？

**推理回答：** 目标是稳住 softmax 的输入尺度。约束是 dₖ 增大时点积是 dₖ 项之和，方差线性涨。先写方差，再看饱和区梯度，最后对照日志里的熵和梯度。若已对 Q/K 归一化，就重新估方差再决定缩放，而不是死记系数。

## ARCH-019. 70B 稠密模型粗算下来参数大部分落在 MLP。这如何指导你加宽 FFN、堆叠层数，以及是否用 MoE 替换 FFN？

**答：** 一层里注意力的 QKV 加输出投影大约是 4d²；膨胀比约 4 的两层 MLP 大约是 8d²，SwiGLU 常见三块投影、中间维大约 (8/3)d 到 4d，FFN 仍通常占一层参数的大半。加宽 FFN 是加容量最直接的旋钮；加层会同时复制注意力和 FFN，并且增加 KV cache 的层数。MoE 则是把这份最重的 FFN 复制成多专家、每 token 只激活少数，用几乎不变的每 token 算力换更大总参数。

**深入展开：** 注意力已经把上下文混进每个位置后，FFN 对每个 token 独立做非线性——常见 SwiGLU：SiLU(xW_gate) ⊙ (xW_up)，再乘 W_down。它不看邻居，负责通道内重组合和记忆型映射。量级例子：d=8192、中间 28672 的 SwiGLU，单层 FFN 约 3×8192×28672 ≈ 7.0×10⁸ 参数；80 层就是大约 560 亿，已经接近 70B 总参数的主体。因此量化、稀疏、专家并行往往先打 FFN。边界：FFN 过宽会让训练激活显存暴涨；MoE 引入路由不均、专家空转和跨设备通信。不要把 FFN 当成注意力后面的小尾巴，它是容量主仓。

**后续追问：** 膨胀比为什么常落在 4 附近而不是 16；SwiGLU 比两层 GELU MLP 多一块矩阵，参数和激活如何折算；推理算力预算固定时，加宽 dense FFN 和加专家数哪个更划算。

**扩展问题：**
- 对 d=4096、32 层、中间维 11008 的 SwiGLU，估算 FFN 占总参数的大致比例。
- 单步 FFN 不看邻居，多层堆叠后远距离信息是怎么进来的？
- 把 FFN 换成 MoE 后，训练要盯哪些路由指标以免专家塌缩？

**推理回答：** 先按层拆参数：约 4d² 的注意力对约 8d² 或三投影 FFN，容量在 FFN。目标是加知识且推理预算紧，就优先把 FFN 做成 MoE；目标是加强上下文混合，才加深注意力栈。用参数公式和激活显存一起限制宽度，而不是只看总参数数字。

## ARCH-020. 某模型的归一化层只做一件事：除以均方根，既不减均值，也没有偏置。与 LayerNorm 相比，前向计算省掉了哪几步？网络很深时，残差流的量级靠什么维持住？

**答：** RMSNorm 计算 x̂ = x / √(mean(x²)+ε)，再乘可学习的 γ，常见实现不加 β。对比 LayerNorm，少了一次求均值、一次向量减法、一次加偏置，归约仍沿 D，kernel 更短、访存更少。它不把各维均值拉到 0，只把向量的欧氏尺度拉回常数附近；残差流因此不会按层数线性胀死。公共偏置要靠后面的线性层吸收。许多现代 decoder 用它配 Pre-Norm，是因为少掉的那几步几乎不换稳定性。

**深入展开：** 对 x∈R^D，LayerNorm 要保存 μ、再广播相减、再算方差；RMSNorm 只做一次平方均值。D=4096 时每层每 token 少几次全宽读写，叠几十层、长序列时带宽可见。尺度目标不同：LayerNorm 把分布钉到标准正态附近，RMSNorm 只钉二阶矩，一阶矩可以非零。若某一层所有通道共享一个很大的加性偏置，RMSNorm 不会清掉它，但下一层 W 可以学到抵消。数值上归约仍建议 FP32，γ 仍建议初始化为 1，避免第一层就把激活放大。它不是“免费的 LayerNorm”：如果你的诊断依赖“各维均值约 0”，RMSNorm 的输出不会满足这条，单元测试不要照搬。

**后续追问：** 为什么很多实现删掉 β 却保留 γ？若残差流已经用 Pre-Norm，再减均值还有没有独立价值？RMSNorm 和后面的门控 FFN（如 SwiGLU）叠在一起时，谁在管尺度、谁在管稀疏？

**扩展问题：**
- 写出 RMSNorm 的三行实现，并和 LayerNorm 并排标出省掉的算子。
- 在混合精度下只把 RMS 归约升到 FP32，线性层留 BF16，通常能消除哪类 NaN？
- 若把 γ 固定为 1 且不可学，深层训练更可能在梯度上失稳还是在激活幅度上失稳？

**推理回答：** 目标是稳住深层尺度，约束是每层算子和显存都要少。先把 LayerNorm 拆成减均值/除方差/仿射，划掉对 Transformer 残差不必要的减均值和 β，剩下除 RMS 和 γ；再用“只控二阶矩、偏置交给下一线性层”解释为何还能训。验收看激活 RMS 是否随层爆炸、以及换算子后 loss 曲线是否仍平滑，而不是看均值是否为 0。

## ARCH-021. 翻译到目标侧第 t 步，就 cross-attention 而言，查询读哪边、键值读哪边？源句 K/V 为何只需算一次？若给源序列也套下三角 mask，会破坏什么？

**答：** 第 t 步，Q 来自解码器当前层、长度为 1（当前目标位置）的隐状态；K、V 来自编码器对整句源文的输出，行数等于源长度 S_src，与 t 无关。公式仍是 `softmax(QKᵀ/√Dh)V`，但分数形状是 `[1, S_src]`（训练时是 `[S_tgt, S_src]`），源侧通常不加因果 mask，因为译第 t 个词时整句原文都允许看见。源文在一次编码后不再变，所以源侧 K、V 只算一次，每个解码步复用——这和自注意力 KV 随 t 增长不同。若误给源序列套上因果 mask，后面的源词对前面的目标位置不可见，等于翻译时“后半句原文被挡掉”，对齐会系统性偏前、漏译后半句。纯文本 decoder-only 对话没有第二条异质序列，提示和检索都是同质 token，拼进因果自注意力即可，不必单开一层 cross。

**深入展开：** 自注意力是 Q、K、V 同源；cross attention 是 Q 与 K/V 分属目标/源。Encoder-decoder 一层里通常先做目标侧因果自注意力（只能看已生成的译文），再 cross 到编码器记忆。源侧缓存生命周期：encode 结束即固定，不随新目标 token 追加；目标侧自注意力 KV 每步追加 1 行。计算上每步增量约 O(S_src · D)，所以源句极长时瓶颈在 S_src，需要分段编码或压缩记忆，而不是怪罪目标长度。同一公式也出现在“用一段固定条件去调制另一条序列”的场景，例如用文本特征当 K/V、用另一模态特征当 Q；条件固定则同样只编码一次。边界：把源句和目标句拼成一条序列、只做自注意力，也能做条件生成，但平方项按 (S_src+S_tgt)² 涨，且源段会挤进每一层的自注意力 cache；那是另一种实现，不能在推理期把 decoder-only 权重“打开成”cross attention，必须按训练图来。

**后续追问：** 训练时目标侧有未来泄漏、源侧却被错误地因果挡住，两种 bug 的 loss 和漏译形态有何不同；源句 4k、目标句 128 时，cross 的 FLOPs 和自注意力比谁大；若源文在对话中途被用户改写，哪些缓存必须作废。

**扩展问题：**
- 源侧 K/V 缓存和目标侧自注意力 KV cache 谁随生成步增长，谁在 encode 后冻结？
- 源序列很长时，bottleneck 在 n_q 还是 n_kv，怎样压缩源记忆？
- 解码器若还要对源文做多次修订（而不是单向查阅），还能否只用一层单向 cross？

**推理回答：** 先固定“谁在被生成、谁是只读条件”，推出 Q 跟目标步走、K/V 跟源长度走且可冻结；再用“源词是否应当全部可见”否定源侧因果 mask。纯文本没有第二源，就不为图式完整加层。验收用注意力矩阵形状 `[S_tgt, S_src]`、源缓存不随 t 变长，以及漏译是否集中在源句后半。

## ARCH-022. 怎样用一次 mask 的 A/B 对照，判断低训练损失、前言不搭后语的自回归输出是否因为泄漏了后续 token？

**答：** 最干净的对照是：同一批样本，分别用严格下三角因果 mask 和全可见 mask 跑前向，比较每个位置的 next-token 损失。若全可见时损失显著更低、生成却仍然崩，说明训练在“抄”未来 token，损失不再代表从左到右生成的质量。自回归 decoder 必须让位置 i 只能看见 ≤i，并且标签相对输入错开一位。

**深入展开：** 实现上通常在 QKᵀ 上给上三角加 −∞，softmax 后对应权重为 0。训练整段并行：输入 [t₀…t_{n−1}] 预测 [t₁…tₙ]，位置 i 的隐状态若读到 t_{i+1}，模型会走捷径，验证损失可以很低；生成时没有未来 token，捷径失效。常见泄露：mask 方向写反、shift 做错、padding 没屏蔽、多文档拼接后跨文档可见。用注意力热图确认上三角是否严格为 0，或对未来位置 embedding 求位置 i 损失的梯度——泄漏不存在时应为 0。

**后续追问：** 双向编码器为什么反而要看见两侧；padding mask 和因果 mask 叠加时谁先写入分数矩阵；多包文档拼进同一序列时，块对角 mask 和纯因果 mask 各挡住什么。

**扩展问题：**
- 画出长度 5 的因果 mask，标出位置 2 允许看到哪些 key。
- 如果只在推理时加因果 mask、训练时忘了加，线上会看到怎样的损失与生成组合？
- 如何用“对未来 token embedding 的梯度是否为零”做自动化回归？

**推理回答：** 自回归的硬约束是生成时没有未来。训练损失只有在可见范围与生成一致时才能迁移。用开关 mask 做 A/B，再查 shift 和 padding。损失低而生成差，优先怀疑泄漏，而不是先调采样温度。

## ARCH-023. 若残差变成覆盖更新，32 层深的 Transformer 会先在何处把训练打崩，梯度又如何回传？

**答：** 残差把每个子层写成 y = x + F(x)，反向时 ∂L/∂x = ∂L/∂y · (I + ∂F/∂x)，单位阵提供一条不经过注意力/FFN 的梯度通路。若改成 y = F(x)，32 层雅可比连乘，梯度范数按层指数衰减或爆炸，loss 尖峰或 NaN 通常先出现在较深的块。残差的工程含义不是“多一条连线”，而是让深层仍能收到接近 1 的梯度，并让底层表示不被每一层彻底重写。

**深入展开：** 以常见 Pre-Norm 为例，数据流是 x ← x + Attn(Norm(x))，再 x ← x + FFN(Norm(x))，残差支路是恒等，张量形状保持 [B, S, d_model]。即使子层局部雅可比的奇异值 σ < 1，恒等项仍把梯度原样下传；σ = 0.9 时 σ³² ≈ 0.03，σ = 0.7 时 σ³² ≈ 1×10⁻⁵，纯覆盖路径在 32 层已经接近断网。Post-Norm 把归一化放在相加之后，恒等通路会被 Norm 的缩放破坏，20 层以上很难训，所以当代 LLM 几乎都把 Norm 放在子层前面（LayerNorm 或 RMSNorm）。边界：若 F(x) 与 x 尺度差几个数量级，残差本身也会漂，需要零初始化残差支路或 layer scale；推理期残差只是一次逐元素加，不是延迟瓶颈。不要把残差和“把两层输出拼接再投影”混为一谈，后者切断了免费的单位增益通路。

**后续追问：** 为什么 Pre-Norm 比 Post-Norm 更能保住残差的恒等通路？给残差支路加可学习缩放是在解决什么？只靠更长的学习率预热、不加残差，32 层有没有机会稳住？

**扩展问题：**
- 残差改成 y = W[x; F(x)] 后，参数量和反向通路相对恒等残差差在哪里？
- 80 层模型里，embedding 信息主要靠残差原样上送，还是靠每层重写？
- 训练后期某层 F(x) 长期接近 0，说明该子层学到了什么，能不能剪掉？

**推理回答：** 目标是深层可训、表示可跨层复用；约束是反向传播为雅可比连乘。比较 y = F(x) 与 y = x + F(x) 的梯度公式，用 σ³² 估计 32 层后的增益，就能解释“先在深层断”以及为何 Pre-Norm 要保留干净恒等支路。用按层梯度范数曲线和首次 NaN 的层号验证。

## ARCH-024. 当 BatchNorm 打在变长 batch 上会随 pad 抖动、按位置归一化却能立刻稳住，均值和方差沿哪一维归约，逐步解码又为何不必维护跑均值？

**答：** LayerNorm 只对单个样本、单个位置的 d_model 维向量算均值和方差，再做 (x−μ)/(σ+ε)，然后乘 γ、加 β；张量 [B, T, D] 上归约的是最后一维 D，不看同 batch 其他句子，也不看同一句的其他 token。BatchNorm 沿 batch（或把 T 也卷进去）统计，pad 比例、句子长度、推理时 B=1 都会让均值方差和训练错位。LayerNorm 的统计量来自当前向量自己，训练和逐步解码同分布，所以变长语言模型用它，而不是视觉里那种要跑均值的 BatchNorm。

**深入展开：** γ、β 形状是 [D]，用来在归一化后恢复各通道的尺度和偏移，否则子层被钉在均值 0、方差 1，表达力被砍。混合精度里这一步的均值/方差常留在 FP32：D 一般是 4k 量级，半精度下很多小数量加再减均值，方差容易下溢或出 NaN。没有归一化时，残差一路累加，深层激活和梯度的尺度会按层数漂。它和 RMSNorm 的差别是：LayerNorm 先减均值再除标准差，RMSNorm 只除均方根；和 BatchNorm 的差别是统计轴。实现时务必 mask 掉 pad 再进后续损失，但 LayerNorm 本身不要把 pad 位置的值掺进别的 token——它本来就不会，这正是它适合变长序列的原因。

**后续追问：** 若有人沿 T 做归一化（同一句子所有位置共享 μ、σ），自回归解码时统计量会怎样变？γ 初始化成 1、β 成 0 之后，早期训练实际在约束什么？为什么 LN 的归约要提精度，而旁边的线性层可以留在 BF16？

**扩展问题：**
- 在 [B, T, D] 上写出 LayerNorm，并标出 pad 位置应不应进入 μ、σ。
- 去掉全部归一化去训一个几十层 decoder，损失和梯度范数通常先在哪一层失稳？
- 同一个 checkpoint 用 LayerNorm 和 RMSNorm 权重能否对换？差的是哪几个参数？

**推理回答：** 故障信号是“batch 组成一变 loss 就抖”，先问统计量依赖了哪些样本。BatchNorm 依赖同批其他序列，变长和 B=1 必然漂移；把归约轴改到 D 之后，每个位置自给自足，推理不必维护 running mean。再用 FP32 归约和 γ/β 解释数值与表达力，最后用“训练/解码统计一致”作为验收，而不是只看训练集 loss 是否还能降。

## ARCH-025. 层数逼近一百、采用后归一化时，grad-norm 会在半程失控。换成进入子层前先归一化、残差按原值加回，预热为何能压短？少乘的 Jacobian 是哪一截？

**答：** Post-Norm 写 x←Norm(x+Sublayer(x))，残差和子层输出都要再过归一化，浅层梯度被一串 Norm 的 Jacobian 连乘，深度到几十上百层就容易炸，需要很长的学习率爬坡。Pre-Norm 写 x←x+Sublayer(Norm(x))，残差支路是恒等映射，梯度可以不经过归一化直通到 embedding。少乘的就是每一层残差之后那道 Norm 的导数。现代深 decoder 多用 Pre-Norm，并在最后一层后再做一次最终归一化，因为残差流本身不再被重新缩放。

**深入展开：** 反传时 Post-Norm 的主路径是 ∂Norm/∂z · (I + ∂Sublayer/∂x)，Norm 在均值–方差约束下会压梯度；层数一多，早期 token 的 embedding 更新极不稳定。Pre-Norm 的主路径多了一条纯粹的 +1，子层梯度再叠加，对 warmup 依赖小得多。代价是残差只加不重新归一，后面层的增量相对前面层变小，同样深度下有时上限略低于调好的 Post-Norm，于是有加深残差、压低子层初始化的 DeepNorm，或子层前后都规范的 sandwich。诊断看两件事：训练前几千步梯度范数是否尖刺，以及最后一层输出 RMS 是否随深度单调胀——Pre-Norm 若省略 final norm，logits 尺度会漂，softmax 变尖或变平。不要把“能训下去”和“同深度最优”当成一回事。

**后续追问：** Post-Norm 为什么特别依赖长 warmup，而不是只把学习率整体调小？Pre-Norm 若去掉最终归一化，哪一组指标先坏（loss、梯度、还是采样重复率）？DeepNorm 和 sandwich 各自补的是稳定性还是表达力？

**扩展问题：**
- 画出两种 block 的数据流，标出反传时哪一条路是恒等、哪一条路经过 Norm。
- 若必须用 Post-Norm 训约 100 层，除了加长 warmup，初始化还要动哪些系数？
- 如何用分图层的梯度范数曲线判断失稳来自 Norm 位置而不是数据噪声？

**推理回答：** 故障是深度一大梯度炸，约束是残差必须能把浅层和输出连起来。写出两种公式后，只看反传是否经过 Norm：Post-Norm 每层多乘一段 Jacobian，Pre-Norm 残差为 I。由此推出 warmup 可以缩短，同时预见到残差流尺度失控，所以补 final norm。用梯度范数和输出 RMS 验证，而不是只比较最终 perplexity。

## ARCH-026. 学得的绝对位置向量已弃用，只靠因果 mask。两条指令互换后，模型还能否可靠察觉谁先谁后？

**答：** 能部分感知，但不能当成稳定的位置系统。双向自注意力对置换等变，但因果 mask 让后句看见前句、前句看不见后句，两句对调会改变“谁能读谁”，模型理论上仍有顺序信号。这个信号弱于显式位置：句内词序、绝对第 k 项、长度接近的两条并列指令，都容易糊。生产里选 RoPE 一类相对位置，而不是把绝对 embedding 表拉到更长，是因为相对旋转不随 `max_len` 线性增表，对超出训练长度的外推通常更可控（仍要实测，不是无限外推）。

**深入展开：** 位置信息至少有三条路径：显式绝对表或正弦表加到 embedding 上；RoPE 在 Q/K 上按位置旋转，分数依赖相对位移；ALiBi 等在注意力分数上减距离偏置；另外就是因果三角本身。只留 mask 时，对调两句（内容换位置）会改可见性方向，所以“完全无法区分顺序”不成立；但把一句内部的三个数字打乱、或问“倒数第二个 ID”，mask 提供的全局坐标不够。绝对 embedding 的硬边界是 `pos < max_len`，超过就要插值或直接报错。RoPE 把位置写进角度，训练到 4k 时偶尔能摸到更长上下文，但极端外推（例如再×8）仍会崩，需要额外的缩放技巧时要单独验证。消融时不要只看语言建模 loss，要加一条“对调两句指令、输出必须跟着变”的任务。

**后续追问：** 因果 mask 已经破坏置换等变，为什么大多数 LLM 仍要 RoPE；相对位置和绝对位置在“复制上下文里第 17 个数字”这种题上谁更稳；长度外推失败时，先观察注意力距离分布还是先看 perplexity。

**扩展问题：**
- 若训练 4k、推理 32k，绝对表插值和 RoPE 外推各自会先坏哪类现象？
- 把 RoPE 的基准频率改大或改小，短句语法和长文检索谁先敏感？
- 编码器双向模型若去掉位置编码，和 decoder-only 去掉位置编码，失败模式有何不同？

**推理回答：** 先问“没有显式位置时还剩什么不对称”，承认因果 mask 的方向性，再用必须依赖绝对下标的任务证明它不够，从而导出 RoPE 的工程动机（相对位移 + 不必扩表）。用对调/第 k 项/超长外推三组用例验收。

## ARCH-027. 绝对位置表在 4k 训、16k 推时会越界。给 Q 和 K 乘上位置相关的旋转之后，点积里还剩下什么位置信息，外推到多长会开始不稳？

**答：** 可学习绝对位置是一张最长 L_max 行的表，下标超过 4k 就没有行。RoPE 不查这张表，而是把每个头的 Q、K 按二维平面旋转角度 m·θ_i（m 为位置），使得 Q_m·K_n 只依赖相对位移 m−n 和内容，没有“第 16000 行”。相对相位在训练长度内学得稳，直接拉到约 2–4 倍有时还能算；再长则高频维转得过快、远处分数被抹平，通常要做插值或调基础频率，并补一段长上下文训练，不能只靠旋转公式硬推。

**深入展开：** 成对维度上，旋转矩阵满足 R_m⊤R_n = R_{n−m}，所以 q⊤R_m⊤R_n k = q⊤R_{n−m}k，绝对下标被消掉。频率常取 θ_i = 10000^{−2i/d}（常见底数，作示意）：低频维转得慢、承载长距离，高频维转得快、承载相邻关系。绝对位置表的失败模式是索引越界或把末行 embedding 硬套到更长位置，两者都破坏训练分布。RoPE 的失败模式不同：超过训练跨度后，本该可区分的相对距离在高频维上转过太多圈，注意力近乎均匀。工程上用位置插值、调大有效 base、分段缩放等把 16k 的相位拉回 4k 见过的范围，再在长文档上继续训练；外推半径以长上下文检索/续写是否仍对齐为准，而不是以公式是否还能算出一个数为准。

**后续追问：** 若把旋转改成加在 embedding 上的绝对向量，长度外推时哪一步先坏？ALiBi 用线性偏置编码距离，和 RoPE 比谁更不怕超长、谁对精确偏移更敏感？做 YaRN/NTK 一类缩放时，低频和高频分别该动哪一端？

**扩展问题：**
- 写出两维情形下 Q_m·K_n 如何化成只含 m−n 的形式，并指出 d_head 必须成对的原因。
- 不改权重、只改 RoPE 频率，把 4k 模型接到 16k，应先用哪类探针（相邻复制、远处复制、针状检索）判断有没有崩？
- 相对位置编码在“插入一段字”之后，后面 token 的相位要不要整段重算？KV cache 怎么办？

**推理回答：** 目标是 16k 仍能算注意力，约束是不能出现没有训练过的绝对下标。先对比“查表”和“旋转相位”两种注入方式，用 R_m⊤R_n=R_{n−m} 说明点积只剩相对位移；再按频率快慢估计直接 4 倍外推的风险，把“公式能算”和“相位还在训练分布里”分开，最后才决定要不要缩放加续训。

## ARCH-028. 边听边出的 32k 转写跑在端侧，内存几乎不许随 n 线性涨。线性循环层为什么值得认真看，标准自注意力为什么不合适？训练期会丢掉什么？

**答：** 标准自注意力让每个新位置和过去所有位置直接交互，路径长度是 1，但缓存 K、V 的显存和逐步注意力的读带宽都随序列长度 n 线性涨，32k 流式场景很容易先把内存打满。线性循环层（含状态空间形式）每步只更新一份固定大小的隐状态，推理内存近似 O(1)，更贴合“边听边出、不能存整段 KV”的约束。代价是训练时沿时间的依赖更强，长程信号要挤过固定宽度的状态，而不是一步到位。

**深入展开：** RNN 类单元按时间展开：h_t = f(h_{t−1}, x_t)，信息必须一级一级传，早期梯度容易消失，LSTM/GRU 用门控缓解但训练仍难按时间完全并行。Transformer 训练时整段并行，这是它能吃下大规模语料的关键，不是因为循环网络理论上不能做序列。线性循环 / 状态空间把 f 做成对输入的线性扫描，可用前缀扫描在训练期重新并行起来，推理仍保持常数量状态。混合块（若干注意力层 + 若干线性层）常见：局部或稀疏注意力补回精确的短距离对齐，线性层扛长上下文的记忆费用。若任务是离线、批量、显存充足的训练，标准注意力仍然更简单、生态更熟。

**后续追问：** 为什么循环结构本身不需要另加位置编码，而自注意力通常需要？固定宽度状态在 32k 处最先丢掉的是哪类信息？训练期的前缀扫描和推理期的逐步状态更新如何对齐？若必须在边缘上保留少量注意力层，你会把它们放在浅层还是深层？

**扩展问题：**
- 对 32k 输入，对比“全量 KV cache”和“常数量隐状态”的内存随长度怎么走，并指出常数里还藏着哪些项（层数、头数、状态维）。
- 自回归生成即使在 Transformer 里也是串行的，这一点和 RNN 的串行训练是不是同一件事？
- 哪些产品约束（电池、最长会话、是否允许丢弃早期音频）会让你改回滑动窗口注意力，而不是上线性循环？

**推理回答：** 目标是流式 32k，约束是内存几乎不随 n 涨。标准注意力的 KV 增长直接撞上这条约束；固定状态的循环层满足内存，但把长程交互变成“能否写进状态”。训练并行度是第二约束：只有能在训练期重新并行的线性扫描，才值得在现代堆栈里认真选型。

## ARCH-029. 若逐步生成时每一步都把完整提示重新算一遍，该缓存哪些张量、形状是什么？修好之后注意力计算量大约能少几倍？

**答：** Prefill 一次吃完整提示，形状 `[B, S, D]`，每层算出该层全部位置的 K、V，写入缓存，形状约为 `[B, H_kv, S, Dh]`。之后每个 decode 步只输入新 token，得到 `q_len=1` 的 Q，对已缓存的 K、V 做注意力，再把这一步的 k、v 追加到缓存末尾；FFN 也只跑这一个位置。若每步把长度为 `S+t` 的整段再做一次全序列自注意力，注意力分数从“1 条 query × 当前长度”退化成“当前长度²”。以约 2k 提示再写 128 个新 token 为例，仅注意力分数这一项，改正后大约少两到三个数量级（约两千倍，随当前长度线性变），FFN 也会从每步 O(S) 降到 O(1)。

**深入展开：** 一层里注意力内部常是 `Q,K,V` 按头拆成 `[B, H, q_len, Dh]`；正确 decode 时 `q_len=1`，`k_len=S+t`，分数 `[B, H, 1, S+t]`。错误实现相当于每步 `q_len=k_len=S+t`。数量级：设 S=2048、T=128，错误做法每步代价 ~ (2048+i)²，128 步合计约 10⁸ 量级次点积位置；正确做法每步 ~(2048+i)，合计约 10⁵ 量级，比值约等于平均序列长度（两千左右）。这还没算投影：错误实现每步对 S 个 token 做 QKV 投影，正确实现只投 1 个。训练时的一次前向更像 prefill：所有位置同时出 logits `[B, S, V]`，用错开一位的交叉熵；不要把训练图和 decode 图画成同一个。现代块常见顺序：RMSNorm → 因果注意力 → 残差 → RMSNorm → SwiGLU FFN → 残差，最后再归一化后乘 LM head，只取最后一个位置采样。

**后续追问：** GQA 下缓存的是按 `H_kv` 还是按 `H` 存，复用时怎样把 K、V 广播到查询头；prefill 的二次项和 decode 的读带宽，哪个先把 2k→8k 打爆；怎样用一个最小实现核对每层输入输出都是 `[B, seq, D]`。

**扩展问题：**
- 把 Pre-Norm 换成 Post-Norm，前向数据流和深层训练稳定会差在哪？
- 只缓存 K、V 而不缓存注意力输出，是因为哪一步必须用到当前 Q？
- 提示不变、用户只追加一句时，哪些层的缓存能增量扩展，哪些必须整段作废？

**推理回答：** 先写清每步“新信息只有 1 个 token”，推出只需追加 K/V、Q 不能按全序列重算；再用 O(n²) vs O(n) 对 2k+128 做同一套求和，得到约 n 倍的差距。用开关 cache 的 logits 逐 token 对比做验收。

## ARCH-030. 从网关接到会触发工具调用的用户消息，到终答流式出来，不可省略的环节有哪些、最容易把时延打爆的两处等待在哪？

**答：** 不可省略的大致是：鉴权与配额、把系统指令/历史/工具 schema 装配成一次请求、输入安全、路由到具体模型、用该模型的 tokenizer 切分、prefill、解码并流式吐 token、解析工具调用、在沙箱执行、把结果追加后再推理、输出过滤与审计计费。首 token 延迟（TTFT）最容易死在排队和超长历史的 prefill；工具往返最容易死在外部 API 等待，以及第二次把变长上下文再 prefill 一遍。工具循环是“模型选工具 → 平台执行 → 模型读结果 → 继续写”，不是单次前向就能结束。

**深入展开：** Prefill 对整段提示并行算注意力并写入 KV，计算量随提示长度近似二次增长，常是计算受限；decode 每步只进 1 个新 token、反复读 KV，常是显存带宽受限。流式响应在第一个 decode 步之后就可以把 token 推给客户端，所以 TTFT ≈ 排队 + 分词 + prefill + 首步 decode，不要和整段生成时间混为一谈。工具调用还要做 JSON/schema 校验、超时、重试和权限；失败必须能回灌给模型或降级，而不是悬挂。生产上一次用户回车可能穿过网关、策略服务、推理引擎、工具 worker 共 1–4 个额外跳。若历史被原样拼进每次请求且不做截断/摘要，prefill 会随轮次线性变长、注意力二次变贵。

**后续追问：** 工具结果很大时，是摘要后回灌还是整段回灌，对第二次 prefill 和计费差多少；输出过滤器应该拦在流式中途还是整段结束，各影响什么体验；如何用 trace 把 TTFT 拆成排队、prefill、首 token、工具 RTT 四段。

**扩展问题：**
- 同一用户连发两条消息时，KV cache 在哪些条件能复用、哪些条件必须作废？
- 工具 schema 放进系统提示会吃掉多少上下文，怎样按权限裁剪可见工具？
- 模型发出格式错误的工具调用时，重试、补全还是直接失败，你怎么选？

**推理回答：** 按“一次用户可见回合”把控制流画成带工具环的状态机，标出同步等待点；延迟优化只打在最长的等待（排队/prefill/外部 RTT），而不是先微优化采样循环。用分段 trace 和超时预算验证，而不是只看端到端平均值。

## ARCH-031. 组内键值取平均之后，32 路查询的 MHA 检查点能不能立刻按 8 组共用 KV 当 GQA 开服？还要再训多久质量才回来？收到单个 KV 头时哪类任务先掉点，按头做张量并行会卡在哪？

**答：** 把 32 个 KV 头按 4 个一组做均值（或一次 1×1 混合）可以得到合法的 8 头 K/V 形状，查询投影和输出投影却仍按当初 32 套独立键空间来的，q_h·k_h 立刻变成 q_h·k_{组(h)}，softmax 和加权 V 都对不上，能跑但不数值等价。必须再做一段续训（常冻结大部分层、用较小学习率改 Q/O 与新的 KV），让查询重新对准共享键；只改权重就上线，短文下一 token 损失会跳，长距复制更先崩。收到 8 组通常比收到 1 组（MQA）更能保住指代和“大海捞针”式检索；MQA 带宽更省，但 1 个 KV 头在按头切的张量并行里很难均分到 8 卡，只能复制或改切隐藏维，通信模式跟着变。

**深入展开：** 形状上 W_K、W_V 从 `[D, 32·d_h]` 收成 `[D, 8·d_h]`：先 view 成 `[D, 8, 4, d_h]` 再对大小 4 的那一维取平均。推理时 KV 头下标是 `h_q // 4`，核内广播或按组索引，不改变查询头宽度。续训要补的是“查询与共享键的对应”，不是再学一套语言建模先验；上下文长度先保持原训练窗，数据用原预训练/指令混合即可，步数从几千到数万量级按验证损失回头，而不是按某个发布配方抄。质量阶梯大致是满头 ≥ 分组 ≫ 单 KV 头：多头本来用来并行抓不同对齐，8 套键还留了一部分分工，1 套键则所有查询抢同一空间，罕见 span 复制、多实体指代、超长检索先掉。张量并行按头切时，32 个 KV 头可以整除很多并行度；8 个 KV 头在并行度 8 时尚能一人一头，再往上或收到 1 头就必须复制 K/V 再 all-gather，或改成沿序列/隐藏维切。不要把“形状能 load”当成“行为等于分组注意力训出来的模型”。

**后续追问：** 组内是均值、只留第一头、还是学一个 4→1 的混合，三种初始化对续训步数差在哪；零续训时先坏的是短文交叉熵还是针状检索；服务端已经按 TP=8 切头，为什么即使带宽还想再降，也未必敢收到 MQA。

**扩展问题：**
- 写出 W_K 从 `[D, 32·d_h]` 到 `[D, 8·d_h]` 的 reshape+mean，并给出查询头 h 到 KV 头的映射。

**推理回答：** 目标是少存 KV，约束是手头只有满头 checkpoint、且上线后还要按头做张量并行。先承认均值池化只解决形状，Q–K 配对是训出来的对应关系，必须续训才能恢复；再按“还留几套独立键”比较 8 组与 1 组会伤哪类对齐；最后用 H_kv 能否整除并行度决定能不能一路收到 MQA。验收看续训前后的针状检索和指代，以及各 rank 上 KV 头数是否为整数。

## ARCH-032. 开头若干 token 一旦滑出窗口，困惑度就飙升——流式 decode 只缓存最近 4k 的 KV。把这些位置永久钉住，数值稳定性为何能回来？

**答：** Softmax 强制每个 query 的注意力权重加起来为 1。预训练时模型学会：当前步若没有特别要看的内容，就把多余质量倒在因果掩码下始终可见的开头几个 token 上，这些位置变成注意力的蓄水池。只留最近窗口时，蓄水池被环缓冲挤出，质量无处安放，分布塌缩，困惑度上升。把开头少数 sink 的 KV 永久保留、再加上最近 W 个，数值稳定性会回来；被挤掉的中间段落仍然不可读，这不是把有效上下文变长了。

**深入展开：** 开头容易成为 sink，是因为从训练第一步起 BOS/首 token 对所有后续位置都可见，模型把它们当“默认槽”。流式缓存于是拆成两段：固定前缀（例如只留 4 个 sink，数量作示意）+ 最近 W 的滑动段，中间历史丢弃。另一种做法是在 softmax 分母里加可学习的 sink logit，让权重之和可以小于 1，推理时甚至不必真留那几个 token。边界很清楚：sink 修的是“分布是否合法”，不修“窗口外事实还在不在”。用注意力热力图看，正常情况下前几列会偏深；sink 被驱逐后热力乱飘，下一 token 的熵升高。不要把“能无限生成”理解成“能记住整场对话”。

**后续追问：** 为什么是序列开头而不是窗口中间的某个位置更容易成为 sink？可学习 sink logit 和永久保留首 token，对 KV 体积和实现复杂度各有什么代价？若 sink 和最近窗口在位置编号上不连续，RoPE 的相位要不要重映射？

**扩展问题：**
- 只保留最近窗口、故意丢掉 BOS，生成曲线上应先看到哪类异常（重复、乱码、还是突然跑题）？
- 把 sink 从 1 个加到十几二十个，稳定性和“浪费掉的注意力质量”怎么权衡？
- 如何用逐层注意力可视化确认某个头是否依赖 sink，而不是依赖最近的语义 token？

**推理回答：** 约束来自 softmax 归一化：质量必须有地方去。先解释训练为何把默认槽放到开头，再对比“窗口滑走后槽没了”和“把槽钉住”两种缓存布局，最后划清“生成不崩”和“中间内容仍在”的界限。验证应看长度–困惑度曲线是否在驱逐 BOS 时出现拐点，而不是只看能不能继续吐 token。

## ARCH-033. 正向激活掉一半、反向变慢且峰值显存回升，发生在打开 FlashAttention 之后。tiled 核在反传里重算哪张矩阵，多短的序列会亏？

**答：** 分块注意力故意不保存 n×n 的分数矩阵 S 和 softmax 权重 P，正向只留下 Q、K、V、输出 O，以及每行的最大值与 exp 累加（或等价的 logsumexp）。反向要用 P 才能算 dV=PᵀdO、以及 softmax 的雅可比，所以每个 SRAM 块里必须从 Q、K 重算 S_ij，再用保存的行统计量还原 P_ij，然后才往 dQ/dK/dV 上累加。省掉的是 O(n²) 激活，买来的是大约再做一遍注意力量级的 GEMM；序列只有几百、n×n 本来就进得了片上缓存时，分块启动和重算会比“物化再反传”更慢，峰值也可能因为同时活着的 dO、O、重算缓冲而回升。

**深入展开：** 注意力反向有一组常用恒等式：dP_ij = dO_i·V_j，而行归约 D_i = Σ_j P_ij dP_ij 恰好等于 dO_i·O_i，于是 dS_ij = P_ij((dO_i·V_j) − (dO_i·O_i))，再 dQ=dSK、dK=dSᵀQ、dV=PᵀdO。没有 P 就写不出这些式子，所以融合核按正向同样的 (B_r, B_c) 切块，片上重放 S_ij=Q_i K_jᵀ，P_ij=exp(S_ij−m_i)/ℓ_i。因果 mask、padding、dropout 必须和正向用同一套块内规则；dropout 还要保存或重放 RNG，否则 P 对不上。数值上这与“先物化再反传”只在浮点结合律上有 ulp 级差别，不改变 Θ(n²d) 算术量。划不来的区间很具体：例如 n=256、头维度 64、FP16，单头 S 只有约 128 KiB，L2 就能装下，重算和间接寻址的固定开销会压过省下的 HBM；decode 的 q_len=1 时本来就没有大激活，应走另一类 decode 核而不是训练用的分块正向/反向；头维度大到一块 SRAM 只能塞 1～2 行 query 时，占用率掉、重算次数变多，墙钟也会难看。若外层已经对整个注意力做了激活重计算，内核再重算一遍 P，会变成双重重算，应只留一层。

**后续追问：** 为什么反向必须同时留下 O 和行统计量，而不能只留 Q、K、V；因果 mask 写在块循环里和写在物化 S 上，漏掉一块会怎样静默错位；已经用选择重计算包住整层时，还要不要让注意力核自己再重算 P。

**扩展问题：**
- 画出一个反向块在 SRAM 里同时活着的张量：Q_i、K_j、V_j、O_i、dO_i 以及 dQ/dK/dV 的累加器，并标出谁必须写回 HBM。
- 同一 batch、同一头数，n=512 与 n=8192 各更可能输给朴素“物化 S”路径，还是赢在 HBM；瓶颈分别是启动开销还是 n² 激活。
- dropout 注意力若正向扔了 mask 位图，反向重算时怎样保证同一位置被置零，代价记在显存还是记在重放 RNG？

**推理回答：** 目标是正向不物化 n×n 激活、反向仍要得到与 softmax 雅可比一致的 dQ/dK/dV。约束是 dS、dV 都显式依赖 P，所以只保存能还原 P 的行统计量和 O，在块内重算 S/P。再用“n² 张量是否本来就装得下”判断重算是否亏：短序列或 q_len=1 时省下的流量接近零，只剩切块开销。验收看反向峰值里是否还出现 [n,n] 工作区，以及短/长两条曲线的墙钟谁先交叉。

## ARCH-035. decode 一步里，总参 400B、激活约 50B 的稀疏模型为何常常慢于同样激活 50B 的稠密模型？

**答：** Decode 一步通常受显存带宽限制：要把这一步用到的权重和 KV 读进计算核。50B 稠密模型每步读约 50B 连续参数；例如总参 400B、激活约 50B 的 MoE，纸面算力相近，但仍要把选中专家从分散地址聚起来，并做跨设备 all-to-all。小 batch 时通信占比高，空闲专家所在设备还在同步等待，墙钟延迟常高于内核更熟、无需路由的 50B 稠密模型。

**深入展开：** 稠密：每层两三个大 GEMM，形状规整，利用率高，延迟随 batch 平滑。MoE：路由是离散选择，同一步不同 token 走不同专家，大核被切成若干小核；为放下 400B 权重必须做专家并行或卸载，前者加通信，后者加主机总线往返。两边的注意力仍是稠密的，KV cache 可以同量级，稀疏并不自动省 cache。适用边界：大 batch 的训练或 prefill 更偏算力墙，稀疏用相近 FLOPs 换更大容量往往划算；在线 decode、batch 小、延迟 SLA 紧时，稠密更可控。若 decode batch 能做大、专家局部性好、互连够肥，MoE 可以追平甚至超过同激活稠密模型——这是条件，不是默认。不要把“稀疏”理解成“权重少读就一定更快”。

**后续追问：** Prefill 阶段 MoE 相对稠密的优劣，和 decode 有何不同？专家卸载到 CPU 后，冷专家被命中时延迟长什么样？同等质量下，你用哪几个指标决定上 50B 稠密还是 400B 级 MoE？

**扩展问题：**
- 画出 decode batch 从 1 到 64 时，MoE 与稠密模型 tokens/s 的交叉区间。
- 若稀疏来自权重剪枝而不是专家路由，decode 还会不会吃通信亏？
- 多租户下请求长度和领域混杂，为什么会加重 MoE 负载不均？

**推理回答：** 目标是低 decode 延迟，约束是带宽、通信和内核效率，不是纸面 FLOPs。比较“读 50B 连续权重”和“路由 + 分散读专家 + 同步”。用 batch = 1 的每 token 时延和通信时间线验证 MoE 是否真更慢。

## ARCH-036. 合同长约 20k token，滑动窗口宽度取 4096。第 4 层和第 32 层的理论感受野分别多长，KV 缓存能降到全量的几分之几？

**答：** 滑动窗口注意力规定位置 i 只和 [i−W+1, i] 做点积，单层复杂度是 O(n·W) 而不是 O(n²)，KV 用环形缓冲只保留最近 W 个位置。信息可以沿层接力：第 ℓ 层的理论感受野大约是 ℓ·W，所以例如 W=4096 时第 4 层约 1.6 万 token、第 32 层约 13 万 token，2 万 token 的合同在深层“纸面够得着”。接力是层层加权混合，不是把远处原句拷过来，免责条款的精确检索仍常失败；KV 则从按 n 缓存降到按 W 缓存，n=2 万、W=4096 时大约只留全量的五分之一。

**深入展开：** 实现上每层维护长度 W 的 K/V 环：新 token 写入 `head % W`，过期位置直接覆盖，不必搬移整段缓存。注意力 FLOPs 大致按 n·W·d 而不是 n²·d 涨，显存按 2×层数×KV 头数×head_dim×序列×字节数估算——例如 32 层、32 头、head_dim=128、FP16 时，全注意力 2 万 token 的 KV 约数 GB 量级，换成 W=4096 可按 W/n 同比缩小。多层感受野 ℓ·W 只保证“有一条依赖路径”，中间层的 softmax 会把远处信号摊薄，所以针状取证（原文数字、除外条款）在窗口外会断。工程上常把滑动层和少量全局层交替，或永久钉住开头几个 sink token：全局层负责目录/标题，窗口层负责局部措辞；不要把理论感受野当成有效检索半径。

**后续追问：** 滑动窗口和分块稀疏、线性注意力在“谁能看见谁”和 KV 布局上差在哪？为什么只靠加层扩大感受野不够，还要插全局层？窗口滑走后若不同时留 sink，注意力分布会怎样坏掉？W 从 1k 加到 8k 时，质量、显存、decode 延迟各自怎么走？

**扩展问题：**
- 给定层数 L、窗口 W 和要定位的 token 距离 Δ，怎样判断“理论够得着”但“取证会失败”？
- 环形 KV 和 attention sink 一起用时，缓存里哪几段是固定的、哪几段在覆盖？
- 若任务是全文对照两条款是否矛盾，滑动窗口要怎样和检索/全局层分工，而不是单纯加大 W？

**推理回答：** 目标是控 KV 显存，约束是远处条款还要能被引用。先从“每层只看 W”写出复杂度与缓存从 n 降到 W，再按层叠推出感受野 ℓ·W，用 2 万对 1.6 万/13 万判断哪一层纸面够得着；然后用“混合≠拷贝”把理论半径和有效检索分开，最后用 W/n 估算省下的 KV。若验收是原文级对上，就不要只报感受野数字。

## ARCH-037. decoder-only 要同时吃商品图和「这双鞋是什么底」。patch 拼进同一条自注意力，对比借助 cross-attention 把图侧特征送进去，两者在 KV 开销与定位上差在哪里？

**答：** 两条路都能用，缓存和交互不同。拼进同一条因果自注意力：视觉编码器或线性投影把图块变成视觉 token，和文字一起算注意力，实现简单，但每个视觉 token 都要占 KV，分辨率一高，prefill 和缓存线性变贵。Cross-attention：语言模型的 Q 去读图像侧的 K/V，图侧算一次即可在每个解码步复用，不占文本序列的长度配额，但对齐更重，能否指到「鞋底」取决于图像分辨率和 cross-attention 是否够密。

**深入展开：** 视觉 Transformer 把图切成规则图块（例如 16×16 像素一块），加位置编码后当序列；接到聊天模型时，还要用投影或压缩模块把这些特征对到语言模型隐空间。早期融合让文字 token 直接看见每个图块，对「指着局部问材质」更直观，但例如几百到上千个视觉 token 会吃掉上下文窗口。Cross-attention 把图像当作另一条源序列，注意力矩阵形状是 [文本长度, 视觉长度]，源侧 K/V 可缓存。无论哪条路，模型学的是图块和文本的共现，不是人类意义上的看见；小字 OCR、细腻材质、少见光照仍常失败。评测要用能指向局部的图文题，而不是只问「图里有没有鞋」。

**后续追问：** 提高输入分辨率时，拼接方案的 KV 增长和 cross-attention 差多少？把视觉 token 压到几十个会丢掉什么空间细节？纯文本轮次还要不要保留空的视觉占位？

**扩展问题：**
- 估算边长约 336、patch 边长 14 时大约有多少视觉 token，以及它占 4K 窗口的比例。
- 用户说「左下角那块」时，两种融合方式各自怎样把空间坐标送进模型？
- 视觉 token 与「再裁一块高清图」的工具调用如何分工？

**推理回答：** 从窗口和 KV 预算出发，决定养得起多少视觉 token；从是否要细粒度定位出发，决定要不要高分辨率或二次裁剪。拼接实现快、占窗口；cross-attention 省序列长度、实现复杂。用定位题和首 token 延迟、KV 占用一起选，而不是抽象比较谁更「理解图像」。

## ARCH-038. 这份 MoE 专家数 8、每 token 只走 top-2，总参数可以涨数倍，但 FLOPs 不按同倍涨，服务延迟却可能更差。这两段反差怎么解释？

**答：** MoE 通常只把 FFN 换成 E 个专家，注意力仍全体共享；top-2 表示每个 token 只跑 2 个专家 FFN。相对“同宽度、单 FFN”的稠密块，FFN 参数约 ×8，整模型总参常见到约 4–6 倍（注意力不复制），而 FFN 浮点运算只约 ×2，再摊上注意力后每 token FLOPs 只高一截。线上变慢多半不是纸面 FLOPs，而是热专家过载、把 token 运到持有专家的卡的 all-to-all、以及小 batch 下专家 GEMM 被切碎。

**深入展开：** 数据流：hidden → 路由器对 E 维打分 → 选出 top-k 及门控权重 → token 发往对应专家 → 加权求和写回。容量因子 > 1 允许专家多接一些 token，超出则丢弃或溢出，丢弃直接伤质量。负载均衡用辅助损失惩罚专家频率方差，或给路由 logits 加可学习偏置，避免“热的更热”。专家并行时一次前向至少一次 all-to-all，延迟跟被路由 token 数和跨节点带宽有关；decode batch = 1 时 8 个专家只用 2 个，其余设备空转，理论算力优势被同步等待吃掉。边界：总参数决定显存（专家默认都要驻留），激活参数决定 FLOPs；不能把“总参百 B、激活数十 B”的延迟按数十 B 稠密模型去估。训练还要防专家崩塌——少数专家吃掉几乎全部 token 后，容量退化成一个略宽的稠密 FFN。

**后续追问：** token 选专家和专家选 token 两种路由，负载形态有何不同？decode batch = 1 时 MoE 为什么特别亏？不用辅助损失怎么做均衡？

**扩展问题：**
- 把 top-2 改成 top-1，算力、质量和专家崩塌风险各怎么变？
- 同一 hidden 进两个专家再加权，和把稠密 FFN 加宽一倍相比，表达力差在哪？
- 如何监控每个专家的 token 占比，并设告警阈值？

**推理回答：** 先拆总参数、激活参数、通信、均衡四笔账。用 E = 8、k = 2 代入，得到参数涨数倍、FFN FLOPs 约 ×2 的直觉，再解释 all-to-all 和空转如何拉高墙钟时间。用专家负载直方图和通信耗时占比验证。

## ARCH-039. 上下文从 8K 加到 100K 量级时，一套在线 MoE 服务若仍用稠密注意力，先见底的是算力还是 KV 缓存？各层搭配不同压缩方式能缓解哪一头？

**答：** Prefill 全注意力的浮点运算按长度二次涨，8K → 100K 大约是 (100/8)² ≈ 156 倍的注意力计算；KV cache 按长度线性涨，大约 12.5 倍。窗口只有几 K 时，常常先感到 KV 把并发挤掉；到 10 万级，prefill 墙钟和 KV 会一起爆。MoE 稀疏的是 FFN 激活量，救不了这两项。层间混合的做法是：一部分层做窗口或按块检索的稀疏注意力（压 KV 条目和点积次数），一部分层做压缩后的稠密全局混合，并保留开头 sink 与最近窗口，避免远距离精度被砍光。

**深入展开：** 标准多头/分组注意力：每层每 token 存一份 K、V，对全部历史做点积。按 40 层、8 个 KV 头、d_h = 128、BF16 估算，每 token 约 160 KiB，100K 约 16 GiB/序列，再乘并发就不现实；prefill 里注意力项约 L·n_q·n²·d_h，n 放大 12.5 倍则平方项放大约 156 倍，FFN 只线性放大 12.5 倍，长上下文时注意力重新主导。架构侧手段（通常要在训练时就位）：①滑动窗口，KV 只留 W，计算 O(nW)；②块稀疏或压缩索引，把每 m 个 token 收成可检索条目，轻量打分后只对 top-k 块做注意力；③潜变量 KV，缓存低维隐向量，用时再展开，体积按隐维降；④层间交替，避免每一层都付满 n²。边界：没被选中的 token 会丢，精确“到 80K 处找一句话”会降级；只靠堆层扩大感受野，远距离仍是间接传递。MoE 路由按 token 选 FFN，和注意力压缩正交。

**后续追问：** 为什么 FFN 的专家稀疏救不了 KV？滑动窗口堆 40 层后理论感受野是多少，为什么实际检索仍差？潜变量 KV 和分组注意力减少的是同一维吗？

**扩展问题：**
- 只在偶数层做全注意力、奇数层做窗口，KV 和远距离精度大概怎么折中？
- 100K prefill 必须在 10 秒内结束时，你更该砍 n² 项还是砍专家 FFN？
- 如何用“精确查找”和“全局摘要”两组任务分别验收稀疏层有没有砍过头？

**推理回答：** 把 8K → 100K 的放大系数分别套到 O(n²) 注意力和 O(n) 的 KV/FFN 上，定位先爆谁。MoE 只稀疏 FFN，所以必须改注意力结构。按“保全局 / 保局部 / 保 sink”分配层类型，再用查找型和摘要型任务成对验收。

## ARCH-040. 推理型模型在多步演算上写中间步骤，延迟会高出一个数量级（相对普通指令模型）。哪些任务值得投入测试时计算，思考额度该怎样封顶？

**答：** 值得花的是中间步骤可验证、错一次代价高的任务：多步计算、必须过测试的代码、多约束规划。这类模型在后训练里就被可验证奖励推着写出可检查的长推理，推理时用更多 token 换正确率，也就是测试时计算。寒暄、闭集分类、检索里已有现成事实的问题不该走这条路，否则又慢又贵，还可能绕远。用最大思考 token、超时或档位封顶，并按难度路由：低难度走普通指令模型。

**深入展开：** 提示里写「请一步步想」只改输出格式；推理型模型把「先想后答」写进训练目标，用答案对错、测试是否通过等信号学习自检和换路。代价是输出从几十个 token 变成成百上千，用户等待大致随思考长度增长。简单题上可能过度展开；写出的思维过程是生成文本，不一定忠实反映内部计算，直接展示给用户有误导和泄露风险。工程上应记录思考 token 数与对错，画正确率对成本的曲线，找到收益递减的拐点。评估按难度分桶，避免被简单题的平均分掩盖。

**后续追问：** 只靠提示做逐步思考，和专门训练的推理模型，失败模式有何不同？思考 token 若单独计量，产品上怎样对用户解释等待？预算用尽时，是截断思考硬答，还是失败并重试？

**扩展问题：**
- 如何为客服工单定义升级到推理模型的规则，避免把查运单号也送去长思考？
- 思维过程可以给质检看、不宜直接给终端用户看的理由分别是什么？
- 怎样判断继续增加思考 token 已经进入收益递减？

**推理回答：** 约束是延迟和单价，目标是难例正确率。先问对错能否自动验证、失败代价是否高；两个条件都满足才配测试时计算。用路由和硬预算防止所有请求都深度思考。用分桶正确率和该类请求占总成本的比例验收。

## ARCH-041. 函数中段空缺，前后都已写好。逐步把掩码揭开，为何可能比自回归往下写更省事？长度预估一旦偏了，收场办法是什么？

**答：** 从左到右的生成默认只能在末尾接龙；要填中间，通常得拿掉后缀再重写，或专门训“前缀-后缀-中间”格式。掩码扩散把每个输出位置看成可并行去噪的槽位：已知 token 保持不动，未知位置从掩码出发，每步同时预测所有掩码位，留下高置信结果，对其余位置继续去噪。左右上下文作为同一条序列上的条件，不必先破坏后缀。

**深入展开：** 前向过程逐步把离散 token 换成掩码（或转入吸收态），反向模型学的是“在当前部分可见序列下，被掩码位是什么”。推理步数 T 是独立旋钮：T 小则快而粗，T 大则反复精修，这和自回归“步数等于输出长度”不同。代价是必须先给定或估计长度 L，把序列画成 L 个槽再去噪；L 太短会截断，太长会填进空洞或结束符。工程上可先用启发式或小模型估 L，或并行几条不同长度再打分。逐步追加的 KV cache 不好直接搬，因为每步改的是整段而不是一个新位置。长程一致性和多步推理上，这类模型整体仍不如成熟的自回归工具链。一次性掩码填空只做一步、不迭代生成整段，不能和这套去噪循环混为一谈。

**后续追问：** 怎样画步数-质量曲线，并在服务延迟预算下选 T？为什么低置信位置要留到后面再揭开？长度能否做成可变的吸收过程，而不是预先固定？代码补全里的缩进和括号平衡，怎样变成去噪时的硬约束？

**扩展问题：**
- 比较“前缀-后缀-中间”的自回归填空和掩码扩散填空：实现复杂度和缓存利用率差在哪。
- 用户事后只改了中间三行，扩散模型能否只对这三行再去噪？自回归要怎么做才等价？
- 训练时对所有掩码位做独立预测，还是建模它们的联合，对重复 token 和全局一致性各有什么影响？

**推理回答：** 任务的已知集是两边都在的上下文，未知集是中间一段。能对任意位置子集并行揭开的过程，正好匹配这个划分；严格从左到右会把已经写好的后缀错当成未知。离散槽位的长度是额外自由度，必须单独估计或搜索。

## ARCH-042. 128k 的窗口接不住约 2M token 的仓库，题目还是安全审计。为什么不先切块做检索，而让模型写探查代码、按需去读文件？

**答：** 固定分块加检索先假定你知道审计线索会落在哪些片段；“这把密钥谁在用、顺着数据流再往下追”这种多跳问题，嵌入召回很容易断链。递归式用法把整仓留在环境里（文件树、只读读文件 API），主模型只拿到短指令和几个原语：列目录、读一段、再拉起子调用。它按问题自己决定切哪里、对每片问什么，子结果回收后再汇总，子调用还可以继续往下切。

**深入展开：** 要同时躲开三件事：窗口硬上限、超长上下文中间段落被忽略、以及把整仓塞进提示的费用。和普通工具调用是亲戚——都是模型选动作、环境执行——差别在于原始仓库默认不进注意力，必须“看见”一块才花钱。和检索的差别是探索策略在生成时决定，而不是建索引时定死。代价是一次用户问题可能打出几十次模型调用，延迟和账单上升；子调用的错误会向上汇总；探查代码必须在只读、禁网、有超时和调用次数上限的沙箱里跑。单文件、远小于窗口的问题不值得上这套，直接放进上下文更便宜。覆盖率要当作一等输出：没读到的目录必须声明，不能假装审完。

**后续追问：** 递归深度和总 token 预算怎样封顶才不会账单爆炸？子调用返回明显矛盾时，主模型靠什么发现？仓库里若有密钥文件，沙箱和提示要如何隔离？这和先做一层 map-reduce 摘要再回答有何不同？

**扩展问题：**
- 给系统设计硬限制：最大子调用次数、每层最多读入字符、总墙钟时间；超限时如何降级成“只报告已看见的部分并给出覆盖率”。
- 在“跨三十个文件对比两个协议实现”上，按需探查和预先建调用图各会漏掉什么？
- 如何记录每次子调用的输入输出，以便事后复盘漏检路径？

**推理回答：** 约束是不能把两百万 token 一次性放进注意力，目标是按问题动态分配阅读预算。最小机制就是：控制面留在提示里，数据面留在环境里，用递归子调用把阅读变成按需 I/O。没有覆盖率输出，系统会系统性低估自己没看见的部分。

## ARCH-043. 闭集 20 类工单路由，什么情况下该用分类器给固定标签打分，而不是让生成式模型吐类名？校准后的概率如何决定自动处理或交人工？

**答：** 当输出必须落在闭集、需要稳定延迟和可设阈值的置信度时，用分类器对固定标签打分，比让生成模型自由写出类名更合适：不会出现拼错的类名或额外解释，一次前向即可，概率也能单独校准。生成模型留给还要写回复或做开放推理的步骤。自动处理只在校准后的最大类概率超过你在验证集上标定的阈值、且不属于高风险类时执行，否则转人工或升级到生成模型。

**深入展开：** 让模型生成类别名的典型故障是别称、多余标点、偶发拒答，后面还得再写解析；采样开启时同一张单还可能抖到邻类。闭集分类头在固定维 logits 上做 softmax，解析成本为零，但永远可能选错类——格式不出错不等于类别正确。校准（例如温度缩放，并用可靠性图、校准误差检查）决定阈值有没有业务含义：模型说 0.9 时大约 90% 正确，才能写「超过 θ 自动关单」。分类器不写理由，也处理不了训练时不存在的新类，新业务线要扩标签并重评。常见接法是分类器做路由和护栏，生成模型只在需要写文本时启动。评估看闭集准确率、校准误差、p95 延迟，以及生成式基线的解析失败率（通常不是零）。

**后续追问：** 为什么要求「输出 JSON」仍然会出现类型失败，而闭集分类头不会？未校准的 0.99 有什么危险？出现第 21 个新类时，继续用旧分类器会怎样？

**扩展问题：**
- 在验证集上画可靠性图，说明你如何选出自动关单的阈值。
- 哪些任务不适合闭集分类头（必须引用原文、必须多步工具、标签事先未知）？
- 分类器与生成模型级联时，如何避免两套模型对「紧急」的定义不一致？

**推理回答：** 先看输出契约：是闭集决策还是开放文本。闭集、要阈值、要稳定延迟，就该用打分模型；需要写句子再请生成模型。阈值必须来自校准后的概率，否则自动化没有可靠的覆盖与风险权衡。用校准误差、误关单率和延迟一起验收。

## ARCH-044. 意图分类日调用量约五百万，全部送进 70B 会贵且慢。第一跳小模型该选多大参数量，哪些在线信号出现才把流量交给大模型？

**答：** 意图分类、槽位抽取、安全初筛这类闭集决策，通常几亿到大约十亿参数、针对本任务微调的小模型就能先接住，因为标签空间有限，并不需要大模型的开放生成。先用自己的业务评测集比质量、p95 延迟和单次成本，不要用通用聊天榜。升级条件写成事先约定的不确定度：分类熵高、槽位校验失败、用户连续改口，或命中高风险意图，再把原文交给大模型，而不是随机抽成。

**深入展开：** 「小」没有法定阈值，实践中常指能在单张消费级加速器或端侧芯片上以数十到一两百毫秒跑完的模型，参数大致从几亿到十几亿；也有团队把 7B 级仍当小模型用。它们靠更干净的数据、蒸馏和更长训练，在窄任务上逼近大模型，但世界知识、多步推理和长尾说法弱。系统做成级联：高置信请求由小模型直接返回，其余升级。端侧还要量化、选对运行时，并保证词表覆盖任务语言。评估必须含长尾意图和对抗改写，避免只在高频类上看起来已经够用。具体覆盖多少流量，以你在验证集上标定的阈值曲线为准，而不是套一个固定百分比。

**后续追问：** 小模型的概率怎样校准才能拿来做升级阈值？蒸馏会不会把教师的误拒一并学走？什么时候应该继续增大小模型，而不是永远级联？

**扩展问题：**
- 设计「小模型先判、低置信升级」的路由，列出你要落盘的四类日志字段。
- 端侧 4-bit 量化对分类概率的校准可能有什么影响？
- 如何证明微调后的小模型已经能在大部分流量上替代大模型，而不只是开发集过拟合？

**推理回答：** 目标是在时延和单价约束下覆盖闭集任务。先确认任务是否真闭集、错分代价多大。若是，小模型加阈值级联是默认架构；开放生成和重推理仍留给大模型。用业务质量、延迟、升级率和升级后挽回率验证，而不是看参数量本身。

## ARCH-045. 隔夜自动循环以公开榜分数为信号，Agent 还能改提示和工具封装。如何确保变好的是能力本身，评测器没有被改写或拿来刷分？

**答：** 自我改进的正反馈只有在“打分规则比被测系统更难被改写”时才对应真实能力。评测程序、金标和隐藏留出集必须放在 Agent 的文件系统和权限之外：它只能提交产物，不能改打分脚本，也不能读隐藏题。循环里至少两条线——它看得到的开发集，和它看不见的留出集；只有留出集上升才算改进。

**深入展开：** 常见形态包括：模型合成数据再训自己、自我博弈、改提示或工具后交给执行器验证、用另一个模型当奖励。共同失败是刷分和模式崩溃（合成文本越来越同质、熵下降）。隔离清单要写成机制：评估器只读且哈希钉死；沙箱无外网、不能写评测目录；每次改动留 diff 和轨迹；分数或工具调用次数跳变超过阈值就停、等人审。公开集暴涨而留出集不动或下降，按刷题处理。生成器和评估器若共享权重或共享可被改的提示，评估端会被连带污染，必须分模型或至少冻结评估端。

**后续追问：** 这和自动超参搜索差在哪里（搜索空间是否包含评估器自身）？合成数据自训练何时该看多样性，而不是只看损失？若评估器也是模型，怎样避免两边互相抬分？多大的分数跳变构成熔断？

**扩展问题：**
- 为代码优化循环拆评估器：正确性、运行时间、可读性里哪些能全自动，哪些必须人工抽检？
- 怎样检测合成语料循环里的模式崩溃（重复率、嵌入聚集、下游任务掉点）？
- 列出必须交给人审的信号：留出集下降、试图读评测目录、输出长度崩塌、工具调用次数异常。

**推理回答：** 正反馈的符号由评估器定义。先固定“什么叫更好”，并让被优化对象够不着这个定义，再允许它改自身。任何能改评估器、或只优化可见代理分数的循环，默认按刷分而不是按能力提升来处理。
