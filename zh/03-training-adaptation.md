## TRAIN-001. 正确答案的 logit 若只比第二名高 0.1，梯度主要打在哪些位置？若一个 batch 的平均交叉熵是 2.3 nats，对应的 token 级困惑度大约多少？

**答：** 语言模型交叉熵是 −log p_θ(y*)，自然对数下单位是 nats。困惑度 PPL = exp(平均 CE)，2.3 nats 对应 PPL ≈ e^{2.3} ≈ 10，表示模型对下一个 token 的不确定度大约相当于在 10 个等可能候选里猜。对 logits 的梯度是 softmax 概率减去 one-hot：g = p − e_{y*}。正确类只比第二名高 0.1 时分布仍然平，p_{y*} 往往只有约 0.2–0.3，梯度会明显打在一批近邻错误 token 上，把它们往下推、把正确类往上推。

**深入展开：** 设 z 为词表维 logits，p = softmax(z)，L = −log p_{y*}，则 ∂L/∂z_j = p_j − 1[j = y*]。模型越自信且正确，梯度越小；p_{y*} → 1 时 g → 0。Label smoothing 把目标从 one-hot 换成 (1−ε)e + ε/V，梯度不再只打在一个位置。量级示意：词表 10⁵ 时均匀分布 CE = log(10⁵) ≈ 11.5 nats，PPL = 10⁵；训到 2.3 nats 意味着质量已集中到大约 10 个候选，这是数量直觉，不是某个已发布模型的报告值。边界：平均 CE 会被代码、数字、罕见实体等难 token 拉高，要看分桶；只盯训练 CE 下降可能在背数据，需要验证集和下游任务；采样温度改变的是生成分布，不改变已训好的 CE。交叉熵高概率不等于事实正确，不能拿它当正确率。

**后续追问：** 目标是 one-hot 时，交叉熵和 KL 散度为什么只差一个与模型无关的常数？为什么很少从零用 BLEU 或强化学习训语言模型？对 logsumexp 加惩罚（z-loss）是在压哪类数值问题？

**扩展问题：**
- 损失只在答案 span 上算、提示位置 mask 掉，梯度规模和收敛速度会怎样？
- 同样 2.3 nats，词表 32K 和 128K 对“模型有多确定”的解读有何不同？
- 验证 CE 在降、对话评分在掉，你先查数据重复还是对齐目标错位？

**推理回答：** 从 CE 定义推出 PPL = exp(CE)，用 2.3 算出约 10 建立数量直觉。再对 softmax 交叉熵求导得到 g = p − e，结合“正确类只高 0.1 → 分布平”判断梯度落在近邻类别。用分词级 CE 直方图确认不是被少量极端 token 主导。

## TRAIN-002. 在算力锁死的前提下，把 N 乘四却不给更多 token，验证损失经常变差。参数与数据该按什么经验一起涨？线上请求量非常大时，这条配比还适用吗？

**答：** 预训练损失随参数量 N、token 数 D、算力 C 近似按幂律下降。2022 年那组计算最优实验给出的经验是：固定 C 时 N 和 D 应大致同比例增长，而不是只堆参数，配比大约是每个参数 20 个训练 token，预算用 C≈6ND 换算。只把 N 乘 4、D 不变，等于在更稀的数据上欠拟合大模型，验证损失变差符合这条曲线。若上线后推理次数远大于训练步数，计算最优不等于部署最优：应故意训更小的模型、用远超 20 倍的数据换更低的单次延迟和显存。

**深入展开：** C≈6ND 来自一次前向约 2ND、反传约 2 倍于前向，总量约 6ND（数量级公式，忽略注意力对数项和通信）。代入 D≈20N 得 C≈120N²，于是 N≈√(C/120)、D≈20N；例如 C 取 6×10²³ 量级时，大约是 70B 参数配 1.4T token，和“更大参数、更少 token”的配置相比，前者往往更省算力地降损失。曲线假设数据近乎独立、质量均匀；重复文档、低质爬取、错误配比都会让指数走样。它预测的是预训练损失，不是下游突然出现的工具使用或长推理。数据不够时，多 epoch 会很快撞上重复记忆，合成数据要单独验收是否只是在复读模板。部署侧把目标从“同等 FLOPs 最低 loss”换成“同等延迟下的任务分数”，配比就会偏向过度训练的小模型。

**后续追问：** C≈6ND 里的 6 是怎么从前向/反传拆出来的，MoE 还成立吗？数据不够 20N 时，多 epoch、去重、合成数据各先试哪一个？微调或强化学习阶段还能否用同一条幂律外推学习率或步数？

**扩展问题：**
- 给定 C，按 20 token/参数估算 N 和 D，并说明若实际数据只有估算值的一半该减参数还是接受重复？
- 推理 QPS 很高时，如何把“计算最优”改写成带延迟约束的目标函数？
- 同一算力下画两条曲线：一条涨 N、一条涨 D，怎样用小规模拟合判断你处在哪一侧？

**推理回答：** 目标先定为固定 C 下的最低预训练损失，约束是 N 与 D 争夺同一笔 FLOPs。用 C≈6ND 和 D∝N 得到应同比例拆分，从而解释“只扩 4 倍参数”为何更差。再把目标换成高 QPS 推理，约束变成单次显存和延迟，于是转向小模型+更多 token。验收用小规模拟合的损失–C 曲线是否还能外推，而不是用一次下游分数否定整条律。

## TRAIN-003. 两周预训练：单卡装得下 7B、装不下 70B。数据并行与模型并行分别在什么时机采用？每一步同步的对象有何差异？

**答：** 7B 单卡能放下前向、反向和优化器状态时，走数据并行：每卡一份完整模型，吃不同微批，步末 AllReduce 梯度。70B 单卡放不下时，必须先做模型并行（按层切或按张量切）把一段放进显存，再在外层叠数据并行扩样本吞吐。两者同步的对象不同：数据并行同步整网梯度，模型并行同步的是每层激活或分片后的部分和。

**深入展开：** 数据并行的每张卡计算图相同，区别只是数据切片。每步通信体积大约是 2×参数字节（梯度 AllReduce 的双向量级），7B BF16 梯度约 14 GB，在机内高速互连上往往能和后向计算重叠；它不降低单卡峰值显存——若优化器对每个参数再存两份状态，7B 可能再加数十 GB，80 GB 卡通常仍放得下。模型并行把参数拆开：流水线按层切，阶段之间点对点传激活和梯度，通信量是微批激活而不是整网参数；张量并行按矩阵维度切，一层之内就要 AllReduce / AllGather，通信次数随层数线性涨，必须机内高速互连。70B BF16 权重 140 GB，优化器状态再数倍，单卡 80 GB 不可能，所以先模型并行解决“放得下”，再数据并行解决“样本够不够快”。常见 3D 组合是机内张量并行 × 机间流水线 × 外层数据并行。不要把“参数分片后的数据并行”和“单层必须多卡合力”的张量并行混为一谈：前者每卡最终仍能独立算完整层，后者一层都算不完。

**后续追问：** 为什么数据并行的 AllReduce 可以和后向重叠，张量并行的 AllReduce 却常落在层内关键路径上；流水线空泡和数据并行同步等待哪一个更伤步时；只加卡、不改并行策略时，70B 会先 OOM 还是先等通信。

**扩展问题：**
- 若 70B 坚持纯数据并行，靠激活重计算和 CPU offload，吞吐会掉到什么量级的直觉？
- 数据并行度加大但全局 batch 不变，对收敛和通信各有什么影响？
- 推理期还要不要数据并行？它和服务副本的区别是什么？

**推理回答：** 以“单卡是否装得下模型 + 优化器”为分界：装得下就用数据并行摊样本，装不下就先用模型并行摊参数；再比较每步同步的是梯度还是激活，从而选出该走机内切分还是机间切分。

## TRAIN-004. 显存被 Adam 的 m 与 v 顶满，这是在 70B 微调里发生的。FSDP 与 ZeRO-3 分别如何切开权重、梯度和优化器状态？何时该用这种全分片，而不是改成按层切的流水线？

**答：** 两者都把每个参数对应的「参数片 + 梯度片 + Adam 的 m/v 片」按数据并行秩切开，算到某一层或某一单元时再短时聚集参数。ZeRO-3 是 DeepSpeed 这条线上的全分片；FSDP 是 PyTorch 原生的同类全分片（按 wrap 单元聚集，算完再拆回）。优化器状态通常是大头：Adam 的 m、v 常用 fp32，约 8 字节/参数，加上参数和梯度，未分片时常常到十几字节/参数。选 FSDP 还是 ZeRO，看你要不要 DeepSpeed 的卸载和现成配置，还是留在纯 PyTorch。只有全分片之后激活或通信仍放不下、撑不住时，才再叠加按层切开的流水线。

**深入展开：** 示意：70B × 约 16 字节/参数 ≈ 1.1 TB 的训练状态（尚未计激活），8 张卡做全分片则每卡大约是百 GB 量级的状态，激活仍要另算，所以还常开激活重计算。ZeRO-1 只切优化器，ZeRO-2 再切梯度，通信比把参数也切开更少，适合「参数还能复制得下、只是 Adam 爆了」的中等模型；70B 的 bf16 训练通常直接走到参数也切的 ZeRO-3 或 FSDP。通信模式相近：前向和反向前聚集出完整单元参数，反向梯度再按秩打散，与计算重叠得好才能藏掉延迟。FSDP 的切分粒度是你 wrap 的模块（常见每个 Transformer 块），粒度太粗则峰值显存高，太细则聚集次数多。DeepSpeed 把状态卸到 CPU 或 NVMe 的路径更成熟；若团队已有一份稳的 ZeRO 配置，不必为了对齐名词而迁移。按层切开的流水线走的是深度方向，阶段间传激活，用气泡换更少的单卡层数；它不替代优化器分片，常与数据并行叠在一起。互联偏弱、整层参数聚集的延迟已经大过计算时，再加流水线或矩阵维切分，比「再加若干 FSDP 副本」更对症。

**后续追问：** 只用 ZeRO-1 能不能把 70B 训起来，缺的是哪一块显存；把整个模型 wrap 成一个 FSDP 单元和逐块 wrap，峰值显存差在哪；开启 CPU offload 后，瓶颈怎样从 HBM 变成主机内存带宽和 PCIe。

**扩展问题：**
- 为什么 FSDP 和 ZeRO-3 是在数据并行轴上分片，却常被说成「另一种把矩阵切开的并行」？
- 8 卡 FSDP 和 8 卡按层流水线，对一张 80 GB 卡的激活峰值各是什么形状？
- 如何用每层聚集耗时和计算耗时判断该减小 wrap 粒度还是该改并行策略？

**推理回答：** 先用「字节/参数 × 70B / 卡数」判断必须把优化器和参数都切开，再按生态选 FSDP 或 ZeRO-3。流水线只在激活或聚集通信成为新墙时叠加。验收看每卡峰值显存、逐步时间里的通信占比，以及和小规模单卡实现对照时损失是否一致。

## TRAIN-005. 训 70B 时切成八段流水线，空泡大约占掉单步时间的四成。该把微批加上去、换成 1F1B 调度，还是承认阶段切得过细？

**答：** Bubble 比例大约是 `(P−1)/(M+P−1)`。P=8 且只有 8 个微批时，空泡约 7/15≈47%，和“四成”对得上。把微批数加到远大于阶段数（例如 M=32，空泡约 7/39≈18%），或改用 1F1B 让前向后向交错，把悬挂激活从“所有微批同时在飞”里救下来。若全局 batch 锁死、微批加不上去，八阶段就不划算，应降低 P，改用更多张量并行或换更大显存的卡。

**深入展开：** 流水线把相邻层块放在不同设备上：微批 b 在阶段 1 算完前向，把激活传到阶段 2，同时阶段 1 接下一个微批。先跑完所有微批前向再后向的调度，需要存 M 份激活，显存压力大，bubble 出现在填满和排空两端。1F1B 在稳态里每个阶段交替做一次前向和一次后向，悬挂激活降到大约 P 份，步时仍受最慢阶段限制——层切不均、某段含更大的 MLP 时，其他阶段只能等。通信是点对点传激活，体积为 `[microbatch, seq, hidden] × 精度`；以 seq=4K、隐宽 8192、BF16、微批=1 为例，一份激活大约 4K×8192×2 ≈ 64 MB，机间往往还能重叠，但阶段太多时边界上的小层会让通信占比上升。推理期的流水线更尴尬：decode 常常就是微批 1，几乎填不满，单请求会串行穿过 8 张卡，延迟叠加，这时同卡数的张量并行通常更好。训练要让流水线划算：M ≫ P、各阶段 FLOP 均衡、用点对点而不是整网集合通信，并和张量 / 数据并行组成 3D，而不是无限加阶段。

**后续追问：** 为什么单纯加阶段数会让 bubble 和切分不均同时变差；1F1B 具体怎样降低激活内存；推理 decode 几乎没有微批时，为什么流水线经常输给张量并行。

**扩展问题：**
- 若全局 batch 被收敛约束锁死，不能靠加微批填管道，你还剩哪些减 bubble 的手段？
- 把大 MLP 单独切成一段，和按层数均匀切，哪一种更容易制造掉队阶段？
- 阶段跨越两台机器时，激活前传和梯度回传哪一方向更容易成为长尾？

**推理回答：** 先用 P 和 M 代入 bubble 公式对上“四成空闲”，再在“加微批 / 换 1F1B / 减阶段数”里选同时满足显存和全局 batch 的解；若 M 加不上去，就承认八阶段不合适，改张量并行或减小 P。

## TRAIN-006. 指令样本仅 3000 对，未标注手册约 200 亿 token。何种情形下领域续预训练才划算？何种情形下这只是烧算力的遗忘？

**答：** 当基座在手册上的困惑度明显偏高——术语被切碎、套话续写不下去、SFT 后仍把内部缩写当普通词——才值得用领域生语料继续做因果语言建模（续预训练）。若痛点只是「会写手册句子但不会按工单格式回答」，那 3000 条指令对加提示就够，先做续预训练只会把模型拧回续写器并冲掉已有对齐。续预训练之后仍然要做指令/对话 SFT，否则线上又变成「接着手册往下编」。

**深入展开：** 续预训练的目标和 SFT 不同：前者最小化领域原文的 next-token loss，吃进术语共现、章节八股、长表描述；后者最小化「指令条件下的合格回答」。数据流：清洗手册（去页眉、扫描垃圾、重复条款折叠）→ 按文档切长序列 → 低学习率因果 LM → 再拿 3000 对做聊天模板 SFT。值得做的信号：领域词的分词又碎又长、基座零样本读内部型号完全乱、你有远超指令对的洁净未标注文本（例如数十亿 token，且还能再混一部分通用文本）。不值得的信号：手册其实只有几百万 token 还重复、事实每周改、任务是分类或抽槽而不是「像内部人一样写」。遗忘风险：纯领域续预训练会抬高通用 perplexity、弄坏拒答；应用回放（通用文本或原预训练分布的子集）、短于预训练的步数、比预训练小一到两个数量级的学习率。3000 对在续预训练后的 SFT 里很容易过拟合，要早停并保留通用指令混合。成本：200 亿 token 即使用小模型也是重计算，先在一小段手册上测「领域 PPL 是否真降、通用探针是否可接受」再铺开。边界：检索已经能把条款送到上下文时，不要为了「把手册背进权重」做续预训练。

**后续追问：** 领域 PPL 降了但 SFT 后工单格式更差，说明续预训练破坏了什么；手册和通用数据 1:1 混还是 9:1，你用哪两个探针决定；续预训练做到哪一步该停，避免把安全对齐训没。

**扩展问题：**
- 给「高领域 PPL / 低指令量」和「低领域 PPL / 只要改格式」各画一条训练栈。
- 续预训练用 packing 长序列时，跨手册拼接会引入什么虚假依赖？
- 如何用「未见过的内部型号」评测续预训练是否真的吸收了术语，而不是背了某章原文？

**推理回答：** 目标是先补领域语言分布，再补任务行为。约束是生语料没有指令标签，续预训练会拉回续写。只有领域 PPL 和术语破碎证明基座读不懂手册时才付这次计算；否则直接 SFT。两次都要留通用回放，并用领域 PPL + 通用探针双收。

## TRAIN-007. 去年的拒答策略和整体文风要保住，同时每月新法规还得会用。回放、检索、参数正则、LoRA 隔离，你会按怎样的次序尝试？

**答：** 先问知识是否必须写进权重。法规文本可检索、要能指出条款号、还要能整段撤回，带版本戳和权限的检索通常第一优先：基座不动，遗忘面最小。只有口吻、内部术语或必须离线推理的规则，才进入训练。训练时先冻结基座、把新条款放进少量附加参数；再在新数据里混入旧法规和安全/通用回放；最后才对关键参数加正则或对旧策略加 KL。

**深入展开：** 灾难性遗忘来自新任务梯度在共享权重上覆盖旧决策面；即使低秩更新，也可能碰到拒答和安全相关的方向。回放比例没有通用公式：太低则旧能力掉，太高则新条款学不动，实践中常从新旧大致各半试起，用回归集决定。附加参数合并回基座、或多个月份的适配器同时挂上时，隔离效果会打折。补语料的继续预训练和改行为的指令微调要分开评估，不要混成一次“全量再训”。每次发布都跑旧法规问答、新条款问答、拒答与越狱、通用写作，并保留数据与权重快照以便回滚。

**后续追问：** 你怎样定量定义“遗忘不可上线”（旧集掉几个点）？按月累加的附加参数是合并、按路由选择，还是弃旧？检索解决不了“口吻必须改成新监管口径”时，训练目标怎么写？十亿参数上精确的 Fisher 正则算得起吗，常用什么近似？

**扩展问题：**
- 画出每月发布流水线：数据冻结、训练、回归、灰度、回滚各自卡哪些指标。
- 回放集里安全样本占比过低时，最先坏掉的通常是哪类行为？
- 新条款与旧条款矛盾时，你希望模型拒答、以新为准，还是把冲突交给检索层的时效字段？

**推理回答：** 目标是新知识可用，约束是旧能力与安全不可回退、变更可撤销。写入共享权重不可逆程度最高，所以按可撤销性排序：检索、隔离参数、回放混合、全参正则。每一层都用新旧双向评估决定还要不要往下走。

## TRAIN-008. 三张工单一起砸到刚发布的客服基座上：昨天刚换的价目表、填不齐模板字段的回复、被写成大白话的内部缩写。真正需要更新权重的是哪几张？

**答：** 微调是在已有预训练或指令 checkpoint 上，用任务对继续做梯度更新，把「这一类输入应落到那一类输出」写进权重。模板字段对不齐、内部缩写被展开，是稳定的格式和术语习惯，提示钉不住、又要低延迟短上下文时，才值得收集示范再训。价目昨天刚改，是会过期的事实，写进权重明天又错，应走检索或查询接口，而不是微调。

**深入展开：** 一次微调请求的数据流是：示范（指令 + 目标续写）→ 前向得到下一 token 分布 → 通常只对回答 token 做交叉熵 → 反向更新全部或部分权重。训完后，映射住在 checkpoint 里，线上可以把系统说明从两千 token 收到一两百，输出 schema 的方差也会下降。数量级上，锁一种工单 JSON、一种部门口吻，常常是 10³–10⁴ 条干净示范就够看趋势；想靠微调「记住本周全部 SKU 价格」，样本要跟着价目表一起腐，回滚还得重训。边界很硬：失败模式是「缺一条现行事实」就不要动权重；失败模式是「同一意图、十次里有四次少字段或乱扩写缩写」，且加长提示后仍不稳或账单不可接受，才进入微调候选。微调不负责新鲜知识，也不自动带来可追溯出处。

**后续追问：** 模板已用 JSON schema 约束解码仍有 10% 缺字段，还该不该微调，还是该加后处理补全；内部缩写表只有两百条且几乎不改，微调、词表替换和提示里塞对照表你怎么排；若业务坚持「把价目也训进去方便离线包」，你用什么过期时钟和回滚条件拒绝。

**扩展问题：**
- 同一批工单里格式错误和事实错误各占一半，训练集会怎样互相污染，你如何拆开两条适配路径？
- 微调后提示已经缩短，却把拒答边界也训丢了，上线前哪项回归不能省？
- 日请求只有几百次、示范要专家手写，微调的固定成本怎样和「再加 800 token 规则」比？

**推理回答：** 先把目标写成「稳定映射」还是「可更新事实」，再看约束：延迟、上下文预算、事实半衰期。只有映射不稳定、且上下文手段已经用尽时，才把问题交给权重；事实类失败必须能在不重训的情况下替换。验收看字段合规率、术语一致率，以及价目类问题是否仍走检索命中，而不是看几条漂亮回复。

## TRAIN-009. SFT 预算锁死在 8 万条：把覆盖铺成 400 种任务，或只保留 50 种并把每种堆到 1600，你怎么选？同一任务要准备几种问法？思维链与拒答应各占多少？又如何证明对持出的指令类型并非死记清单？

**答：** 先把预算花在覆盖「看见规格 → 选出行为类型」，而不是把同一类任务堆到饱和。每类先给到能锁住输出契约的量级（简单分类/改写大约两三百条高质量对就常够稳住格式，多约束或分步任务可到大约一千条），多出来的名额优先加新任务族和同一金标的不同问法。另留一小撮逐步推理和拒答，并且各自配上「只要短答案」「应当完成」的对照，让这两种行为成为由指令开关的条件，而不是默认文风。验收必须整族持出从未训练过的指令类型，再加上同族换措辞、约束重组两张表，禁止从已见任务里随机抽 10% 就自称泛化。

**深入展开：** 8 万条是样本容量，不是任务容量。模型在指令微调里拟合的是条件分布 P(回答 | 规格)，规格的动词、约束顺序、材料位置一变，就可能离开训练支撑。把 8 万条全部喂给大约 50 个高频任务、每类约 1600 条，这 50 类的格式会很稳，但第 51 种规格——例如「按时间线而不是按人物重排事件」——会被最近的改写任务吞掉，看起来像会写，其实是在套清单。反过来铺到大约 400 类、每类 200 条，覆盖面够大，可每类刚够锁简单契约：标签集合稍乱、单位时有时无，梯度会在同类内部打架。可执行的切法是先列任务族（抽取、分类、改写、比较、规划、计算、代码、创作、多轮澄清、元指令如「更短 / 换人称」），每族先填到契约稳定，再把边际预算给长尾族和难约束组合，而不是给已稳定族再复制模板。问法要显式多样化：同一金标至少准备数种表面形式（祈使、疑问、先约束后材料、先材料后约束、限制放进 system），否则模型绑定的是那句口号。逐步推理按条数先从大约 5%–15% 试起，但必须立刻改按 token 复核——一段四倍长的草稿若只占条数 8%，token 占比可能到大约四分之一，梯度会偏向「先写草稿」。同一题要留「只给最终答案」的对照，短指令才关得上推理通道。拒答必须写成正例，否则完成类样本会把「总是给满」推成众数；占比应明显小于完成类（例如先从大约 2%–8% 试起，按有害、缺关键槽、越权分桶），并混入易混淆的应完成题，避免「看起来难就关」。三种持出缺一不可：①整族未出现过的指令类型；②同族换模板；③见过的单条约束做笛卡尔式重组（分别见过「不超过 80 字」和「改成表格」，测试「表格且不超过 80 字」）。报告时单列「不该推理却推理了」「不该拒却拒了」。不要用和训练同模板的内部留出冒充未见类型。

**后续追问：** 带逐步推理的样本只占条数约 8%，平均长度却是短答的四倍，你按条数配比还是按 token 配比重采样；整族持出很低、换模板却很高，缺的是任务概念还是表面句式；拒答掺到约 15% 后，只缺一个可补槽的请求开始被拒，你砍条数，还是把「缺槽但可追问」改写成澄清而不是关闭。

**扩展问题：**
- 同一任务 12 种问法和 2 种问法、总条数不变，持出改写指令的遵循率差从哪一层来？怎样用嵌入簇证明那 12 种其实还挤在同一句式里？
- 真实任务族不够铺满预算时，用另一模型改写指令算不算新种类？怎样用「改写后仍落在原簇」把表面多样丢掉？
- 思维链几乎全来自计算题、拒答几乎全来自安全题，开放写作会分别搬来什么坏习惯，你用哪两条探针先抓到？

**推理回答：** 目标是 Cond(规格) 能泛化到训练清单外的规格，而不是把 8 万条变成一张背得下来的任务菜单。约束是条数固定，且长推理、拒答会按 token 和梯度权重扭曲名义混合比。于是每类只加厚到契约稳定，边际预算给新任务族和问法；推理和拒答都带对照，写成可开关的条件行为。验收拆成整族持出、换模板、约束重组，并用 token 占比校正配比，而不是看已见任务上的平均分。

## TRAIN-010. 多训几个 epoch 时，最先崩掉的通常是哪类行为？监督微调单步里若用户问题的 token 也进交叉熵，会养成什么坏习惯？学习率为何常低于预训练峰值？

**答：** 这一步和语言模型训练同构：打包（指令，回答）→ 前向 → 对位移的交叉熵 → 反向 → 用较保守的学习率更新选定参数。用户问题对应的 label 通常打成忽略（例如 -100），否则模型会把容量花在复述问题、学会「先把问句抄一遍再答」。学习率低于预训练峰值，是因为你已经在一个可用盆地里，步子太大先冲掉通用先验。epoch 一多，最先坏的往往是表面 n-gram：开始背示范原句、拒答变松、或把训练里的口头禅当成任务格式。

**深入展开：** 数据流上，提示 token 仍要进前向，因为回答的条件分布依赖它们；只是损失掩码让梯度不从「预测用户刚才说了什么」那条路径回来。全量微调更新全体 W，PEFT 只让附件或前缀接收更新，损失定义不变。学习率量级只作示意：全量 SFT 常见从 1×10⁻⁵ 附近起扫，LoRA 可以略高（例如 1×10⁻⁴ 量级），都要配 warmup 和按验证集早停，不能照抄预训练的峰值。有效 batch 太小会让本就窄的任务梯度很噪；太大则一张卡的激活先爆。示范只有几百条时，2–3 个 epoch 就该看训练/验证差距；继续加 epoch 很少补来新能力，只会提高 verbatim 复述和成员可推断风险。何时该走这条循环：需要把格式或口吻写进权重；若只是补事实，不要用更多 step 硬灌。

**后续追问：** 多轮对话里，历史回答要不要进损失，只训最后一轮助手消息会漏掉什么；损失已经很低但字段合规率不动，你查掩码、模板分隔符还是学习率；PEFT 和学习率同时改时，怎样做一次对照才能说「是更新面的问题不是步长问题」。

**扩展问题：**
- 为什么把系统提示也放进损失，模型有时会在用户可见输出里回声内部规则？
- 同一条示范复制十遍再训一个 epoch，和十个 epoch 各见一遍，过拟合形态有何不同？
- 只对回答的第一个 JSON 键算损失、后面键不算，训练会偏向什么？

**推理回答：** 从目标「学会条件在指令下的回答分布」反推损失必须对准回答 token，再从约束「保住预训练盆地」推出小学习率和少 epoch。先画清哪些参数收梯度、哪些 token 回损失，再解释复述和过拟合是这条循环的默认失败，而不是额外诅咒。验收看验证损失、字段合规、以及与基座对比的通用小题，而不是训练集 CE 是否接近零。

## TRAIN-011. 更大模型把 200 对金标扩到 1 万条，随后做监督微调。教师幻觉会在学生的哪些环节被放大？必须留下哪几类过滤器？

**答：** 放大发生在三步：教师在无依据时编造槽位，过滤没拦住；合成指令挤在金标附近的几个模板上，学生把偏见学成稳定行为；合成条数远大于 200，梯度被教师风格主导。不能省的过滤器是：相对金标和彼此的近重复、schema/规则校验、对可检索事实做蕴含或工具核对、毒性和 PII、以及与评测集的重叠检查。合成数据必须和金标按比例混（例如先按 1:1 试），并保留来源标签；教师分数不能当唯一质量信号。

**深入展开：** 典型流水线：从 200 条种子抽任务模式 → 让教师改写指令（换实体、换边界）→ 再让教师或规则写回答 → 过滤 → 与金标混合训练。幻觉在第二、三步进入：教师对「订单状态」类问题会补一个看起来合理的物流节点，若没有和系统记录核对，1 万条里会有同一类假节点反复出现，学生会把它当领域知识。多样性塌缩也常见：改写后的指令表面不同，嵌入却挤成一簇，等于把 200 条复制了 50 遍。过滤要分层：①字符串或 simhash 去重和长度异常；②JSON schema、枚举、必填字段；③能查的就查（工单号格式、金额勾稽），查不了的标成「不可自动信任」并降权或丢掉；④毒性、辱骂用户、PII；⑤与 val/test 的最长公共子串或近邻，防止刷分。人工抽检应按簇抽，每簇几条，而不是随机 20 条——随机会漏掉小簇里的系统错误。训练时金标上调采样或损失加权，避免例如 9800 条合成淹没 200 条真值。边界：教师和基座同族时，学生会更快模仿教师的套话和自信错误；开放叙事任务过滤器弱，合成比例更要压低。这里要的是覆盖稀有边界，不是复制教师的全部分布。

**后续追问：** 过滤器误杀了所有长尾边界怎么办；教师自洽地错（每次都编同一个税率）时，多数票会不会一起放过；合成数据要不要刻意生成不合格回答当负例。

**扩展问题：**
- 设计过滤漏斗：每层丢弃的是什么错误，以及你准备抽检的比例。
- 金标:合成从 1:1 调到 1:20，你用哪两个曲线决定停手？
- 如何证明学生学到的是任务规则，而不是教师的口头禅？

**推理回答：** 目标是用合成补覆盖，而不是用教师的先验重写学生。约束是教师会稳定地错、且数量会压过金标。先核验再混合，梯度向金标倾斜。验收看持出真值和对抗边界，不看合成集上的自洽准确率。

## TRAIN-012. SFT 语料来自线上客服，一共八千段会话。哪些轮次配进训练集？哪些轮次一旦写入会把模型带坏？

**答：** 能进的是：意图清楚、最终回答已被人审或业务规则判定为合格、角色完整、工具调用能对上 schema 的轮次。必须丢掉或改写的是：含未脱敏身份证/手机/卡号、重复粘贴的宏、客服自己的错误承诺、当时模型的幻觉回复被当成金标、同一用户问题对应互相矛盾的处理口径。先按会话或用户切分训练/验证/测试，不要按单轮随机切，否则同一投诉的前后句会泄漏。缺字段、该转人工的对话要作为拒答或转交正例留下，而不是当噪声删光。

**深入展开：** 原始日志不是数据集。一条可用样本至少有：规范化后的角色序列、用户可见输入、期望助手输出、以及可选的工具观察。数据流建议是：会话切分 → PII 扫描与哈希替换 → 近重复（simhash 或归一化后哈希）去重 → 规则过滤（空回复、全是「好的」、明显未完成）→ 冲突检测（相同用户文本、不同标准动作）→ 按会话 ID 分层抽样进 train/val/test。污染有两类：把当时线上模型的坏回复当标签，等于用旧错误当监督；把内部工单备注、调试前缀、检索原文整段粘进「助手」角色，模型会学会把隐私和思维草稿当产品文案。工具任务必须保留函数名和 JSON 参数的合法形状，缺右括号的轨迹宁可不训。类别要按线上先验分层，但稀有事故（欺诈、投诉升级）要过采样，否则梯度会被「查物流」淹没。量级上，8000 段对话清洗后只剩一两成千条真金标并不奇怪，宁少勿脏。每条保留来源标签（人工改写 / 规则改写 / 可回放工单号），出问题才能回溯。边界样本（用户骂人、索要违规操作）应写成合格拒答，而不是从集里消失，否则模型只会在礼貌工单上好看。

**后续追问：** 同一会话前后口径改过，你留新口径、两条都留，还是整段丢弃；工具观察里有实时库存数字，要不要打进监督文本；验证集按会话切了，但测试集仍按时间切，会漏掉哪种泄漏。

**扩展问题：**
- 写出清洗流水线的通过/丢弃规则，并在给定假设下估计 8000 段大概会剩下多少量级。
- 如何检测「同一问题两种金标」而不靠纯字符串相等？
- 拒答和转人工样本占训练集 2% 与 20%，分别会把线上什么行为带偏？

**推理回答：** 目标是监督信号等于「我们真正想要的助手行为」。约束是日志里混着 PII、旧模型错误和冲突口径。先按会话隔离切分，再按隐私、一致性、schema 合法性过滤，最后才谈数量。验收看持出会话的任务正确和泄漏检查，而不是看清洗前的条数。

## TRAIN-013. 整包各存一份，或冻结骨干只训很小参数集，用来给同一 7B 挂上 12 种部门口吻。磁盘占用、回滚方式、部门之间会不会互扰，这三项各换来什么？

**答：** 全量微调让每个部门得到一份完整权重，能力上限高，但一份 7B 的 bf16 就大约 14GB，12 份是百 GB 级副本，回滚等于切换整包，训练时优化器状态还把显存再抬一截。参数高效微调冻结基座，只训练低秩矩阵、瓶颈模块或前缀之类的小参数集，磁盘上是一份基座加 12 个通常几十到几百 MB 的附件，回滚就是卸掉那个附件。部门之间默认隔离；只有有人把多个附件硬加到同一份权重上，互扰才会出现。

**深入展开：** 全量路径里每个可训参数都有梯度，Adam 一类优化器还要为每个参数挂一阶、二阶矩，训练峰值显存往往是权重体积的数倍，必须分片或梯度检查点。PEFT 路径上基座可冻结甚至低比特存放，可训参数常常只有基座的 0.1%–2%，优化器状态按这个小集合计。推理时 LoRA 类线性增量可以合并进 W，延迟与基座同构；前缀和带非线性的瓶颈模块则不能无代价合并，要在前向里多留一条支路。边界：部门数据只有几百条时，全量很容易把通用能力冲掉，PEFT 的小自由度反而安全；若目标是换语言、换推理深度，且数据以十万计，小附件可能欠拟合，这时全量才对得起容量。不要把「能训得动」和「该为每个部门复制 14GB」当成一回事。

**后续追问：** 12 个附件要在同一进程按请求热加载，你怎么避免加载瞬间的显存尖峰；某个部门数据混进了另一部门的保密称呼，隔离是靠附件文件还是靠训练数据 ACL；若合规要求「卸载后磁盘上不能留下部门权重」，合并进基座的方案为什么反而更难删干净。

**扩展问题：**
- 基座升级到下一个 7B 版本后，12 个附件要不要全部重训，判断依据是什么？
- 两个部门口吻几乎相反（一个极简、一个必须致歉套话），共用一份全量权重再靠提示切换，为什么通常不如两份附件？
- 只训附件时，通用安全回归失败，你是降低附件学习率，还是把安全示范混进该部门数据？

**推理回答：** 从目标「12 套可切换口吻」和约束「一份基座、可回滚、磁盘和显存可控」出发，比较「复制全部权重」和「复制一小撮增量」的存储与更新面。先按数据量和需要改写的深度判断附件容量够不够，再把互扰定义为「是否有人把增量加到一起」。验收看每部门任务集、一份通用回归、以及卸载附件后是否回到基座行为。

## TRAIN-014. 线上只许一份基座、禁止热合并，每个租户还要自己的口吻。用虚拟 token 当可训练前缀，对比给注意力投影加低秩增量，各自动的是前向通路哪一段？硬 JSON 约束下谁会先饱和？

**答：** Prompt Tuning 只学一小段软嵌入，拼在输入最前面，改的是第一层看到的「虚拟历史」；Prefix Tuning 在每一层注意力的 K、V（或等价前缀状态）前再接一段可训前缀，让各层都带着这段虚拟历史。LoRA 不占序列位置，改的是选定线性算子本身。虚拟 token 参数极少（例如长度 20、隐层 4096 只有约 8×10⁴ 个数），表达力主要靠占用那一小截上下文，严格 JSON、工具调用这类硬约束上更容易先饱和。低秩增量改的是算子，同样数据量下通常更先够到字段合规；但你禁止合并时，它必须在前向里多留 BA 支路，而前缀天然就是「不改 W 文件」。

**深入展开：** 数据流对比：Prompt Tuning 是 [P; x] 做 embedding 后走原栈，P 只在第 0 层以 token 身份出现，深层只能通过注意力间接读到。Prefix Tuning 每层 K、V 变为 [Pₖ; K]、[Pᵥ; V]，前缀长度直接加进 kv_len，decode 的 cache 也要为这段虚拟前缀留位。LoRA 是 y = Wx + (α/r)BAx，序列长度不变。服务含义：前缀方案的权重文件可以始终是那一份基座，租户差异全在一小包向量里，热切换不必写 W；代价是每个请求多出 prefix_len 的注意力，且这段长度不能靠合并消去。边界：租户只要换问候语和少数拒答句，软提示往往够；要稳定输出可解析 JSON 或多工具 schema，前缀先顶满时不要继续加长到吃掉用户上下文，应换算子级增量（仍不合并、按请求加载 BA）。不要把「参数更少」读成「一定更合适」。

**后续追问：** 前缀长度从 16 加到 64，占用的是预填充还是 KV 增长，和把 LoRA rank 从 8 加到 32 比，谁先碰到 8k 窗口预算；同一套软提示迁到下一个基座版本为什么常常直接失效；禁止合并的 LoRA 在 decode 期多一次瘦 GEMM，和前缀加长 kv_len，延迟各自敏感什么。

**扩展问题：**
- 两个租户的前缀在 batch 维拼在一起时，注意力 mask 漏了前缀段会串味到什么程度？
- 只在底层加前缀、上层不加，和每层都加，JSON 合规通常差在深度的哪一段？
- 若平台连 BA 支路都不许留，只许改 embedding 表外的向量，你还怎么做多租户口吻？

**推理回答：** 先画清「不许改、不许合并 W」这条部署约束，再把三种方法按注入点分类：输入嵌入、每层 K/V、线性算子。约束排除合并后，前缀在运维上更贴约束，算子增量在硬格式上容量更大。用同一批 JSON 金标看合规率，并用「只加载租户包、基座文件哈希不变」做运维验收。

## TRAIN-015. 同一 LoRA 跑出交叉熵尖峰、领域升通用降、训练满分但验证不动三种曲线。每种先碰哪一颗超参？为什么不能一次同时改三颗？

**答：** 损失尖刺先砍学习率（或加 warmup / 梯度裁剪），不要先加 rank。领域涨、通用掉先减有效更新强度：更低 LR、更少 step，必要时降 rank 或混回放，这是遗忘信号。训练满分、验证不动先减 epoch/步数并查去重，其次才加 dropout 或 weight decay，这是过拟合。一次拧三颗会让你无法归因：第二天曲线好了也不知道是 LR 救的还是数据去重救的。

**深入展开：** LoRA 里真正放大更新的是 η 和缩放 α/r：有效旁路是 (α/r)BA。常见起步（示意，需按实现验证）：LR 约 1e-4～2e-4，r=8 或 16，α=16 或 32，warmup 约总步数的 3%～5%，weight decay 取小（例如 0～0.01），目标层先试注意力的 q/v。尖刺：η 过大或某个 batch 有超长异常样本，梯度范数爆；先把 η 降半、把梯度裁剪到例如 1.0，检查 packing 是否把两条指令粘成一条。遗忘：η 和 step 太大，ΔW 把基座行为顶走；r 过大（例如一下到 64）也会提高有效容量，更像全参数。过拟合：重复样本 × 多 epoch，验证集近邻被背诵；先把 epoch 收到 1～2 并看验证，再考虑 LoRA dropout。有效 batch = micro_batch × 累积 × 卡数，过小则噪声大（像 LR 偏高），过大则同样 η 可能偏猛，不要和 LR 同时改。序列长度决定激活显存和截断：把 8k 工单截成 2k 会丢结尾的金标字段，损失看起来正常，验证全错。纪律：一次只改一个旋钮，用同一种子、同一冻结评测包对比。边界：数据标签冲突时怎么调超参都不会好，先回到清洗。

**后续追问：** α 固定、r 从 8 加到 32，等效缩放发生了什么，要不要同步改 α；warmup 从 0 拉到 500 step 能消掉哪些尖刺、消不掉哪些；梯度累积加到等效 batch 256 时，学习率要不要按线性或平方根缩放。

**扩展问题：**
- 画一张「症状 → 第一超参 → 禁止同时改的项」对照表。
- 只训 q/v 与把 MLP 也加上，容量和过拟合风险差在哪？
- 验证集不动但线上变好，说明验证集怎样建错了？

**推理回答：** 目标是每次实验只回答一个因果。约束是 LR、步数、rank 会耦合进同一个 ΔW 尺度。按尖刺/遗忘/过拟合选第一旋钮，其余冻结。用验证和通用探针同时看，而不是只盯训练 loss。

## TRAIN-016. 评审误把「线性层旁边再挂小稠密块」叫做 LoRA。合并进原权重后，为何解码计算图仍与基座相同？真正多出来的是哪两个矩阵，谁必须保持冻结？

**答：** LoRA 不另开一层非线性，而是用两个瘦矩阵逼近增量：对冻结的 W₀ ∈ R^{d×k}，学习 B ∈ R^{d×r}、A ∈ R^{r×k}（r ≪ min(d,k)），前向是 y = W₀x + (α/r) BAx。只有 A、B 走梯度；W₀ 冻结，否则这就不是低秩适配而是全量再加附件。因为 ΔW = (α/r)BA 与 W₀ 同形，部署时可写成 W′ = W₀ + ΔW 后丢掉 A、B，解码仍是一次原规格矩阵乘，没有额外层、也没有额外序列长度。

**深入展开：** 常见挂点是自注意力的 q、v 投影，有时再加 k、o 或 MLP 的门控/上投影。以宽度约 4096、约 32 层的 7B 量级为例，只在 q、v 上用 r=8，可训参数是百万量级而不是 7×10⁹。初始化通常让 A 小随机、B 全零，于是 ΔW 从 0 起步，第一步不会把基座分布掀翻。α/r 用来把有效步长和秩解耦：升 r 时若不同时看 α，增量尺度会漂。秩过低，严格格式和多约束口吻会欠拟合；秩过高，小数据集上附件自己过拟合，显存和保存体积也涨。实现坑：若框架仍对 W₀ 建梯度或开了全参学习率，显存会回到全量水平，评测再好看也不叫 LoRA。合并是推理优化，训练期必须保留分离的 A、B，否则无法再按任务热插拔。

```python
# y = W0 @ x + (alpha / r) * (B @ (A @ x))  # W0 frozen
```

**后续追问：** 只挂 q、v 和四套投影全挂，格式合规率通常在哪类任务上才拉开差距；合并后还想按租户热切换，你是保留未合并的 A、B 在请求间替换，还是为每个租户存一份 W′；α 固定、只扫 r，和 r 固定、扫 α，哪一种更容易把「没学到」和「步子太大」分开。

**扩展问题：**
- 某层 W₀ 已经是低秩分解部署，再套 LoRA，合并时形状和数值要先满足什么？
- 训练用 dropout 加在 A 的输入上，推理合并时这条路径为什么必须关掉？
- 若评测只涨在训练领域、通用题掉点，你是降 r，还是把挂点从 MLP 收回注意力？

**推理回答：** 从目标「用低维增量逼近权重更新、推理不改图」出发，先写出 W₀ 冻结和 ΔW=BA 的形状契约，再推导合并为什么合法（两条支路都对 x 线性）。用可训参数量、合并前后逐 token logits 是否对齐、以及挂点消融来验收，而不是看「旁边是不是有一块小矩阵」。

## TRAIN-017. 瓶颈插入子层、骨干冻结、下线只卸模块，而且必须能热插拔。解码时每个插入点多做哪些矩阵乘？为何这类残差瓶颈不能像 LoRA 那样折进 W？

**答：** 典型做法是在注意力子层和/或前馈子层的残差支路上插入降维 → 非线性 → 升维的瓶颈（d → r → d，r ≪ d），近零初始化让它起步接近恒等，只训练这些小模块。基座 W 不动，下线一个任务就是卸掉对应模块文件。解码每个插入点每步都要多做两次瘦矩阵乘再加非线性，这条支路对 x 不是纯线性，所以不能写成一个与 W 同形的 ΔW 一次性加回去；LoRA 可以，是因为它的增量是 BA 这种线性映射。

**深入展开：** 插入位置常见两种密度：注意力后和前馈后各一处，或每层只留一处以换延迟。参数量示意：单处、d=4096、r=64、32 层，大约 2×32×4096×64 ≈ 1.7×10⁷ 个可训量，仍远小于 7B。前向是 h ← h + U σ(Dh)（还可带一层小 LayerNorm）。训练期基座可完全冻结，多任务就是多套 (D,U)。推理期 decode 本就带宽受限，额外小 GEMM 次数随「层数 × 每层插入数」涨，合并式 LoRA 把增量吃进 W 后没有这笔开销。边界：若产品要「零额外层、延迟与基座逐 bit 对齐」，带非线性的瓶颈不合适；若平台要按任务名热加载、并且希望模块自己有点非线性容量，瓶颈比只能线性的低秩增量更贴运维。不要把 Adapter、LoRA、前缀都叫「插一小块」——它们改的是残差流、算子增量还是注意力前缀，失败模式不同。

**后续追问：** 下线模块后是否必须回到数值上的基座前向，你用什么逐层激活对照证明没有残留；同一层插两处和只插前馈后，吞吐和任务分数通常谁先饱和；模块的 r 和 LoRA 的 r 能不能用同一数字比较容量，为什么不能。

**扩展问题：**
- 若非线性改成恒等，这个瓶颈还能不能合法合并进邻近的线性层，代价是什么？
- 多个任务模块在同一层串接，顺序换了输出分布会不会变，要不要规定加载序？
- 只在后半段层插入模块，前半段完全跳过，对「口吻」和「推理格式」各伤哪一边？

**推理回答：** 从目标「热插拔、卸模块即回基座」推出必须把可训部分做成独立残差模块；从「带非线性」推出不能合并进 W，因此 decode 必须付额外 GEMM。把延迟预算和隔离要求放在容量前面：先满足可卸载和延迟，再选 r 和插入密度。验收是任务集、卸模块后的基座回归、以及单 token 延迟增量。

## TRAIN-018. 7B 全量微调走 bf16 与 Adam，80GB 单卡在 Adam 状态刚建完、第一步尚未开始就 OOM。把每参数占用的字节摊开记账，LoRA 与 QLoRA 各从显存账上划掉哪几行？

**答：** 优化器初始化就要为每个可训练参数挂上主权重和 Adam 的两份矩，这笔账在第一次前向之前就会爆。按常见混合精度记账（示意）：每参数约 bf16 权重 2 字节 + bf16 梯度 2 字节 + fp32 主副本 4 字节 + Adam m/v 各 4 字节 ≈ 16 字节；7×10⁹ × 16 ≈ 112GB，一张 80GB 卡在参数状态这一栏就已经放不下，还不含激活。LoRA 把「可训练参数」从 7B 收到百万到千万级，基座只以冻结权重占显存（bf16 大约 14GB）。QLoRA 再把冻结基座存成 4-bit（大约 3.5GB 加少量量化常数），省的是基座存储栏，不是把全部计算变成 4-bit。

**深入展开：** 全参数这 16 字节是「状态」，不是「算力」：Adam 的一阶/二阶矩按参数各一份 fp32，所以 7B 光矩就是 56GB，加上 fp32 主权重 28GB、bf16 权重与梯度各 14GB。有的实现不保留 fp32 主副本，降到大约 12 字节/参数 ≈ 84GB，对 80GB 仍然贴边，只要再分配激活或临时缓冲就会 OOM。激活与 batch、序列长度、隐藏维度、层数有关，梯度检查点用重计算换激活峰值，能把这一栏压下去，但压不了优化器状态。要把 112GB 状态塞进多卡，需要 ZeRO/FSDP 一类分片：阶段 1 切优化器、阶段 2 再切梯度、阶段 3 连参数一起切；单卡满血全参数在 80GB 上基本无解。LoRA：冻结 W 只需一份 bf16（或更低），约 14GB；可训练的 A/B 若占 0.1%～1%（例如几百万到几千万参数），按 16 字节计往往不到 1GB；剩下主要是激活，中等序列（例如 2k）加检查点后，整卡常见落到大约 16–24GB 量级，24–40GB 卡即可起步。QLoRA：冻结权重按 4-bit 存，7B×0.5 字节 ≈ 3.5GB；前向/反向时按实现反量化到计算精度，激活和 LoRA 的梯度/优化器仍是较高精度，所以不要按 3.5GB 估峰值。代价是反量化吞吐和可能的量化误差。无论哪种，序列从 2k 拉到 8k，增长最快的通常是激活，不是 Adam 状态。

**后续追问：** 8-bit Adam 把哪一栏从 4 字节降下来，全参数还能不能挤进 80GB；ZeRO-3 能切开状态后，通信和可训练性有什么新成本；为什么 QLoRA 显存下来了，step 时间反而变长。

**扩展问题：**
- 按 16 字节/参数重算 13B 全参数，需要几张 80GB 卡才只够「状态」这一栏？
- LoRA r 从 8 改到 64，适配器状态大概按什么比例涨，相对 14GB 基座是否仍可忽略？
- 画出从「加载权重」到「第一次 backward」各阶段的显存峰值构成。

**推理回答：** 目标是解释「第一步都没有、初始化就 OOM」。约束是 Adam 状态按可训练参数线性涨。先写每参数字节，乘 7B，对账 80GB；再说明 LoRA 缩小可训练栏、QLoRA 缩小冻结权重存储栏。激活另计，不能用参数存储代替峰值。

## TRAIN-019. 改 7B 说话风格，却要把模型放进一张 24GB 的消费级卡。QLoRA 实际缩小的是哪一档常驻占用？权重已经装进去之后，把上下文开到 4k 仍会爆显存，原因是什么？

**答：** QLoRA 把冻结基座按 4-bit 存放（常见是 NF4，尺度常数还可以再压一层），只对 LoRA 附件用更高精度（例如 bf16）求梯度。7B 的权重占用从 bf16 约 14GB 落到大约 3.5–4.5GB 加少量量化元数据，Adam 状态也只挂在百万到千万级附件上，所以 24GB 卡常常「先能把模型装进去」。4-bit 的是存储，不是整图计算：反量化后的激活、注意力工作区和反传缓存仍按 batch × 序列 × 层 × 隐层涨，序列到 4k、再开到 2–4 的有效 batch，峰值照样可以顶满 24GB。

**深入展开：** 前向时 4-bit 权重按实现反量化到计算 dtype 再做 GEMM，附件路径是普通低秩乘；不要假设内核全程 4-bit 算术。分页优化器解决的是优化器状态偶发尖峰，不缩小激活。梯度检查点用重算换激活缓存，4k 上下文时往往必须开。消费卡还要给碎片、CUDA 上下文和临时缓冲留出数 GB，所以「模型 4GB + 附件 1GB」并不等于「还剩 19GB 都能给序列」。质量边界：4-bit 基座会轻微扰动原分布，领域 loss 下降但通用题变差时，先查量化误差和过训，不要先怪 rank。上线前同时看峰值 reserved 显存和一份通用回归，而不是只看「这张卡能跑完一个 step」。

**后续追问：** 同样 4k，开梯度检查点前后你预期峰值大概差一档还是差一个数量级；batch=1 仍 OOM 时，优先砍序列、砍 LoRA 挂点，还是改量化常数的双重量化；反量化放到哪一层内核融合里，会同时影响速度和峰值，你怎样分别测。

**扩展问题：**
- 把基座改成 8-bit 存放、附件不变，24GB 预算里你收回的是权重还是激活？
- 多轮对话把历史拼到 4k 再微调，和截断到 2k 只训最后一轮，口吻稳定性差在哪？
- 同一套 QLoRA 权重在 24GB 卡上能训、在 16GB 卡上只能推理，缺的那截显存通常是谁？

**推理回答：** 把 24GB 拆成「冻结权重存储 / 附件优化器 / 激活与临时区」三本账。QLoRA 只保证第一本账大幅下降；第二本账随 rank 与挂点线性涨；第三本账随序列近似线性甚至更陡。OOM 时先看第三本，不要回头怀疑 4-bit 权重没装下。验收是峰值显存曲线加领域/通用双集，不是「模型文件几 GB」。

## TRAIN-020. 采用 QLoRA 时基座以 4-bit 存放，是否就表示前向、反传以及优化器更新全部以 4-bit 完成？
**答：** 不是。基础权重以低比特存储且通常冻结，计算时按实现反量化到计算精度，训练的是 LoRA 参数；激活、梯度和优化器状态并不全是 4-bit。
**深入展开：** 显存估算要包括适配器、激活、优化器及临时缓冲区。
**后续追问：** 长序列训练为何仍可能 OOM？QLoRA 只减少部分权重存储，激活、临时缓冲和优化器等仍可能成为峰值显存来源。
**扩展问题：**
- 如何分别测量模型加载、前向、反向和优化器更新阶段的显存峰值？
- 改变存储精度与计算精度时，应分别验证哪些质量和性能指标？
**推理回答：** 低比特权重只减少部分内存，不能用参数存储量代替峰值训练内存。

## TRAIN-021. 输出格式已经稳住、多跳归因几乎没动，这是三千条工单上的 LoRA。升秩、换插入层、改全参数，怎样对照才能分清是 LoRA 容量不够，还是数据教不会推理？

**答：** 固定这三千条和大致学习率量级，做三组只改一个因素的对照：例如把秩从 8 提到 64、把目标层从注意力投影扩到 MLP、以及用更小学习率做一小段全参数（或全参数但冻结底层）。若加大容量后归因仍贴着基座、训练损失已经很低，偏向数据缺少可学的推理轨迹；若全参数明显拉开、LoRA 再加秩仍不动，才是低秩更新表达不了这套行为。默认先穷尽层与秩，再考虑全量，因为全量贵、难回滚、更容易伤通用能力。

**深入展开：** LoRA 用 `ΔW ≈ BA`、秩 r 远小于 `min(d_in, d_out)` 去逼近权重更新。格式、语气、字段顺序常常落在低秩方向，几千条就够；多跳归因要改更多中间计算，可能是子空间不够，也可能是样本只给了结论没给路径。对照纪律：① `r=8` 对 `r=64`，缩放系数按常用做法随 r 调整，看验证归因是否跟损失一起降；② 只挂 q/v 对 q/k/v/o+MLP；③ 全参数步数更少、学习率更小，避免把对照变成过拟合比赛。量级：7B 上 r=64 且挂满线性层时，可训参数仍常在千万量级，远小于七十亿；若这都不够而全量只涨一点点，就不要指望换训练算法拯救数据。边界：路径写了但被最大长度截断，看起来像容量不足；LoRA 学习率过大造成遗忘，看起来像全量更好，其实是超参。运维上 LoRA 可关、可按业务线加载，这是先用它建基线的理由，不是效果上限的证明。评估必须拆开格式合规和归因正确，否则“更像工单的口吻”会被当成推理进步。

**后续追问：** 秩加到 64 后验证损失降、归因不动，你怀疑标注太浅还是评测在考训练集没有的知识；只训 embedding 和 lm_head 的全参数算不算公平对照；多条业务线要共存时，全量微调如何提供 LoRA 那种可插拔回滚。

**扩展问题：**
- 画一棵决策树：数据量、要改的行为深度、回滚需求、显存，分别在哪一节点排除全量或排除继续加秩。
- 全参数归因高几个点、通用指令掉得更多时，你还选全量，还是拆成领域模型加路由？
- 怎样用合并前后权重更新的有效秩，辅助判断是不是已经用满低秩预算，而不是只看验证曲线？

**推理回答：** 目标是归因提升且方案可回滚。约束是三千条数据和低秩假设。用单因素对照把“容量不够”和“数据不可学”拆开，容量没吃满就不上全量。用格式、归因、通用三项分别验收。

## TRAIN-022. 改口吻、改工具调用、改地区用语的三套 LoRA 挂在同一基座上。若要合成一份权重，线性相加何时才安全？什么情况下必须按意图路由、不能做加权相加？

**答：** 三个适配器基于同一基座、改的目标层一致、任务方向大体正交（一个改套话、一个改工具 JSON、一个改用词）时，可以试 W' = W + Σ λᵢ BᵢAᵢ，再在三个任务的持出集上验收。若两个 ΔW 在同一线性层上方向相反（例如地区用语要更郑重、口吻适配器却在推口语），线性相加会互相抵消或写出四不像。这时按意图路由、一次只加载一个，或先合并再在冲突层上用小数据修，比直接相加更安全。合并省的是推理时的额外适配器计算；路由省的是任务间干扰。

**深入展开：** 单个 LoRA 在冻结的 W 上学习 ΔW ≈ (α/r)BA。合并进基座后推理与无适配器同速，服务拓扑简单。多适配器相加要求：相同基座校验和、相同插入模块（都是 q/v 才能逐层加；一个插 MLP、一个插注意力要对齐到层）。λᵢ 常用任务验证集网格搜，不必 1:1。冲突检测：分别记录各适配器在同一层的 ΔW 或 BA 的余弦；接近 −1 的层不要直接加。也可以先丢掉小幅度增量、只保留符号一致的方向再相加，减少抵消，但仍必须跑三套评测，不能只看合并后 loss。路由：分类用户意图 → 加载对应 A/B（或预先把三份都放 GPU 里做分支矩阵乘）。工具调用和口吻常常不该同时全力生效——工具要冷、口吻要热——路由比融合更干净。顺序合并（先合工具，再在其上训地区）能减少后训任务被冲掉，但会改写先合并的那个。评测矩阵是 3×2：单任务分数 ×（合并后 / 单独加载），再加一个「同一句又要敬语又要调工具」的交叉集。边界：基座版本不同的适配器绝对不能加；rank 不同可以零填充再加，但意义仍取决于是否同层。

**后续追问：** λ 取平均后工具 JSON 合规掉了、口吻还在，你是调 λ 还是回到路由；三个适配器同时加载但不合并，延迟和显存各付什么；交叉集上合并优于任一单适配器，说明什么。

**扩展问题：**
- 写出合并公式，并说明 α/r 不一致时要先对齐哪个系数。
- 如何用一层上的余弦相似度决定「可加」还是「必路由」？
- 合并后只在地区用语集掉点，怎样做局部修复而不重训工具适配器？

**推理回答：** 目标是一份权重服务三类行为，约束是低秩更新在同一 W 上可能反向。先验证同基座同层，再试加权加和并用三套持出集加交叉集验收；冲突层或交叉集崩了就路由。延迟收益不能压过任务正确和工具合规。

## TRAIN-023. 口吻、字段名、过期制度叠在同一条失败记录里，周五拿来复盘。怎样用一次只动一层的消融，判定该动提示层、检索层还是权重层？

**答：** 不要三处一起改。冻结模型和解码参数，按「先契约、再提示、再检索、最后权重」做减法/加法对照：加上 schema 校验后字段是否立刻稳；只换系统规则或 few-shot 后口吻是否收回；只换索引或把现行 PDF 置顶后制度是否改口。哪一层一动故障消失，下一刀就只打那一层。三处都微调会把可变事实、文风和 schema 焊进同一份 ΔW，以后改一条制度就要重训，还无法归因。

**深入展开：** 选型看「变化频率 × 是否必须进条件分布」。字段名是有限枚举，后处理比梯度便宜：生成后用 JSON schema 校验，失败则重试或填默认——这层过了，就不要为漂移开 SFT。提示改的是当前前缀下的条件，小时级可回滚，适合试口吻和拒答口径；当同一套口吻要在长短工单里都稳、且提示已经长到挤占检索位时，才把风格示范做成小规模 SFT。制度属于会过期的知识：检索把现行条文放进上下文，答案可引用、可撤换；写进权重的旧条款会和下次发文并存，变成自信幻觉。数据流对照：提示是「规则 + 可选 few-shot → 生成」；RAG 是「问题 → 检索 → 带引用生成」；微调是「离线样本 → 更新 W 或 LoRA → 线上短提示」。成本账（示意）：校验和提示是小时级；索引和引用评测是天级；一轮领域 SFT 常是周级。对照纪律：每次只打开一个开关，用同一条失败输入回放。边界：字段依赖只有内部才懂的缩写、提示示范不够时，可以把「缩写 → 字段」做成窄 SFT，但仍不要把税率表或制度全文写进权重。

**后续追问：** 口吻 SFT 之后模型开始改写检索到的金额，你如何证明是风格数据污染了事实；制度一周变三次时，微调发布节奏怎样永远跟不上；schema 校验失败率约 15% 时该重试、改提示还是开微调。

**扩展问题：**
- 画一张「一次只改一层」的实验表：每行写冻结什么、改什么、用哪条日志判定成败。
- 若产品坚持「一个模型包打天下」，你怎样用路由把事实题和口吻题拆开，避免单次微调同时修三层？
- 提示已经 2k token 仍锁不住口吻，微调数据最少要覆盖哪几类工单才值得付周级成本？

**推理回答：** 目标是用最便宜、最好撤的手段改对的那一层。约束是事实会变、格式可校验、风格才需要进权重。用单层对照把失败归因到契约、前缀或知识源，再按 schema → 提示 → RAG → 微调加码。验收看：制度更新无需重训、口吻稳定、字段可解析，且能指出是哪一次单层改动起的作用。

## TRAIN-024. 思维链轨迹与拒答要不要一起蒸给学生？从 70B 蒸到 8B 时，仅贴合词表上的 logits 为何不够？

**答：** 只做词表 KL，学生只能在教师已经高置信的一步分布上靠近，学不到多步决策，也学不到学生自己滚动生成时的误差累积。数学、工具调用、多步规划要把教师的中间轨迹写进监督；安全拒答是另一种输出分布，若不进入蒸馏混合，学生会在“会答题”上接近教师、在“该闭嘴”上崩掉。蒸馏转移的是行为分布，不是权重本身，缺哪类轨迹就缺哪类行为。

**深入展开：** 常见层次：①给定前缀，用温度 T 做 KL(softmax(z_T/T) || softmax(z_S/T))，软标签比硬标签信息多，但只对齐一步条件分布。②序列级：教师生成完整回答，学生做监督微调，实现简单，训练前缀来自教师、推理前缀来自学生，存在暴露偏差。③把思维链或工具轨迹写进监督，8B 才有机会学会“先拆再算”。④让学生自己生成，教师给 token 级或序列级目标（on-policy），缩小训练/推理鸿沟。70B→8B 容量差大，学生逼近不了教师的全部分布，必须按产品加权采样：多采样难题，也要多采样拒答和“我不知道”。风险：教师幻觉会被学成自信的错；只蒸开放域问答会冲掉拒答；只蒸最终正确答案会让过程监督缺失。验收要分能力集和安全集，两套分数都过才算蒸成功。

**后续追问：** 正向 KL 和反向 KL 谁更容易让学生分布变尖、谁更容易变平？为什么学生自己生成再让教师打分，往往比纯模仿教师文本更能保住推理链？教师拒答本身不稳定时，学生该对齐哪一种行为？

**扩展问题：**
- 只蒸最终答案、不蒸过程，8B 在两三步算术和多步证明上会分别差在哪？
- 如何设计蒸馏配比，避免学生把套话风格学走、把约束丢掉？
- 同样要把 70B 变便宜，蒸馏、量化和剪枝各在什么约束下更划算？

**推理回答：** 目标是 8B 在任务质量和安全边界上复现 70B 的行为。列出产品需要的行为清单（短答、长推理、拒答、工具），看一步 logits 覆盖了哪几项，缺的就补对应轨迹。用分项评测而不是单一总分决定还要不要蒸链。

## TRAIN-025. 离线要用 7B 接住 API 教师模型的解题轨迹。只拿最终结论、只拿词表上的概率分布、只拿分步推导当监督，各能迁走哪些能力？动手之前，合约与数据条款必须先禁止哪几类做法？

**答：** 只学最终答案等于普通监督模仿，迁的是格式和结论，迁不了教师的不确定性和次优说法。能拿到 token 分布时，用温度软化后的 KL/CE 把概率质量而不是 argmax 传给学生，短答和分类更稳。学逐步推理是在迁中间计算路径，有助于解题，也会把教师的错误推导一起放大。法律与合同上先否决三类，和技术路线无关：条款禁止用输出训练其他模型、提示或输出里含无权再训练的受保护材料、日志里有未获处理依据的个人信息。

**深入展开：** 技术数据流：同一批提示走教师接口 → 记录答案文本、在接口允许时记录 logits 或 logprob、可选思维过程 → 学生在对应位置做交叉熵或 KL。很多接口只给文本，这时所谓蒸馏退化为合成示范 SFT，没有软标签。温度例如 τ>1 会抬高教师的次优 token，学生学到“还可以怎么说”，而不只是标准答案一句。量级：教师调用按 token 计费，十万条带长推理的轨迹往往比学生 GPU 时间更贵，所以要先用可检验规则丢掉答错或格式坏的轨迹，避免把教师错误放大。合规按一般原则处理（具体以适用合同与法域为准）：①使用权是否允许将输出用于训练、是否禁止训练实质替代该服务的模型；②教师若复述了受保护文本，学生会二次记忆；③提示和轨迹里的姓名、账号、病历等必须先剥离或取得处理依据；④学生权重一旦分发，许可链条要解释得清。保留提示哈希、教师模型版本和许可记录，便于抽检。边界：换一层参数不能改变输出的权利来源，蒸馏不是洗白。也不要把这和“用自有语料做持续预训练”混为一谈，后者审查的是自己的来源，不是接口输出。

**后续追问：** 教师只返回文本、不返回 logits 时，评价协议和真软标签蒸馏有何不同；思维过程若被条款标成不可存储，你怎样改训练目标才不违规；学生在教师常错的题型上反而更高分，这是蒸馏成功还是过滤偏差。

**扩展问题：**
- 写一份开工前清单：必须拿到的使用权、禁止项，以及日志里要留下的出处字段。
- 软标签蒸馏和只学答案，在同一短答集合上，学生过度自信（校准误差）通常差在哪？
- 教师输出被发现含一段受保护代码时，你是删样本重训、做局部遗忘，还是整模型停用，依据是什么？

**推理回答：** 目标是把教师能力压到可离线的小模型；约束是接口能提供什么信号，以及输出能不能用于训练。先用条款否决不能做的数据流，再按要迁的是结论、分布还是过程选择损失。持出题质量与许可审计必须一起过，缺一不可。

## TRAIN-026. 线上抱怨模型错了还更自信，尽管微调后准确率高出 8 个百分点。评测套件当时漏掉了哪几类检查？

**答：** 多半只测了和训练集同分布的任务准确率，没测校准、拒答、事实可核验和通用回归。微调会把模型推到「总是给出完整答案」的模式，该说不知道的时候也编一个字段，离线准确率照样涨。一套能挡住发版的评测至少要：与早停验证集隔离的持出集、格式/schema 合规、该拒不拒、引用或工具结果是否被改写、训练前冻结的通用与安全包、以及按线上真实流量分层的人工量表。上线后还要用「自信错误」工单做单独切片，而不是只看平均分。

**深入展开：** 「+8 个点」若来自和训练高度重叠的验证集，水分很大：近重复、同一模板换了两个实体，都会被当成泛化。持出集必须按会话或时间切，并报告与训练的 n-gram 或嵌入近邻重叠率。自信错误是校准问题：看在错误样本上的平均置信（若模型输出概率或自报信心），以及「应弃权却作答」的比率。事实题要把答案拆成断言，和检索片段或工具返回做蕴含，而不是字符串匹配一个金标句子——微调后措辞变了，匹配会误杀，幻觉却漏网。安全与拒答往往在领域准确率上升时下降，因为领域数据里很少有「我不能办」。成本与延迟也是回归项：回答变长会伪装成更专业。人工评审应用固定量表（正确、部分对、幻觉、态度），抽的是线上先验，不是 demo。对照必须是同一基座、同一解码参数下的微调前模型，否则 8 个点里可能有采样噪声。边界：开放生成没有唯一金标时，不要用另一个未校准的裁判模型单独判「更好」就发版。

**后续追问：** 持出集只有 80 条，8 个点的波动大概有多宽，能不能发版；如何区分「任务真的变强」和「模型更会套评测模板」；线上点赞率和断言级忠实度打架时听谁的。

**扩展问题：**
- 列出发版门槛：哪些指标必须不降，哪些允许用延迟换准确率。
- 怎样构造「缺字段必须弃权」切片，专门抓自信错误？
- 微调前后输出长度分布若右移约 40%，你如何避免把它算进质量分？

**推理回答：** 目标是证明线上风险下降，不是刷一个和训练同分布的分数。约束是微调会奖励「总是答完」。把评测拆成持出任务、校准/拒答、事实核对、能力保持和流量分层人工审。缺任一刀都不能把 +8 当成上线理由。

## TRAIN-027. 本院缩写得会用、化验数值绝不能编。医院这份出院小结，该焊进权重的是哪类行为，只放检索的是哪类，必须留给医师把关的又是哪类？

**答：** 写进权重的应是稳定行为：本院小节标题顺序、缩写展开习惯、该引用哪类字段、缺检查就声明「未见」。化验数值、当日医嘱、会过期的路径写进检索或结构化病历接口，生成时必须能指回源字段，对不上就留空。诊断结论、治疗建议、出院带药是否合适，必须医师签发，模型最多起草。训练数据要脱敏，专家改写后的小结当金标，不要用未审核的历史幻觉稿。

**深入展开：** 高风险领域的微调目标是「格式和术语」，不是「成为科室知识库」。数据流：业务系统拉结构化字段 → 检索或填槽得到「可用事实包」→ 模型按院内模板写成小节 → 规则核验（每个数字能在事实包里找到、缩写在受控词表）→ 医师编辑签发。SFT 样本应是「事实包 + 合格小节」，损失打在小节上，并包含「缺钾离子则写未见」的拒写正例。若把整本指南和三年病历无过滤地续预训练，模型会背到具体患者轨迹，隐私和幻觉一起进来。法律意见书、金融机构研报同构：套话、章节、监管用语可进权重；现行条款、客户持仓、利率以检索或系统为准；最终法律责任留人。评估必须由领域专家按「数字是否可溯、缩写是否本院校准、有没有额外医嘱」打分，通用流畅度不算通过。上线要免责声明、审计日志（事实包哈希、模型版本、医师改动 diff）。边界：缩写歧义（同一缩写既可能是病人标识也可能是检验名）用受控词表，不要指望模型在权重里消歧所有冲突。

**后续追问：** 事实包缺一项时，模型补了一个「常见正常值」，你在哪一层拦截；专家金标只有 150 份时，该扩写格式还是扩写病例事实；同一套流程迁到金融投研，哪一条映射要改。

**扩展问题：**
- 列出至少五类禁止写进权重、必须来自系统字段的出院数据。
- 核验器只做字符串匹配，遇「K⁺ 3.8」和「血钾 3.8 mmol/L」如何避免误杀或漏放？
- 医师平均每份改 30% 句子时，说明微调学到的是模板还是还在编内容？

**推理回答：** 目标是院内文风稳定且数字可溯。约束是事实会变、法律责任不能进模型。按「稳定行为 / 可变事实 / 职业判断」拆三层：SFT、检索或接口、人工签发。验收看数字溯源率和专家改动量，不看小节是否好读。

## TRAIN-028. 问法一换仍反复冒出同一个数字，而且已废止费率表被讲成现行规则。如何判断这是脏监督焊进了权重，而非基座幻觉？先清数据再续训，还是先让这些事实离开参数？

**答：** 先做三路对照：同一问法分别问微调前基座、当前模型，以及“上下文里只给现行费率表”的检索版。微调前正确、微调后稳定复述过期数字，就是脏监督写进了权重；三路都编且数字随采样抖动，是生成幻觉；有检索就改口、无检索就说错，说明可变事实本不该写进参数。线上先对费率类槽位改走检索或规则表，并拦截过期表述；线下倒查并删除或改写冲突样本后再小步续训。不要在脏集上继续加轮次。

**深入展开：** 脏数据造成的事实错误有指纹：同一金额、日期、条款号在改写问法后仍出现，并且常能在训练集用字符串或近邻检索找回几乎相同的错误句。基座幻觉更像采样噪声，换温度或换问法数字会变。排查数据流：错误数字 → 倒查训练样本 → 核对标注时间和权威源是否已废止 → 统计该源在损失里的占比。例如只有几十条过期样本，但短集多 epoch 或被过采样，就足以压过正确先验。可变事实（费率、库存、法规生效日）应进检索或工具，微调只学“如何引用、如何声明生效期、如何拒答过期信息”。重训可能要数小时到数天，检索补丁能先把线上错误压住。边界：同一实体的正误样本共存时，只删错的不够，还要补一条带生效期的正确示范，否则空位会被基座胡填。评估集必须包含“过期 vs 现行”成对题，否则会把背诵废止表当成领域准确率。不要用再生成一批合成费率数据来“覆盖”错误，除非合成源本身已与权威表对齐。

**后续追问：** 倒查找不到字面相同的脏句、只有同义改写，你还认定是数据问题吗；检索补丁上线后无检索降级路径仍说错，服务是否允许这条降级；小步续训修正一个实体时，怎样防止把相邻实体又训偏。

**扩展问题：**
- 设计一个最小倒查：从模型吐出的数字反查训练集命中条数和时间戳，命中多少条就该停训。
- 事实每周都变、微调跟不上时，哪些字段永远不该成为 SFT 的目标 token？
- 如何用“有检索准确率 / 无检索准确率 / 与训练集冲突率”证明修复来自清数据，而不是换了个更会编的检查点？

**推理回答：** 目标是现行事实正确且可追溯。用三路对照把失败分到脏权重、幻觉或缺失检索，再按“先拦线上、再清数据、可变事实不进权重”修复。用冲突对和倒查命中验收，而不是看领域题总分。

## TRAIN-029. 评测集里出现了几乎照抄训练集的工单，模型把工单编号连同内部备注一并背出。怎样区分逐字记忆与学到话术骨架？在不停服的前提下，泄漏先从哪一层堵住？

**答：** 用改写和挖空区分：把工单号、金额、独特口头禅换成同结构的新值，若模型仍吐出训练集里的旧号，就是逐字记忆；若只复用话术框架并填新槽，是泛化。不停服先在解码侧做近重复与标识符拦截，对高相似训练原文拒答或改写，并撤掉容易触发这段的缓存提示；再下线对应 adapter 或回退检查点。不要先加轮次“看能不能忘掉”，那会把记忆打得更死。

**深入展开：** 小而重复的微调集很容易把独特 n-gram 收进权重：例如几百到几千条、多 epoch、近重复没去掉、学习率偏大。检测不能只看训练/验证损失缺口。①用训练独有的罕见实体提问，做成员暴露抽查；②把输出和训练集做最长公共子串或相似度分位，接近整句重合就当泄漏；③构造同结构未见过样本，正确槽位必须随输入变。修复分两层：服务层立刻切断输出（标识符过滤、对高相似原文拒答）；训练层去重、降 epoch、降学习率、加 dropout 或权重衰减并早停，敏感样本删除后重训。边界：标准问候或故意示范的免责声明高相似不是泄漏；复述内部备注则是安全事件，不能和“口吻有点像训练集”混为一谈。LoRA 可训参数少，不保证不会背诵——独特标识符只出现几次也可能被记住。不要用“再喂更多相同工单”来修泛化，那会加重记忆。隐私处理完成的标准是：线上不再吐出训练独有实体，并且权重侧已删除或重训，而不是只加了一层输出过滤器。

**后续追问：** 验证损失还在降，但成员实体已经能被挖出，你听哪一个做早停；只拦输出、权重里仍有工单号，对安全团队算不算处理完毕；如何用实验比较 LoRA 和全参数在同一小集上的逐字复述率，而不是靠口吻猜测谁更不容易记。

**扩展问题：**
- 写一个最小泄漏测试：十条含独特实体的训练样本，十条同结构未见面样本，通过标准分别是什么。
- 去重按字面还是按语义近邻，漏掉“只改了称呼”的近重复会上线后怎样表现？
- 怎样同时给出线上拦截有效的证据，以及删除样本后重训的时间表，而不是把事件解释成普通过拟合？

**推理回答：** 目标是停止泄漏训练独有内容，同时保留话术能力。用改写和挖空区分背诵与泛化，先切服务输出再改训练数据与强度。成员实体复述率和 hold-out 任务质量必须成对下降/保持，才算修完。

## TRAIN-030. 新任务交叉熵仍在下降，但安全拒答、小学算术、开放域问答这些通用探针已经失分。这算灾难性遗忘，还是只是一般的过拟合？训练中途优先动哪些设置？

**答：** 先拆两张曲线：新任务的训练/验证损失一起降、只是旧能力掉，是灾难性遗忘；新任务验证损失已经抬头、旧能力也乱，更像过拟合或学崩。遗忘是顺序训练改写了对旧输入仍有用的特征，模型没有「保留旧映射」的约束。中途优先降学习率、提前停在通用探针尚未崩的步数、在每个 batch 混入一部分通用指令和安全样本做回放；全参数仍在狂降通用分时，应改成冻结基座只训 LoRA，而不是再加 epoch。

**深入展开：** 过拟合的诊断锚在「同一任务」：训练损失远低于验证损失，或验证集里近重复样本被整段复述。遗忘的诊断锚在「任务外」：领域分类还在涨，但冻结的通用集（短数学、常识问答、安全拒答、遵循无关指令）单调下滑。机制上，全参数更新让 ΔW 覆盖原特征方向；若领域数据窄（全是病历口吻或合同套话），梯度会把通用方向推走。LoRA 把更新限制在低秩旁路，基座 W 冻结，遗忘面通常更小，但 rank 很高、学习率很大时仍会通过叠加 ΔW = BA 改变有效计算。可操作旋钮按侵入性排序：①学习率降半（领域 SFT 常见从例如 2e-4 降到 5e-5 量级，视实现而定）；②步数或 epoch 砍掉，用通用探针做早停，不要只看领域 val；③每个 batch 混约 10%–30% 通用指令和安全拒答，当作经验回放；④对参考模型加 KL 或 logit 约束，限制偏离；⑤从全参数退回 PEFT。评估必须双轨：领域切片 + 训练前就冻结的通用/安全包，每隔 N step 跑，不能等训完才发现。这里要的是训练过程中的刹车，不是训完再补救。不要把通用集泄漏进训练集去「刷探针」。

**后续追问：** 通用探针只有 50 题，掉 4 题算遗忘还是噪声；回放通用数据后领域分回吐，你怎么调混合比；安全拒答掉了但数学还在，说明改写发生在哪类特征上。

**扩展问题：**
- 设计一份「遗忘仪表盘」：至少四个与领域无关的切片，以及你会设的早停规则。
- 为什么只降低 epoch、不降学习率，有时仍会在前几个 step 就把安全行为冲掉？
- LoRA rank 从 8 拉到 64 时，遗忘风险沿什么机制上升？

**推理回答：** 目标是领域能力涨的同时旧映射不被覆盖。约束是 SGD 只会优化当前 batch 损失。先用双轨曲线区分遗忘和过拟合，再按「降步长 → 回放 → 缩小可训练参数」减更新幅度。验收看领域增益和冻结通用/安全包是否同时可接受，而不是只看领域 loss。

## TRAIN-031. 一到多步推理和工具失败后的回溯明显落后，尽管短问答上 7B 学生已接近 70B 教师。该补过程轨迹、加验证器，还是改走路由？

**答：** 先把失败拆成「格式对但中间步错」「中间步对但不会换路」「压根不会规划」。短问答接近，说明风格和浅层知识已经蒸过去了；复杂推理掉队，通常是学生容量装不下长依赖，或教师数据里只有最终答案、没有可学的中间决策。优先用经过外部校验的分步轨迹做过程监督；若补齐后仍系统性落后，就按难度路由——简单题走学生，多跳或工具循环走教师——而不是逼小模型当完全替代。

**深入展开：** 只蒸最终答案时，学生学的是表面分布，遇到未见过的数字或工具报错就不会自我纠正。更有用的数据是：教师写出步骤，计算器、单测或规则滤掉错轨迹，再对学生逐步计损失。困难样本应专挑「教师对、学生对错」的提示，而不是再堆一遍容易题。同样计算量下，学生的深度和宽度有限，超长思维链本身也可能超出它能有效利用的上下文。路由阈值可用多次采样是否自洽，或一个小校验器是否打回：不一致就升级。评估必须分桶：单跳事实、多跳计算、工具恢复，避免被短问答均分掩盖。

**后续追问：** 教师自己也会算错，如何避免把错误推理蒸进去？过程监督和只对最终答案计损失，梯度信号差在哪？路由误把难题留给学生，线上怎样用正确率和升级率一起发现？

**扩展问题：**
- 设计一条「教师轨迹 → 验证器过滤 → 学生微调」的最小流水线，数学和代码的验证器各看什么信号？
- 学生在见过的题型上很好、只换数字就崩，更像在记轨迹还是缺算法？
- 什么情况下继续增大学生参数，比永远路由到教师更划算？

**推理回答：** 目标是在固定延迟和成本下尽量接近教师的难例表现。先用分桶评估证明缺口集中在多步推理，再比较「更好的轨迹」和「换更大模型」两条杠杆。过程数据补齐后仍系统性失败，就是容量或测试时计算不够，应路由而不是继续盲蒸。用难例正确率、升级率和单请求成本三条曲线一起验收。

## TRAIN-032. 通用能力下滑且禁止重新训练，领域全参权重已经在磁盘上。分词器换过或文风彻底塌掉时，为何在基座与微调权重之间走直线也救不回来？两者之间怎样做线性插值，又怎样对任务向量做加减？α 该看领域、通用哪两条验证曲线？

**答：** 把领域微调写成相对基座的位移 τ = W_ft − W_0，事后修补就是沿线段取 W(α) = W_0 + α τ，也就是 (1−α)W_0 + α W_ft；若同一基座上还有别的任务向量，可以再做加减而不是重跑优化器。α 不能默认 0.5：在持出的领域轴和通用轴上扫一遍，选同时满足通用门槛、又保住大部分领域增益的膝点。这条直线只在两份检查点同结构、词表一一对应、且微调位移仍停在可线性连接的盆地时才有意义；词表对不上，或输出已经塌成单一腔调并走远，中点会变成两边都不会的中间态。

**深入展开：** 这是训后的权重空间手术：不回放语料、不改学习率、不重开一轮。做法建立在一个反复被验证的观察上——从基座走到领域最优点的路径上，靠 W_0 一端更稳、更通用，靠 W_ft 一端任务分更高，线段中段常常能同时留下两者的一大部分，等价于把过大的 ΔW 按比例缩回。操作是对齐两份 state dict（同键、同形状、同精度配方）后逐参数混合；LoRA 落盘时退化为 W_0 + α·(α_lora/r)BA，只是缩放已有增量，不必再物化稠密 W_ft。

```python
W_a = {k: (1 - a) * W0[k] + a * Wft[k] for k in W0}
```

任务向量是同一线性结构的算术：τ_domain = W_ft − W_0；若还有同一 W_0 上训出的通用指令向量 τ_sft，可试 W_0 + α τ_domain + β τ_sft；若另有一条几乎只含腔调的小增量 τ_style，可试 τ_domain − γ τ_style，意图是减口吻、留实体。选 α 必须看双轴，而不是看单一平均分：横轴用领域持出（实体是否仍对、时序是否仍对），纵轴用与领域集隔离的通用包（短问答、无关指令遵循、安全拒答），α 从 0 扫到 1，步长例如 0.1，膝点附近再加密。常见形状（示意，以你的曲线为准）：α=1 领域最高、通用最低；α 降到大约 0.4–0.7 时通用回一截而领域只吐一小点。若几乎是没有膝的斜线，插值只是凸组合妥协，不是白捡。直线失效要写死：①分词器或词表变了——嵌入和 lm_head 行列对不上，新 token 在 W_0 无对应行，零填充只会在词汇面上加噪声，整网插值没有定义；②文风彻底塌死——高学习率、多 epoch、极窄领域把 W_ft 推离与 W_0 线性连通的盆地，中点损失很高，输出或是两种腔调的乱码，或是普通算术题也先写成病历主诉，α 怎么扫都上不了双门槛；③基座本身没有的能力（从未学过指令遵循）——往 W_0 插值只会退回续写，变不出通用助手；④层数、隐藏宽或位置编码基数不同——没有逐参数对应。两边检查点都没有的事实或拒答策略，α 也变不出来。

**后续追问：** α=0.4 时通用分够了，但产品仍要领域口吻，你是把 α 再抬高，还是把口吻交给解码侧约束、权重留在膝点；只有一份 LoRA 时扫 α，和全参插值相比，少了哪一段「回到真正 W_0」的能力；做 τ_domain − γ τ_style 时，构造腔调向量的数据若夹着术语，你用哪张表判断必要实体有没有被一起减掉。

**扩展问题：**

- 对从未做过指令微调的基座做领域插值，通用遵循为什么回不来？这时缺的是哪一条可加的任务向量？

**推理回答：** 目标是不重训，把过大的领域位移按比例缩回去，使通用不低于门槛、领域增益大部分还在。约束是只能动已经存在的检查点，且线性混合要求逐参数对齐和盆地连通。于是写成 W_0 + α τ，用领域×通用双轴扫 α 找膝点；词表错位或腔调塌死并走远时直接判失败，不把 α=0.5 当作折中。验收看膝点上的两轴分数，而不是看权重是不是「看起来各一半」。
